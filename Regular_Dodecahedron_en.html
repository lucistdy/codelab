Hamilton's Trip Around the World: Hamiltonian Cycles on the Dodecahedron

In 1857 the Irish mathematician Sir William Rowan Hamilton invented a puzzle, which a London games company soon sold as a toy. Its board was a dodecahedron: 20 corners, each named after a city. The challenge was to visit every city exactly once and come back home. Today such a round trip is called a Hamiltonian cycle, and it leads straight to one of the biggest unsolved questions in computer science.

LEVEL 1

Meet the dodecahedron

"Dodeca" is Greek for twelve, and "hedron" means face. A regular dodecahedron is a solid made of 12 identical pentagons (five-sided shapes), with three of them meeting at every corner.

Drag the model to spin it. Dashed lines are edges at the back.

20 corners · 30 edges · 12 pentagon faces

The dodecahedron is one of only five perfectly regular solids, called the Platonic solids. In each one, all faces are the same regular shape and every corner looks exactly alike:

A magic formula

For every one of these solids, V − E + F = 2. For the dodecahedron: 20 − 30 + 12 = 2. This is Euler's formula, and it works for any solid without holes. You'll check all five in practice problem 1.

Counting without counting

You don't have to count the edges one by one. There are 12 pentagons with 5 edges each, which makes 60, but every edge is shared by 2 faces, so 60 ÷ 2 = 30 edges. In the same way, there are 12 × 5 = 60 pentagon corners, and 3 of them meet at each point of the solid, so 60 ÷ 3 = 20 corners.

LEVEL 2

Squash it flat: from solid to map

Imagine the dodecahedron is made of rubber. Poke a hole in the front face, stretch it wide open and press the whole thing flat. The corners and edges survive, and you get a map.

Mathematicians call a picture like this a graph. That doesn't mean a chart of numbers. Here it means:

a city
The dots. The dodecahedron has 20. Hamilton named them with 20 consonants, from B to Z.

A line joining two cities. There are 30.

Count the roads at a city. On the dodecahedron every city has exactly 3.

The outer edge of the map is the face we stretched open. Count the pentagons: 11 inside the map plus the outside one makes all 12. In Python, a graph is easy to store as an adjacency list: for every city, a list of its neighbours. We number the cities 0–19 (B = 0, C = 1, …, Z = 19):

dodecahedron.py
NAMES = "BCDFGHJKLMNPQRSTVWXZ"      # Hamilton's 20 city letters

def dodecahedron():
    adj = {v: [] for v in range(20)}
    def road(a, b):                    # a two-way road
        adj[a].append(b)
        adj[b].append(a)
    for i in range(5):
        road(i, (i + 1) % 5)              # outer pentagon
        road(i, 5 + 2 * i)                # outer spokes
        road(6 + 2 * i, 15 + i)           # inner spokes
        road(15 + i, 15 + (i + 1) % 5)    # inner pentagon
    for j in range(10):
        road(5 + j, 5 + (j + 1) % 10)     # middle ring of 10
    return adj

adj = dodecahedron()
print(len(adj))                                    # 20  cities
print(sum(len(roads) for roads in adj.values()) // 2)   # 30  roads
print(sorted(set(len(r) for r in adj.values())))     # [3]  every city has 3 roads
print(adj[0])                                    # [1, 5, 4]  B's neighbours: C, H, G

Why divide by 2? Each road appears in two lists, once for each end. That's the "handshake" trick again.

LEVEL 3

Hamilton's puzzle

Hamilton's challenge: start at any city, travel along roads, visit every city exactly once, and finish back where you started.

A round trip. This is Hamilton's puzzle.

You don't need to get back home. It's easier, because a cycle minus its last road is a path.

every road once
A different puzzle! You may revisit cities, but must use each road exactly once.
Don't mix up Euler and Hamilton

About 120 years before Hamilton, Leonhard Euler solved the famous Bridges of Königsberg puzzle and found a simple rule for road puzzles: you can make a round trip using every road once only if every city has an even number of roads. On the dodecahedron every city has 3 roads, which is odd, so an Euler circuit is impossible. Euler's question has an easy test like this. Hamilton's question, as you'll see, does not.

euler_check.py (uses adj from Level 2)
odd = [city for city in adj if len(adj[city]) % 2 == 1]
print(len(odd))   # 20  → all 20 cities are odd, so no Euler circuit
LEVEL 4

Play the Icosian Game

Hamilton's game was called the Icosian Game ("icosa" means twenty). Pegs numbered 1 to 20 were pushed into holes at the cities to record the trip. Now it's your turn.

Visit all 20 cities and come home

Click a city to start, then click a neighbouring city (dashed green ring) to travel there. Each city only once! When all 20 are visited, the last city must have a road back to your start.
Strategy hints
  • Getting stuck is normal. When every neighbour is already visited, you've hit a dead end: undo a few moves and try another road. That's exactly how the computer solves it too.
  • "Can I still finish?" tells you whether your route so far can still be completed, without giving the answer away.
  • A good habit: don't leave a city "stranded" with only one unvisited neighbour, or you'll never be able to pass through it.
LEVEL 5

Teaching Python to play

The computer plays exactly the way you did: pick a road, keep going, and when you're stuck, back up and try the next road. That's backtracking: Choose → Explore → Un-choose.

find_trip.py (uses adj and NAMES from Level 2)
def hamilton_cycle(adj, start=0):
    n = len(adj)
    path = [start]
    visited = {start}

    def explore(city):
        if len(path) == n:                    # every city visited…
            return start in adj[city]         # …and a road leads home?
        for nxt in adj[city]:
            if nxt not in visited:
                path.append(nxt); visited.add(nxt)      # choose
                if explore(nxt):                       # explore
                    return True
                path.pop(); visited.remove(nxt)         # un-choose
        return False

    return path if explore(start) else None

trip = hamilton_cycle(adj)
print(" → ".join(NAMES[c] for c in trip + [trip[0]]))
# B → C → D → F → G → R → Q → P → N → M → L → K → J → T → V → W → X → Z → S → H → B

The answer goes once around the outer pentagon (B C D F G), zig-zags around the middle ring, circles the inner pentagon and comes home. Try tracing it on the map!

LEVEL 6

How many different trips are there?

Instead of stopping at the first trip, let's count all of them. The only change is to add 1 to a counter instead of returning True.

count_trips.py (uses adj from Level 2)
def count_cycles(adj, start=0):
    n = len(adj)
    path = [start]
    visited = {start}
    count = 0

    def explore(city):
        nonlocal count
        if len(path) == n:
            if start in adj[city]:
                count += 1
            return
        for nxt in adj[city]:
            if nxt not in visited:
                path.append(nxt); visited.add(nxt)
                explore(nxt)
                path.pop(); visited.remove(nxt)

    explore(start)
    return count

trips = count_cycles(adj)
print(trips)         # 60
print(trips // 2)    # 30
60
trips starting at B (going either way round)
30
really different round trips
Why divide by 2?

Every round trip can be travelled in two directions: B → C → … → H → B and B → H → … → C → B use exactly the same roads. The program counts both, so the number of truly different cycles is 60 ÷ 2 = 30. And the starting city doesn't matter either: a cycle passes through B no matter where you "start" it, so fixing B as the start doesn't lose any.

LEVEL 7

Hamilton's secret code: Left and Right

Hamilton was an algebra genius, and he found an amazing way to describe the trips without a map.

Arrive at any city and you'll see exactly two roads you haven't just used: one on your left-hand side and one on your right-hand side. So a whole trip can be written as a string of letters: L means "take the left-hand road", R means "take the right-hand road". Hamilton built a whole system of algebra around these moves, which he called the Icosian Calculus.

Here is the code for a complete trip. Start at B, walk to C, then obey these 20 letters:

LLLRRRLRLRLLLRRRLRLR

Notice that it's the same 10-letter pattern LLLRRRLRLR twice! Press Follow Hamilton's code in the game above to watch it happen. To follow the code in Python, we need to know which road is on which side. We use the position of every city on our map and sort its three roads by direction, going counter-clockwise:

left_right.py (uses adj and NAMES from Level 2)
import math

def position(v):                              # where city v sits on the map
    if v < 5:
        angle, r = 90 - 72 * v, 200                  # outer pentagon
    elif v < 15:
        angle, r = 90 - 36 * (v - 5), (140 if v % 2 == 1 else 105)   # middle ring
    else:
        angle, r = 54 - 72 * (v - 15), 55            # inner pentagon
    a = math.radians(angle)
    return r * math.cos(a), r * math.sin(a)

def around(v):                                # v's 3 roads, counter-clockwise
    x, y = position(v)
    return sorted(adj[v], key=lambda w: math.atan2(position(w)[1] - y, position(w)[0] - x))

def follow(code, start, first):
    route = [start, first]
    for turn in code:
        here, came_from = route[-1], route[-2]
        ring = around(here)
        k = ring.index(came_from)
        # facing away from where we came from: clockwise = left-hand road
        route.append(ring[(k - 1) % 3] if turn == "L" else ring[(k + 1) % 3])
    return route

route = follow("LLLRRRLRLR" * 2, 0, 1)
print(" ".join(NAMES[c] for c in route))
# B C D F G R Q P N M L K J T V W X Z S H B C
print(len(set(route[:20])))     # 20    → all 20 cities, each once
print(route[20:] == [0, 1])     # True  → back at B, heading to C again

After 20 turns we're back at B, walking towards C again, exactly where we began. It's the same trip Python found in Level 5!

The most surprising fact on this page

There are 30 different round trips, yet every single one has the same secret code LLLRRRLRLR repeated twice. The only differences are where in the code you start reading, and whether the trip is a mirror image (all L's and R's swapped). The dodecahedron is so symmetric that, deep down, there is only one Hamiltonian cycle, seen from different angles.

Don't believe it? Let Python check all 60 trips
check_code.py (uses adj and around() from above)
def all_cycles(adj, start=0):
    n, path, visited, found = len(adj), [start], {start}, []
    def explore(city):
        if len(path) == n:
            if start in adj[city]:
                found.append(path[:])
            return
        for nxt in adj[city]:
            if nxt not in visited:
                path.append(nxt); visited.add(nxt)
                explore(nxt)
                path.pop(); visited.remove(nxt)
    explore(start)
    return found

def turns(trip):                     # the L/R code of a trip
    code = ""
    for i in range(len(trip)):
        came_from, here, going = trip[i - 1], trip[i], trip[(i + 1) % len(trip)]
        ring = around(here)
        k = ring.index(came_from)
        code += "L" if ring[(k - 1) % 3] == going else "R"
    return code

PATTERN = "LLLRRRLRLR" * 2
MIRROR = PATTERN.translate(str.maketrans("LR", "RL"))

def same_code(code):                 # a rotation of PATTERN or of its mirror?
    return code in PATTERN + PATTERN or code in MIRROR + MIRROR

trips = all_cycles(adj)
print(len(trips))                                  # 60
print(all(same_code(turns(t)) for t in trips))      # True
LEVEL 8

Why Hamilton's puzzle is secretly HARD

For Euler's puzzle there's an instant test: count the roads at each city. Is there a simple test like that for Hamilton's puzzle?

You might guess: "If every city has 3 roads, like the dodecahedron, there must be a round trip." Meet the Petersen graph. It has 10 cities, every city has exactly 3 roads, and it looks very friendly:

petersen.py (uses count_cycles from Level 6)
petersen = {v: [] for v in range(10)}
for i in range(5):
    for a, b in ((i, (i + 1) % 5),           # outer pentagon
                 (i, i + 5),                 # spokes
                 (i + 5, (i + 2) % 5 + 5)):   # inner star
        petersen[a].append(b)
        petersen[b].append(a)

print(sorted(set(len(r) for r in petersen.values())))   # [3]  every city has 3 roads
print(count_cycles(petersen))                           # 0    NO round trip at all!

Zero! The same number of roads per city as the dodecahedron, but no Hamiltonian cycle. So "3 roads everywhere" proves nothing. In fact, after more than 150 years, nobody has found any quick test that works for every map.

A million-dollar question

Computer scientists put Hamilton's puzzle in a famous group of problems called NP-complete. Checking a proposed trip is easy (practice problem 2), but finding one seems to need a search that grows explosively with the size of the map. Nobody knows for sure whether a fast method exists. This is the P vs NP problem, and there's a $1,000,000 prize for solving it.

How real programs fight back
  • Prune dead ends early: if an unvisited city has fewer than 2 unvisited-or-endpoint neighbours left, it can never be passed through, so back up right away.
  • Smart order: try the most constrained cities first (fewest free roads).
  • Remember work: dynamic programming over subsets of visited cities (see Dynamic Programming) handles about 20–25 cities exactly.

Hamiltonian cycles hide inside real problems too: delivery routes, circuit-board drilling and DNA sequencing all ask "visit everything once, efficiently".

CHECKPOINT

Quick concept quiz

Try to answer in your head before you peek.

Q1. A route uses every road exactly once. Is it a Hamiltonian cycle?

Not necessarily! That's an Euler circuit. Hamilton's rule is about cities: each one exactly once. An Euler circuit may pass through a city many times. On the dodecahedron an Euler circuit doesn't even exist (all degrees are odd), but Hamiltonian cycles do.

Q2. Our program found 60 trips from B. Why do we say there are only 30 different cycles?

Each cycle is found twice, once in each direction (clockwise and anticlockwise). They use the same set of roads, so we count them as one: 60 ÷ 2 = 30.

Q3. Every city in the Petersen graph has 3 roads, just like the dodecahedron. Why doesn't it have a Hamiltonian cycle?

Because the number of roads per city doesn't decide the answer. What matters is how the roads are connected. The Petersen graph is "twisted" in a way that traps every attempt: the search tries every possibility and finds none. This is exactly why Hamilton's puzzle is hard. There's no simple counting rule like Euler's.

2. The trip inspector ★

Write is_hamilton_cycle(adj, route) that returns True only if the route visits every city exactly once and each step (including the last one, back home) is along a road. Checking is easy, even though finding is hard!

💡 Hint

Two checks: sorted(route) == sorted(adj) (every city exactly once), and for every i, route[(i + 1) % n] is in adj[route[i]].

✅ Solution
ex2_inspector.py
def is_hamilton_cycle(adj, route):
    if sorted(route) != sorted(adj):          # every city exactly once?
        return False
    for i in range(len(route)):
        a, b = route[i], route[(i + 1) % len(route)]
        if b not in adj[a]:                   # is there a road a → b?
            return False
    return True

good = [0, 1, 2, 3, 4, 13, 12, 11, 10, 9, 8, 7, 6, 15, 16, 17, 18, 19, 14, 5]
print(is_hamilton_cycle(adj, good))                            # True
print(is_hamilton_cycle(adj, good[:-1] + [6]))                 # False  (city 6 twice)
print(is_hamilton_cycle(adj, good[:5] + good[6:] + [good[5]]))   # False  (no road 4 → 12)

4. Paths vs. cycles: the little house ★★

The "house" graph is a square (0-1-2-3) with a roof (city 4 joined to 2 and 3). Count its Hamiltonian paths (any start, any end) and its Hamiltonian cycles. Remember to divide by 2 for direction!

💡 Hint

For paths, try every starting city and count each time the path reaches all 5 cities (no need to return home). Every path is found twice, once from each end.

✅ Solution
ex4_house.py
house = {0: [1, 3], 1: [0, 2], 2: [1, 3, 4], 3: [0, 2, 4], 4: [2, 3]}

def count_paths(adj):
    n, total = len(adj), 0
    for start in adj:
        path, visited = [start], {start}
        def explore(city):
            nonlocal total
            if len(path) == n:
                total += 1
                return
            for nxt in adj[city]:
                if nxt not in visited:
                    path.append(nxt); visited.add(nxt)
                    explore(nxt)
                    path.pop(); visited.remove(nxt)
        explore(start)
    return total

print(count_paths(house) // 2)    # 7   Hamiltonian paths
print(count_cycles(house) // 2)   # 1   Hamiltonian cycle: 0-1-2-4-3-0

5. Hamilton's own challenge ★★

One of the puzzles that came with the Icosian Game gave you the first five cities and asked you to finish the trip. If your trip must start B C D F G (once around the outer pentagon), in how many ways can you finish it? Print them.

💡 Hint

Start the backtracking with path = [0, 1, 2, 3, 4] and those cities already visited, then explore from city 4 (G).

✅ Solution
ex5_finish.py
def finish_trip(adj, prefix):
    n, path, visited, found = len(adj), list(prefix), set(prefix), []
    def explore(city):
        if len(path) == n:
            if path[0] in adj[city]:
                found.append(path[:])
            return
        for nxt in adj[city]:
            if nxt not in visited:
                path.append(nxt); visited.add(nxt)
                explore(nxt)
                path.pop(); visited.remove(nxt)
    explore(path[-1])
    return found

ways = finish_trip(adj, [0, 1, 2, 3, 4])
print(len(ways))   # 2
for w in ways:

7. The knight's tour ★★★

A chess knight moves in an "L" shape. Can it start in a corner of a 5 × 5 board and land on every square exactly once? This is a Hamiltonian path problem in disguise: squares are cities, and knight moves are roads. Find a tour, then count all tours from the corner.

💡 Hint

Write the move number (1–25) into each square as you go, and set it back to 0 when you un-choose. Counting every tour takes a second or two.

✅ Solution
ex7_knight.py
MOVES = [(1, 2), (2, 1), (2, -1), (1, -2), (-1, -2), (-2, -1), (-2, 1), (-1, 2)]

def knight_tours(n, count_all):
    board = [[0] * n for _ in range(n)]
    found, first = 0, None
    def jump(r, c, step):
        nonlocal found, first
        board[r][c] = step                           # choose
        if step == n * n:
            found += 1
            first = first or [row[:] for row in board]
        else:
            for dr, dc in MOVES:
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < n and board[nr][nc] == 0:
                    jump(nr, nc, step + 1)          # explore
                    if first and not count_all:
                        break
        board[r][c] = 0                               # un-choose
    jump(0, 0, 1)
    return found, first

_, tour = knight_tours(5, count_all=False)
for row in tour:
    print(row)
# [1, 14, 19, 8, 25]
# [6, 9, 2, 13, 18]
# [15, 20, 7, 24, 3]
# [10, 5, 22, 17, 12]
# [21, 16, 11, 4, 23]
print(knight_tours(5, count_all=True)[0])   # 304  tours from the corner

8. Grid cities: when is a round trip possible? ★★★

Cities sit on an m × n grid, with roads between neighbours left/right/up/down. Test every grid from 2 × 2 to 5 × 5 for a Hamiltonian cycle and spot the pattern. Then explain why it happens.

💡 Hint

Colour the grid like a chessboard. Every road joins a black city to a white one, so a round trip must alternate colours: black, white, black, white… What does that say about the total number of cities on the trip?

✅ Solution
ex8_grids.py
def grid(m, n):
    return {(r, c): [(r + dr, c + dc) for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1))
                     if 0 <= r + dr < m and 0 <= c + dc < n]
            for r in range(m) for c in range(n)}

def has_cycle(adj):
    start = next(iter(adj))
    path, visited = [start], {start}
    def explore(city):
        if len(path) == len(adj):
            return start in adj[city]
        for nxt in adj[city]:
            if nxt not in visited:
                path.append(nxt); visited.add(nxt)
                if explore(nxt):
                    return True
                path.pop(); visited.remove(nxt)
        return False
    return explore(start)

for m in range(2, 6):
    print(m, [has_cycle(grid(m, n)) for n in range(2, 6)])
# 2 [True, True, True, True]
# 3 [True, False, True, False]
# 4 [True, True, True, True]
# 5 [True, False, True, False]

Pattern: a round trip exists exactly when m × n is even. Why: a cycle alternates black, white, black, white…, so it uses equally many of each colour, which means it has an even number of cities. If m × n is odd, a cycle through all the cities is impossible. (When m × n is even, you can always snake up and down the columns and return along the edge.)
