Codeforces 17A · 题目精讲

诺德巴赫问题：素数邻居联手创造新素数

Nick 太喜欢素数了，以至于他仿照一个著名的数学问题，发明了自己的版本。Codeforces 17A 问的是：如果把每一对"相邻"素数加起来，再加 1，从 2 到 n 之间，一共能这样造出多少个素数？这个数够不够 k 个？这道题不是要你跟一个巨大的数字斗智斗勇——而是要你把规则读得*非常*仔细。

写给爱思考的 13 岁少年 复习埃拉托斯特尼筛法 可互动
第一关

认识这个任务

你可能听说过著名的、至今还没被证明的哥德巴赫猜想：任何大于 2 的偶数都能写成两个素数之和（比如 10 = 3 + 7）。Nick 太喜欢这个想法了，于是发明了属于自己的版本，取名叫诺德巴赫问题（懂了吧？Nick 的哥德巴赫）：

Nick 的主张

从 2 到 n 之间，至少有 k 个素数能写成两个相邻素数之和，再加 1。比如：19 = 7 + 11 + 1，或者 13 = 5 + 7 + 1。

给你两个整数 n 和 k。你的任务：判断 Nick 说得对不对——如果 2 到 n（含）之间至少有 k 个素数能这样造出来，就输出 YES，否则输出 NO。

题目原话

n=27, k=2 → YES。13（= 5+7+1）和 19（= 7+11+1）都符合条件，2 ≥ 2。
n=45, k=7 → NO。实际上，45 以内只有 5 个素数能这样造出来——不够 7 个。

第二关

"相邻"到底是什么意思？

这是整道题里最重要的一句话，所以我们放慢速度："如果两个素数之间没有其他素数，就称它们是相邻素数。"意思是：把所有素数按顺序排成一排——2, 3, 5, 7, 11, 13, 17, 19, 23, …——"相邻"就是"在这个队列里挨在一起"。它不是说这两个素数必须恰好相差 2！

一个值得避开的陷阱

你可能会以为"相邻素数"就是孪生素数（像 11 和 13 这样恰好相差 2 的一对）。这是个常见的误解，但在这里是错的！23 和 29 也是相邻素数（中间的 24、25、26、27、28 全都是合数，没有别的素数插进来），尽管它们相差 6。"相邻"只表示"在素数队列里挨在一起"，不管中间的间隔有多大。

第三关

手动验证一下题目给的例子

用第二关的定义，确认一下题目提示里给的两个例子确实成立。

  • 5 和 7 是相邻素数（6 这个位置没有素数）。5 + 7 + 1 = 13，而 13 本身也是素数。所以 13 是"可以用诺德巴赫方式表示"的。
  • 7 和 11 是相邻素数（8、9、10 都没有素数）。7 + 11 + 1 = 19，而 19 本身也是素数。所以 19 同样可以用诺德巴赫方式表示。

注意这里的模式：我们不是只把两个相邻素数加起来看看这个和有什么意思——而是在这个和上再加 1，然后检查最终结果是不是恰好也是落在 2 到 n 范围里的一个素数。这道题里其实悄悄藏着两次素数判断：两个"原料"必须是相邻素数，而且最终结果也必须是素数。

第四关

我们的老工具：埃拉托斯特尼筛法

因为这里的 n 最大只有 1000，所以这道题不像你之前解决过的一些题目那样，要跟一个巨大的数字斗智斗勇——规模小得让人松一口气！但我们仍然需要一种又快又可靠的方法，一次性找出 2 到 n 之间所有的素数，还要能反复瞬间回答"这个数是不是素数？"。

这正是埃拉托斯特尼筛法要做的事：从 2 到 n 扫一遍，把每一个找到的素数的所有倍数都划掉，最后剩下的就是真正的素数。对于最大 1000 的 n，造这张筛子几乎不花什么时间。

第五关

解题配方

既然手头已经有了 2 到 n 之间所有的素数，下面是一步步的计划：

  1. 用筛法找出 2 到 n 之间所有的素数，并按顺序存成一个列表。
  2. 沿着列表往下走，逐一查看每一对相邻的素数（第1个和第2个，第2个和第3个，第3个和第4个，以此类推）。
  3. 对每一对相邻素数，算出它们的和再加 1。
  4. 检查：这个结果本身是不是素数？如果是，我们就又找到了一个"诺德巴赫可表示"的素数——把它记下来。
  5. 检查完所有相邻素数对之后，数一数这样找到了多少个不同的素数，再和 k 比较。
最重要的一句话

把每一对相邻素数都走一遍，检查"和加1"是不是素数，数一数这个检查一共命中了多少个不同的素数。如果这个数量至少是 k，答案就是 YES。

第六关

逐行读代码

下面是完整的解法。先看左边的代码，再看右边的大白话翻译。

noldbach.py
n, k = map(int, input().split())

is_prime = [True] * (n + 1)
is_prime[0] = is_prime[1] = False
for i in range(2, int(n ** 0.5) + 1):
    if is_prime[i]:
        for j in range(i * i, n + 1, i):
            is_prime[j] = False

primes = [i for i in range(2, n + 1) if is_prime[i]]

found = set()
for i in range(len(primes) - 1):
    total = primes[i] + primes[i + 1] + 1
    if total <= n and is_prime[total]:
        found.add(total)

print("YES" if len(found) >= k else "NO")

走一遍每一对相邻素数（第五关的第2~4步）。total <= n 防止我们越界查看筛子表之外的地方；is_prime[total] 是一次瞬间查表，不需要重新判断。

用 set 存 found，重复的结果只会被算一次。把最终的数量和 k 比较，正是题目要求的。

第九关

练习题：先自己算，再用工具核对

每一题都先在纸上算一遍，再用上面的小工具验证答案。

练习 1：n=13, k=1。是哪一对相邻素数让它成立的？为什么答案是 YES？

13 以内的素数：2,3,5,7,11,13。逐一检查相邻和：2+3+1=6（否），3+5+1=9（否），5+7+1=13（是！而且 13 ≤ 13），7+11+1=19（太大了，19>13，跳过），11+13+1=25（也太大）。只找到 1 个素数（13），刚好满足 k=1。答案：YES。

练习 2：n=19, k=3。我们已经知道 13 和 19 都符合条件（第一关）。19 以内还藏着第三个吗？为什么答案是 NO？

用 19 以内的素数（2,3,5,7,11,13,17,19）检查每一对相邻素数：只有 5+7+1=13 和 7+11+1=19 这两个和落在了不超过19的素数上。下一对，11+13+1=25，不是素数，而 13+17+1=31 已经超过19了。所以只有 2 个素数符合条件，不是 3 个。答案：NO。

练习 3：n=20, k=2。把 n 从 19 提高到 20，会不会改变练习 2 里的计数？

19 和 20 之间没有新的素数出现（20 不是素数），所以能达成的集合仍然只有 {13, 19}——还是 2 个。这次 k=2（不是 3），2 ≥ 2 成立。答案：YES。这说明"至少 k 个"这类题目对 k 的具体取值有多敏感！

练习 4（挑战题）：n=1000, k=44。恰好有 44 个 1000 以内的素数能用诺德巴赫方式表示——一个都不多。那 n=1000, k=45 的答案会是什么？为什么？

k=44 时，数量恰好够（44 ≥ 44），所以答案是 YES。但 k=45 时，1000 以内根本凑不出这么多符合条件的素数——这个 n 能达到的最大数量就是 44，所以再高的 k 值都不可能成功。答案：NO。这提醒我们，"至少 k 个"这类问题往往有一个硬性上限，再怎么找也没法突破。
