Maximum GCD: Pick the Best Pair

Codeforces 1370A asks a deceptively simple question: among every pair of numbers from 1 to n, which pair shares the biggest common factor? There's no need to check them all — one line of code answers it instantly. Let's find out why.

No math background needed One-line formula Interactive
LEVEL 1

The mission

You're given a number n. Somewhere among all the pairs of numbers from 1 up to n, one pair has the biggest greatest common divisor (GCD) of them all. Your job: find that biggest GCD — fast.

The rules are simple: pick two different whole numbers a and b with 1 ≤ a < b ≤ n. Compute gcd(a, b). Out of every pair you could possibly choose, report the largest gcd you can find.

Straight from the judge

n = 3 → the biggest GCD is 1 (every pair among 1, 2, 3 only shares the factor 1).
n = 5 → the biggest GCD is 2, from the pair (2, 4).

Why should you care?

Codeforces can hand you up to 100 separate values of n in one go, and n itself can be as big as 1,000,000. If your solution checks every possible pair one at a time, it will still be running long after the judge has given up on you. The real trick answers each test case in a single step.

LEVEL 2

Quick refresher: what does "GCD" mean?

Before we solve the puzzle, let's make sure "GCD" isn't scary. GCD stands for Greatest Common Divisor — the biggest number that divides evenly into two other numbers, with nothing left over.

Take 12 and 18. The numbers that divide evenly into 12 are 1, 2, 3, 4, 6, 12. The numbers that divide evenly into 18 are 1, 2, 3, 6, 9, 18. Which numbers show up in both lists? 1, 2, 3, and 6. The biggest one they share is 6 — so gcd(12, 18) = 6.

Cold Case File

Python has a shortcut, math.gcd(a, b), that finds this instantly using an algorithm invented by Euclid over 2,000 years ago. But for problem 1370A, we won't even need to call it — we're about to find something even smarter.

LEVEL 3

Why not just check every pair?

The obvious plan: try every pair (a, b), compute gcd(a, b) for each one, and keep the biggest. It would definitely work — eventually.

The problem is n can be as large as 1,000,000, and there can be up to 100 test cases like that. Checking every pair means checking roughly n²/2 pairs per test case — and that number explodes far faster than you'd expect.

LEVEL 4

The key insight: let one number be double the other

Here's the shortcut. If b is exactly double a (that is, b = 2 × a), then a divides evenly into b — so gcd(a, b) = a, automatically, every single time.

a = n // 2
→×2
get
b = 2 × a

Since b is exactly two copies of a, a divides b perfectly — so gcd(a, b) = a, guaranteed.

So to make that shared factor as big as possible, we just want the biggest a for which 2 × a still fits inside n. That's exactly a = n // 2 (integer division: divide by 2, throw away any remainder).

The one sentence that matters most

The biggest GCD you can ever get from a pair inside 1..n is exactly n // 2 — and you get it every time by picking a = n // 2, b = 2 × a.

But why can't anything beat n // 2? Say the winning pair shares a common divisor g. Because g divides both numbers, and the two numbers are different, the bigger one has to be at least one whole "step of g" past the smaller one — so the bigger number is at least 2 × g. Since the bigger number can never exceed n, that forces 2g ≤ n, or g ≤ n // 2. Try to break this with n = 10: could g = 6 work? We'd need two different multiples of 6 that are both ≤ 10 — but the only one is 6 itself; 12 is already too big. So g = 6 is impossible, and indeed 10 // 2 = 5 is the real answer (the pair 5 and 10).

LEVEL 5

Reading the code, line by line

Here's the entire solution. Don't worry about understanding it all at once — read the code on the left, then the plain-English translation on the right.

max_gcd.py
def max_gcd(n):
    # the biggest possible gcd(a, b) for 1 ≤ a < b ≤ n
    return n // 2

t = int(input())
for _ in range(t):
    n = int(input())
    print(max_gcd(n))

LEVEL 8

Quick challenges (no peeking until you've tried)

Test the trick on paper before you check with the tool above.

Challenge 1: What's the answer for n = 7, and which pair achieves it?

a = 7 // 2 = 3, b = 2 × 3 = 6. Check: gcd(3, 6) = 3. Could anything beat 3? The remaining pairs look like (1,7)=1, (2,5)=1, (4,6)=2, (5,7)=1, (6,7)=1 — none reach 3. So the answer is 3, from the pair (3, 6).

Challenge 2: What's the smallest possible n in this problem, and what's the answer for it?

The smallest allowed n is 2 (you need at least two numbers to make a pair at all). For n = 2, the only pair available is (1, 2), so gcd(1, 2) = 1 is the only possible answer — and it matches the formula: 2 // 2 = 1.

Challenge 3: Why can't the answer ever be bigger than n // 2?

Say the winning pair shares a common divisor g. Because g divides both numbers, and the numbers are different, the bigger number has to be at least one whole "step of g" past the smaller one — so the bigger number is at least 2 × g. Since the bigger number can't exceed n, we get 2g ≤ n, or g ≤ n // 2. That upper limit is exactly what a = n // 2, b = 2a reaches — so it's not just a good answer, it's the best possible one.

Challenge 4: The judge only wants the biggest GCD, not the actual pair. Can you change max_gcd(n) to return the pair (a, b) too?
max_gcd_pair.py
def max_gcd_pair(n):
    a = n // 2
    b = 2 * a
    return a, b

print(max_gcd_pair(13))  # (6, 12)
