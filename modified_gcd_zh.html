修改版最大公约数：在区间里搜索

你已经会求两个数最大的公共因数了。Codeforces 75C 问的更刁钻：在 a 和 b 所有的公共因数里，哪一个最大、又刚好落在给定的区间里——而且你能不能把这个问题连续回答 10,000 次，还面不改色？

不需要数学基础 预处理一次，之后飞快 可以互动
第一关

任务目标

给你两个数 a 和 b。接着会有 n 个独立的问题，每个问题都在问：能同时整除 a 和 b 的数里，哪一个最大，并且落在 low 到 high 之间（包含两端）？如果不存在这样的数，答案就是 -1。

题目原样给出的例子

a = 9，b = 27，3 个查询：
low=1, high=5 → 3（3 同时整除 9 和 27，而且是 [1, 5] 区间里最大的一个）。
low=10, high=11 → -1（9 和 27 的公共因数没有一个落在 [10, 11] 里）。
low=9, high=11 → 9（9 同时整除这两个数，而且落在 [9, 11] 里）。

这跟你有什么关系？

a 和 b 最大可以到 1,000,000,000，而且最多会有 10,000 个查询。如果每个查询都从头把整道题重新算一遍，程序还没算完，评测系统早就等不及了。诀窍是把最费劲的活儿只做一次，之后每个查询几乎瞬间就能回答。

第二关

解锁一切的那一个事实

整道题都建立在这一个事实上：a 和 b 的每一个公共因数，都是 gcd(a, b) 的因数；反过来，gcd(a, b) 的每一个因数，也都是 a 和 b 的公共因数。这两组数字其实完全一样。

用样例验证一下：gcd(9, 27) = 9。9 的因数是 1, 3, 9。现在分别列出 9 和 27 的因数：9 的因数是 1, 3, 9；27 的因数是 1, 3, 9, 27。它们共同拥有的数字是什么？1, 3, 9——正好就是 gcd 的因数。这不是巧合。

冷知识档案

还没学过 GCD，或者想复习一下它为什么特别？最大公约数那一页从头讲起——这一页正好从那里接着往下讲。

所以我们不用直接在两个可能非常大的数字里翻找公共因数，只需要研究一个数：g = gcd(a, b)。它的每一个因数都自动是 a 和 b 的公共因数，而且不会有别的因数藏在别处。

第三关

为什么不能直接扫描每个区间？

针对单个查询，最直接的办法：把 low 到 high 之间的每一个数都走一遍，检查它是否同时整除 a 和 b，记录下能整除的最大那个。

问题是 high − low 本身就可能接近 1,000,000,000，而且可能有 10,000 个这样的查询。把一次十亿量级的扫描重复一万次，除非你特别喜欢盯着进度条，否则这不是个好计划。

第四关

关键洞察：把 g 的所有因数一次性找出来

既然 a 和 b 的每一个公共因数都是 g = gcd(a, b) 的因数，我们只需要一份 g 的完整因数列表。而快速造出这份列表还有个诀窍：因数总是成对出现的。

较小因数
i
↔配对
较大因数
g / i

如果 i 能整除 g，那么 g/i 也能整除 g——而且这一对里必定有一个 ≤ √g。所以只要把 i 从 1 检查到 √g，就能找齐每一对因数的两半。

g 最大可以到 1,000,000,000，而 √g 也就大约 31,623——这个循环几乎瞬间就能跑完，哪怕检查的数字大到十亿。找齐所有因数之后，从小到大排个序。

全篇最重要的一句话

把费劲的活儿——求 gcd(a, b) 以及它的每一个因数——只做一次。之后每个查询，都只是在一份简短的、排好序的列表里扫一眼而已。

回答一个查询就变得很简单：从排好序的因数列表里，从最大的因数往小里扫，第一个 ≤ high 的因数就是最好的候选。如果它同时 ≥ low，那就是答案。如果它比 low 还小，那列表里剩下的因数只会更小，全都不可能落在区间里——所以答案就是 -1。

第五关

逐行读代码

下面就是完整的解法。不用一下子全懂——先看左边的代码，再看右边的大白话翻译。

modified_gcd.py
def gcd(x, y):
    while y:
        x, y = y, x % y
    return x

def divisors_of(g):
    divs = []
    i = 1
    while i * i <= g:
        if g % i == 0:
            divs.append(i)
            if i != g // i:
                divs.append(g // i)
        i += 1
    divs.sort()
    return divs

a, b = map(int, input().split())
g = gcd(a, b)
divs = divisors_of(g)   # a 和 b 的每一个公共因数，从小到大排好

n = int(input())
for _ in range(n):
    low, high = map(int, input().split())
    answer = -1
    for d in reversed(divs):   # 从最大的因数开始
        if d <= high:
            if d >= low:
                answer = d
            break
    print(answer)
def gcd(x, y): while y: x, y = y, x % y return x
经典的欧几里得算法求 gcd——Python 自带的 math.gcd 底层用的也是这一招。
while i * i <= g: if g % i == 0: divs.append(i) if i != g // i: divs.append(g // i) i += 1
把每个候选 i 从 1 检查到 √g。每命中一次，就同时得到两个因数（i 和 g/i），除非它们相等（比如 g=9 时的 i=3，因为 3 × 3 = 9）。
divs.sort()
两两配对得到的因数是乱序的（大的小的混在一起），所以排一次序，得到一份干净、方便搜索的列表。
for d in reversed(divs): if d <= high: if d >= low: answer = d break
从最大的因数开始往小找。第一个能挤进 high 以内的因数就是最好的候选——拿它跟 low 比一下就可以停了，因为更小的因数不可能比它更好。
第六关

一起手把手推演一遍：a=9, b=27

gcd(9, 27) = 9，排好序的因数是 [1, 3, 9]。让我们从最大的因数往下扫，把三个样例查询都回答一遍。

查询 (low, high)检查 d=9检查 d=3检查 d=1答案
(1, 5)9 > 5，跳过3 ≤ 5 且 3 ≥ 1——停下—3
(10, 11)9 ≤ 11 但 9 < 10——停下——-1
(9, 11)9 ≤ 11 且 9 ≥ 9——停下——9
和评测系统给出的期望输出完全一致：3, -1, 9

留意查询 2：第一个挤进 high=11 以内的因数是 9，但 9 < 10 = low。既然剩下的因数（3、1）只会更小，它们也不可能 ≥ 10——所以可以立刻停下，报告 -1，不用再继续检查。

第八关

课后挑战（先自己试，别偷看答案）

在用上面的工具验证之前，先自己在纸上把这个搜索试一遍。

挑战一：a=9, b=27，查询 low=9, high=11。答案是多少？

这是样例查询 3。gcd(9,27)=9，因数 [1, 3, 9]。从最大的开始扫：9 ≤ 11，而且 9 ≥ 9——立刻停下。答案：9。

挑战二：a=12, b=18，查询 low=4, high=5。答案是多少？

gcd(12, 18) = 6。6 的因数：[1, 2, 3, 6]。从最大的开始扫：6 ≤ 5？不行，跳过。3 ≤ 5？可以——但 3 ≥ 4？不行。到此停下（剩下的因数只会更小）。答案：-1——12 和 18 的公共因数里，根本没有一个落在 4 和 5 之间。

挑战三：为什么 a 和 b 的每一个公共因数，一定都是 gcd(a, b) 的因数？

可以这样想：gcd(a, b) 是同时整除 a 和 b 的那个最大的数——它完全是由 a 和 b "共享的原材料"拼出来的。a 和 b 的任何其他公共因数，都是从这份共享原材料里截取的更小一块，而更小的一块永远能整除完整的那一块。这正是为什么每一个公共因数都会出现在 gcd(a, b) 自己的因数列表里，不多不少，一个不落。

挑战四：能不能改一下代码，在回答查询之前，先打印出 a 和 b 一共有多少个公共因数？
