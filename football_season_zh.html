足球赛季：重建比分记录

一支球队踢了 n 场比赛，得到 p 分，可惜所有的赛果记录都弄丢了。你只知道赢一场和平一场各值多少分。Codeforces 1244C 问的是：你能不能拼出一份说得通的胜、平、负记录？就算 n 有一万亿、p 有一亿亿那么大，也能做到吗？

建立在埃博尼和艾沃丽之上 一个新技巧：mod d 可以互动
第一关

任务目标

一支球队踢了 n 场比赛，最终得到 p 分。每赢一场值 w 分，每平一场值 d 分，每输一场值 0 分。找出非负整数 x（胜场数）、y（平场数）、z（负场数），使得：

x×w + y×d = p　　并且　　x + y + z = n

任何一组合法的答案都可以，没有唯一的"正确答案"。如果不存在合法的组合，就报告 -1。

题目原样给出的例子

n=30, p=60, w=3, d=1 → 17 9 4（17×3 + 9×1 = 60，17+9+4 = 30）。其实还有别的合法答案，比如 20 胜 0 平 10 负。
n=10, p=51, w=5, d=4 → -1（10 场比赛最多能拿到 10×5 = 50 分，51 已经超出上限）。
n=20, p=0, w=15, d=5 → 0 0 20（0 分意味着每一场都输了）。

这跟你有什么关系？

n 最大可以到 1,000,000,000,000（一万亿！），p 最大可以到 100,000,000,000,000,000。任何一场一场去试的计划，还没试完所有可能，程序早就超时了。

第二关

你其实已经解决了一半

仔细看第一个方程：x×w + y×d = p。这跟 埃博尼和艾沃丽（Codeforces 1036A）里的谜题一模一样——两种"面额"（这里是赢的分数和平的分数）要凑出一个精确的总数。

这次的新花样是：只让 x 和 y 存在还不够，还需要 x + y ≤ n，因为每一场胜或平都会用掉 n 场比赛里的一场，剩下的（z = n − x − y）必须是 0 或更多——总不能有负数场的失利！

冷知识档案

如果在 x×w + y×d = p 里寻找 x 和 y 这件事让你觉得陌生，埃博尼和艾沃丽那一页从头讲起。这一页假设你已经掌握了那部分，重点讲这次新增的"比赛场次预算"。

第三关

为什么旧招数在这里不够快

在《埃博尼和艾沃丽》里，制胜的招数是把 x 从 0 开始往上循环，检查剩下的伤害能不能被 b 整除。那样管用，是因为目标最大也就 10,000，循环很小。

而这里，x 可能需要一路循环到 n，最大能到一万亿。一个要跑一万亿次的循环，就算每一步几乎什么都不做，也没法在 1 秒的时间限制里跑完。我们需要一种办法，直接跳到有用的 x 值上，中间那些没用的全部跳过。

第四关

关键洞察：真正重要的起点只有 d 个

诀窍分两部分。

第一部分——余数每隔 d 步就会重复。拿任意一个 x，给它加上 d。赢得的分数会变化 d×w——而这正好是 d 的倍数，所以完全不会改变除以 d 之后的余数（就像时钟上的 3 点和 15 点其实指向同一个位置，因为 12 是时钟大小的倍数）。所以 x×w mod d 只取决于 x mod d——这意味着真正不同的起点只有 d 个，而不是 n 个。

第二部分——一旦落在一个可行的余数上，就把 x 尽量往大推。比较两种拿到同样 w×d 分的方式：d 场胜利（d×w 分）或者 w 场平局（w×d 分）——分数一样，因为乘法不在乎顺序。但 d 场胜利只用掉 d 场比赛，而 w 场平局要用掉 w 场比赛——题目保证 w > d。所以用胜利换掉平局（分数不变！）总能省出比赛场次。

w 场平局
w×d 分
↔分数相同
d 场胜利
d×w 分

分数一样，但 d 场胜利只用 d 场比赛，w 场平局要用 w 场比赛——而且 w > d，所以用胜利拿下同样的分数"更划算"。

全篇最重要的一句话

只需要检查 x 的 d 种可能余数。对每一种能凑出分数的余数，用上面的"交换"把 x 尽量往大推——这样用掉的比赛场次最少，最有希望塞进 n 场比赛里。

第五关

逐行读代码

下面就是完整的解法。不用一下子全懂——先看左边的代码，再看右边的大白话翻译。

football_season.py
n, p, w, d = map(int, input().split())

best_m = min(n, p // w)   # 最多能负担得起多少场胜利
answer = None

for r in range(d):
    if (r * w) % d == p % d and r <= best_m:
        x = r + d * ((best_m - r) // d)   # 把 x 尽量往大推
        y = (p - x * w) // d
        if x + y <= n:
            answer = (x, y, n - x - y)
            break

if answer is None:
    print(-1)
else:
    print(*answer)

胜场数不可能超过总场次（n），也不可能多到光靠胜场的分数就超过 p。这个数给我们尝试的每一个 x 都设了上限。

把 x 所有可能的余数 r 都试一遍（第四关的第一部分）。只有胜场分数的余数和 p 的余数一致，这个余数才可能行得通。
x = r + d * ((best_m - r) // d)
在所有这个余数的 x 里，直接跳到不超过 best_m 的最大那个（第二部分——用胜利换平局的交换）。

算出还需要多少场平局才能凑够剩下的分数，再检查胜场加平局是不是还能塞进 n 场比赛里。
冷知识档案

"余数每隔 d 步就重复"这个想法，其实就是快速幂那一页里出现过的钟表算术（mod）——同一个技巧，换了个新任务。

第八关

课后挑战（先自己试，别偷看答案）

在用上面的工具验证之前，先自己在纸上把这个搜索试一遍。

挑战一：n=20, p=0, w=15, d=5。答案是什么？为什么循环在 r=0 就立刻找到了？

best_m = min(20, 0 // 15) = 0。在 r=0 时：0×15 mod 5 = 0，而 p mod 5 = 0——匹配！既然 best_m 已经是 0，x 没法再往大推：x = 0。接着 y = (0 − 0) / 5 = 0，0 + 0 = 0 ≤ 20。答案：0 0 20——记分板上一分都没有，说明没有一场是赢的或平的。

挑战二：n=10, p=51, w=5, d=4。走一遍为什么每个余数最终都失败了。

best_m = min(10, 51 // 5) = 10。p mod 4 = 3。逐个检查余数：r=0 得到 0，r=1 得到 1，r=2 得到 2，r=3 得到 3×5 mod 4 = 3——匹配！把 x 往大推：x = 3 + 4×((10−3)//4) = 3 + 4 = 7。接着 y = (51−35)/4 = 4，7+4=11 > 10——需要的场次太多了。没有别的余数匹配，所以答案是 -1。

挑战三：为什么只需要检查 d 种不同的余数，而不是从 0 到 n 的每一个 x？

因为 x×w mod d 只取决于 x mod d（第四关，第一部分）——给 x 加上 d，总是给 x×w 加上 d 的倍数，永远不会改变余数。所以每一个 x 的"匹配或不匹配"结果，都和 d 个可能余数中的某一个完全一样。检查全部 n 个 x，其实就是把同样的 d 种结果反反复复地检查了最多 n/d 遍——纯属重复劳动。

挑战四：这道题接受任何合法的答案。你能不能改一下代码，从所有合法的余数里，找出胜场数最多的那一组？
football_season_max_wins.py
n, p, w, d = map(int, input().split())

best_m = min(n, p // w)
best_answer = None

for r in range(d):
    if (r * w) % d == p % d and r <= best_m:
        x = r + d * ((best_m - r) // d)
        y = (p - x * w) // d
        if x + y <= n:
            if best_answer is None or x > best_answer[0]:
                best_answer = (x, y, n - x - y)

print(-1 if best_answer is None else " ".join(map(str, best_answer)))
