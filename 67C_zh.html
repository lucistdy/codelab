Codeforces 67C · 题目精讲

珠串变形记：用最少时间改好项链

你有一串带字母标签的珠子 A，想把它变成另一串珠子 B。你有四种工具——插入、删除、替换、交换相邻两颗珠子——每种工具花费的时间都不一样。怎样才能用最少的总时间，把 A 变成 B？

不需要数学基础 动态规划 可以互动
第一关

任务目标，原样来自题目

想象一串穿着字母珠子的项链——这就是序列 A。老师要求你把它变成另一串项链 B，只能用下面这四种工具：

插入
在任意位置加一颗珠子——花费 ti
删除
拿掉任意一颗珠子——花费 td
替换
给任意珠子换个字母——花费 tr
交换
交换相邻两颗珠子的位置——花费 te

四种工具可以任意顺序、任意次数使用。问题说起来很简单，做起来却出乎意料地难：把 A 变成 B，最少要花多少时间？

题目原样给出的例子

t_i=1, t_d=1, t_r=1, t_e=1，A=youshouldnot，B=thoushaltnot → 5
t_i=2, t_d=4, t_r=10, t_e=3，A=ab，B=ba → 3
t_i=1, t_d=10, t_r=20, t_e=30，A=a，B=za → 1

提醒一下：这题真的不容易

这是整个系列里最硬核的一道——字符串长度可以到 4,000 颗珠子，把每一种操作顺序都试一遍完全不现实。我们会把这个想法拆成很小的几步、一点一点搭起来，如果一开始觉得信息量大也别担心，讲到最后自然就通了。

题目悄悄保证的一条规则

题目还告诉你 2×t_e ≥ t_i + t_d 永远成立。先把这条记在心里——它其实正是让这道题能被解出来的关键。第五关会揭晓为什么。

第二关

热身：先只用插入和删除

先把替换和交换放一边，假装手上只有插入和删除两种工具。样例三正好是个好例子：A = "a"，B = "za"，t_i=1，t_d=10。

z
a

'a' 这颗珠子本来就已经在正确的位置上——只需要在它前面插入一颗 'z'。

笨办法是：先删掉 'a'（花费 10），再插入 'z' 和一颗新的 'a'（花费 1+1=2），一共 12。但仔细看——A 里的 'a' 相对 B 来说，其实已经在正确的位置上了！根本不用动它。只要在它前面插入一颗 'z'，总花费只要 1——正好是题目给出的答案。

核心想法

解这类问题的聪明做法，是先想清楚哪些珠子可以原封不动地留着，只为真正需要改动的珠子付出代价。也就是从头开始，一颗一颗地对比 A 和 B：这颗珠子已经对上了吗，还是需要用工具？

为了同时记录"A 用掉了多少颗"和"B 已经搭出了多少颗"，我们可以搭一张网格：行数表示已经处理了 A 的多少颗珠子，列数表示已经搭出了 B 的多少颗珠子。每个格子存的是走到这一步的最小花费。这种"用网格搭答案"的技巧有个名字：动态规划——把一个大问题拆成许多更小的、已经解决过的小问题来组合出答案。

只用插入和删除时，格子 (i, j)（意思是"A 的前 i 颗珠子变成 B 的前 j 颗珠子"）的规则是：

如果 A[i−1] == B[j−1]：dp[i][j] = dp[i−1][j−1] （免费——本来就对上了）
否则：dp[i][j] = min(dp[i−1][j] + t_d, dp[i][j−1] + t_i)

第三关

加上替换：经典的"编辑距离"

现在把第三种工具请回来：替换。如果当前两颗珠子对不上，与其删掉一颗再插入另一颗（两次操作），不如直接原地换个标签（一次操作），花费 t_r。有时候这样更划算，有时候不是——网格会自动算出哪种更便宜。

规则只多了一个选项：

dp[i][j] = min(
  dp[i−1][j] + t_d,  删掉 A 的珠子
  dp[i][j−1] + t_i,  插入 B 的珠子
  dp[i−1][j−1] + (0 或 t_r，取决于 A[i−1]==B[j−1] 是否成立)  保留或替换
)

你其实早就见过它的"名门表亲"

当 t_i = t_d = t_r = 1 时，这张网格算出来的东西有个正式名字：莱文斯坦距离（也叫"编辑距离"）——拼写检查、"你是不是想输入……"提示背后用的就是这个想法，用来衡量两个单词有多不一样。样例一（youshouldnot → thoushaltnot，所有花费都是 1）其实就是一道披着外壳的编辑距离题，答案正好是 5。

第四关

特殊招式：交换相邻珠子

这道题真正有意思的地方来了。看样例二：A = "ab"，B = "ba"，t_i=2, t_d=4, t_r=10, t_e=3。

a
b

要变成

b
a

只用前三种工具的话，最便宜的方案是：从前面删掉 'a'（花费 4），再在末尾插入一颗新的 'a'（花费 2）——总共 6。把两颗珠子都换个标签要花 2 × 10 = 20，更贵。但还有一招，前面两种方案都没想到：直接原地交换这两颗珠子。这只是一次交换，花费 t_e = 3——只要删除加插入方案的一半价钱！

题目笔记原文

"在第二个样例中，你可以从第一个位置删掉标记为 'a' 的珠子，再在新的第二个位置插入另一颗 'a'，总时间为 6。但是交换这两颗珠子的总时间是 3。"

所以网格需要第四个选项，但它只在一种非常特定的情况下才适用：目前用到的 A 那一段的最后两颗珠子，正好是目前搭出的 B 那一段最后两颗珠子的镜像。用符号写出来，对于格子 (i, j)，当 i ≥ 2 且 j ≥ 2 时：

如果 A[i−1] == B[j−2] 且 A[i−2] == B[j−1]：
  还可以考虑 dp[i−2][j−2] + t_e

"ab" 变 "ba" 的最后一个格子正好符合这个条件：A 的最后一颗珠子（'b'）等于 B 的倒数第二颗（'b'），A 的倒数第二颗（'a'）等于 B 的最后一颗（'a'）。这正是一次完美的相邻交换。

第五关

完整配方（以及那条奇怪的规则）

把四种工具全部合在一起，每个格子 (i, j) 的完整规则是：

dp[0][0] = 0
dp[i][0] = i × t_d  （全部删掉）    dp[0][j] = j × t_i  （全部插入）

dp[i][j] = 以下几项取最小：
  dp[i−1][j] + t_d  删除
  dp[i][j−1] + t_i  插入
  dp[i−1][j−1] + (0 或 t_r)  保留 / 替换
  dp[i−2][j−2] + t_e  交换（仅当交叉图案匹配，且 i,j ≥ 2）

最终答案就是 dp[len(A)][len(B)]。

为什么 2×t_e ≥ t_i + t_d 这么重要？

我们的配方每一步只交换一对相邻珠子。但如果交换特别便宜呢？比如 t_e = 1，而 t_i = t_d = 10。那你就可以用两次便宜的交换（花费 2），把一颗珠子"月球漫步"般挪动两个位置，而不是花费 20 去删除再插入——而且这颗珠子还能继续这样一步步挪得更远，几乎不花什么钱。我们这个简单的配方从来没考虑过这种"连环交换"，所以算出来的答案会偏贵——是错的。

而 2×t_e ≥ t_i + t_d 这条保证，恰好排除了这种情况。它意味着两次交换（花费 2×t_e）永远不会比一次删除加一次插入（花费 t_i + t_d）更便宜。所以连环交换去把一颗珠子挪得很远，永远不划算——单独一次相邻交换，就是你能占到的最大便宜了。这正是让"每一步只考虑一次交换"的配方值得信赖、能给出真正最小值的原因。

第六关

用 Python 把它写出来

下面是把第五关的配方直接翻译成代码，一行一行地把整张网格搭出来。

sequence_of_balls.py
ti, td, tr, te = map(int, input().split())
A = input()
B = input()
n, m = len(A), len(B)

dp = [[0] * (m + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    dp[i][0] = i * td
for j in range(1, m + 1):
    dp[0][j] = j * ti

for i in range(1, n + 1):
    for j in range(1, m + 1):
        cost_replace = 0 if A[i - 1] == B[j - 1] else tr
        best = min(
            dp[i - 1][j] + td,
            dp[i][j - 1] + ti,
            dp[i - 1][j - 1] + cost_replace,
        )
        if (i >= 2 and j >= 2
                and A[i - 1] == B[j - 2]
                and A[i - 2] == B[j - 1]):
            best = min(best, dp[i - 2][j - 2] + te)
        dp[i][j] = best

print(dp[n][m])
dp = [[0] * (m + 1) for _ in range(n + 1)]
一张 (n+1) 行、(m+1) 列的网格——多出来的那一行一列表示"还没用到任何珠子"。
dp[i][0] = i * td dp[0][j] = j * ti
网格的边界：把 i 颗珠子变成什么都没有，就要把它们全删光；把什么都没有变成 j 颗珠子，就要全部插入。
cost_replace = 0 if A[i-1] == B[j-1] else tr
如果两颗珠子已经一样，"替换"就是免费的——什么都不用做。
best = min(delete, insert, keep/replace)
三个"普通"选项，跟第三关的配方一模一样。
if ... A[i-1]==B[j-2] and A[i-2]==B[j-1]: best = min(best, dp[i-2][j-2] + te)
第四关那个特殊的第四选项——只有在最后两颗珠子正好交叉对称时才会被检查。
关于"变大"的提醒

字符串长度最多可以到 4,000，也就是大约 1600 万个网格格子。对 C++ 这样的快语言没问题，但纯 Python 会明显感觉到吃力。如果要处理最大规模的数据，下面这个技巧只在内存里保留两行网格，而不是整张网格——因为网格永远只往前看一行和两行，剩下的完全不需要留着。

加餐：省内存的"滚动数组"写法
sequence_of_balls_rolling.py
ti, td, tr, te = map(int, input().split())
A = input()
B = input()
n, m = len(A), len(B)

prev2 = [0] * (m + 1)              # 第 i-2 行
prev1 = [j * ti for j in range(m + 1)]  # 第 i-1 行（一开始就是第 0 行）

for i in range(1, n + 1):
    curr = [0] * (m + 1)
    curr[0] = i * td
    for j in range(1, m + 1):
        cost_replace = 0 if A[i - 1] == B[j - 1] else tr
        best = min(prev1[j] + td, curr[j - 1] + ti, prev1[j - 1] + cost_replace)
        if (i >= 2 and j >= 2
                and A[i - 1] == B[j - 2]
                and A[i - 2] == B[j - 1]):
            best = min(best, prev2[j - 2] + te)
        curr[j] = best
    prev2, prev1 = prev1, curr

print(prev1[m])

不再保留一整张巨大的网格，而是只留最近算完的两行（prev2，往前两行；prev1，往前一行），再加上正在搭的这一行（curr）。一行搭完之后，就往下挪一格，变成下一轮的"前一行"。

一起手把手推演一遍：样例二

现在亲手把整张网格填出来：A = "ab"，B = "ba"，t_i=2, t_d=4, t_r=10, t_e=3。网格只有 3×3，正好可以完整走一遍。

表头上方拼出的是 B = "ba"，左侧拼出的是 A = "ab"。挑几个格子仔细看看：

格子 (i, j)含义推算过程结果
(1, 1)"a" → "b"对不上：min(删除 2+4=6，插入 4+2=6，替换 0+10=10)6
(1, 2)"a" → "ba"A[0]='a' 正好等于 "ba" 的最后一个字符 'a'，直接沿用 dp[0][1] + 02
(2, 1)"ab" → "b"A[1]='b' 正好等于 "b" 的最后一个字符 'b'，直接沿用 dp[1][0] + 04
(2, 2)"ab" → "ba"对不上，但出现了交叉配对——交换获胜：dp[0][0] + 3 = 33

最重要的是右下角那个格子，dp[2][2] = 3。它的四个候选值分别是 16（两个都替换）、6（先删再插）、6（先插再删），以及交换选项 dp[0][0] + t_e = 0 + 3 = 3——交换直接胜出，因为 A 的最后一颗珠子（'b'）等于 B 的倒数第二颗（'b'），A 的倒数第二颗（'a'）等于 B 的最后一颗（'a'）：正好是一次完美的交叉配对。这正是题目给出的答案：3。

该你上场了：换成你自己的花费和字符串

输入四种花费，再输入两个短字符串（这里限制得比较短，好让整张网格能显示在屏幕上——正式题目允许每个字符串最多 4,000 颗珠子）。

项链改造花费计算器

小提示：可以试试上面的三个官方样例，或者把 t_e 设得比 t_i 和 t_d 小很多，看看交换能赢多少。
第九关

该你练习了

先自己在纸上算出来，再用上面的工具验证。

挑战一：A="ab"，B="ba"，四种花费都等于 1。最小花费是多少？

把同样的 3×3 网格用花费全为 1 重新填一遍：dp[1][1]=1（替换），dp[1][2]=1（'a' 正好对上 "ba" 里的 'a'），dp[2][1]=1（'b' 正好对上 "ab" 里的 'b'），最后 dp[2][2] = min(替换：1+1=2，先删再插：1+1=2，先插再删：1+1=2，交换：dp[0][0]+1 = 1)。交换又一次胜出——答案是 1。注意这正是第五关那条规则的边界情况：2×t_e = 2，t_i+t_d = 2，两边正好相等——规则允许取等号，不只是严格小于。

挑战二：A="cat"，B="cot"，t_i=t_d=t_r=1（t_e 这里用不上）。最小花费是多少？

'c' 对上 'c'，'t' 对上 't'——只有中间那颗珠子不一样（'a' 对 'o'），而且完全没有出现交叉配对可以让交换派上用场。一次替换就能搞定。最小花费：1。

挑战三：为什么交换选项只会去看 A[i−1]、A[i−2]、B[j−1]、B[j−2]——也就是各自前缀的最后两颗珠子——而不是检查字符串里任意两颗珠子？

因为 dp[i][j] 的定义就是"把 A 的前 i 颗珠子变成 B 的前 j 颗珠子的最便宜方式"——它是从左到右、一个前缀一个前缀搭起来的。填 dp[i][j] 的每一个选项，都必须能接回到某个更小的、已经算好的前缀问题。一次刚好在 (i, j) 这里完成的交换，只可能牵扯到这个前缀边界处的那两颗珠子——字符串里更早的部分，在算更小的子问题时早就已经决定好了。

挑战四：假设（只是假设！）t_e=1，而 t_i=t_d=10，这就打破了 2×t_e ≥ t_i+t_d 这条规则。用你自己的话解释一下，为什么第五关的配方在这种情况下可能算错。

交换这么便宜的话，你可以用两次交换把一颗珠子挪动两个位置，总花费只要 2——比删掉再重新插入（花费 20）便宜得多。这颗珠子甚至可以一次又一次地交换，几乎不花什么钱地"挪"过很长的距离。我们的配方每个格子只考虑一次相邻交换，没办法表示一颗珠子通过一连串交换挪动很远这种情况。所以在这个假设的世界里，真正的最小花费可能比配方算出来的低得多——配方算出来的答案会是错的。这正是题目为什么要保证 2×t_e ≥ t_i+t_d：它让"连环交换"永远不划算，这样每个格子只考虑一次交换就已经足够了。

挑战五（较难）：修改第六关的代码，让它也打印出在最后一个格子（dp[n][m]）达到最优答案时，用到的是四种工具里的哪一种。
sequence_of_balls_trace.py
i, j = n, m
cost_replace = 0 if A[i - 1] == B[j - 1] else tr
options = {
    "delete": dp[i - 1][j] + td,
    "insert": dp[i][j - 1] + ti,
    "keep/replace": dp[i - 1][j - 1] + cost_replace,
}
if (i >= 2 and j >= 2
        and A[i - 1] == B[j - 2]
        and A[i - 2] == B[j - 1]):
    options["swap"] = dp[i - 2][j - 2] + te

winner = min(options, key=options.get)
print("Last tool used:", winner, "costing", options[winner])

如果在每一个格子都这样做（不只是最后一个），并且记住每次是哪个选项赢了，就能把完整的操作序列还原出来，而不只是知道总花费。
