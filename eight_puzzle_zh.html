滑块密室大逃脱：用 BFS 解八数码问题

八块写着数字的方块，一个空位，只有一条规则：只能把方块滑进空位。你能把方块排回原来的顺序吗？能用最少的步数做到吗？我们会先玩一玩这个谜题，再教 Python 瞬间解出任何一个棋盘，抓出示例代码里藏着的 bug，最后揭开一个秘密：有一半的棋盘根本解不开！

适合 13 岁+ 广度优先搜索 可玩的谜题 捉虫 8 道练习题
第 1 关

认识这个谜题

想象你被锁在一间密室里。门上有一块 3×3 的滑块面板，方块上写着 1 到 8，还有一个空格。只有当方块排成 1 2 3 / 4 5 6 / 7 8、空格在右下角时，门才会打开。

自己试试吧！点击空格旁边的方块，它就会滑进空格。带虚线框的方块可以移动，绿色的方块已经回到了自己的家。

🧩 密室之门

点"打乱"换一道新题。打乱时只用合法的滑动，所以一定有解。
一个让全世界疯狂的谜题

八数码是 15 数码（4×4，十五个方块）的小弟弟。1880 年，15 数码风靡全世界：人们在家里玩、在单位玩、在火车上也玩。著名的谜题作家萨姆·劳埃德后来声称，他曾为某一个特定的棋盘悬赏 1000 美元。从来没有人拿到这笔奖金，在第 7 关你就会知道为什么没人能拿到。

用手玩的话，你大概用了 30 步、50 步，甚至 100 步。可最短的解法是多少步呢？靠猜是猜不出来的。我们需要一套系统的方法，这正是计算机科学的用武之地。

移动的是空格

换个巧妙的角度：不要想"方块滑进空格"，而是想"空格在移动"，它和旁边的方块交换位置。这样一来只有四种移动，每种移动只是给空格的位置加上一个数：

空格移动方向字母位置变化什么时候不允许
上u−3在最上面一行（pos − 3 < 0）
下d+3在最下面一行（pos + 3 > 8）
左l−1在最左边一列（pos % 3 == 0）
右r+1在最右边一列（pos % 3 == 2）
"穿墙"陷阱

上下很好检查：新位置小于 0 或大于 8，就是掉出棋盘了。左右却很狡猾。如果空格在位置 3（中间一行的开头），3 − 1 = 2 是一个完全合法的数字，可位置 2 却是第一行的末尾！空格会"穿墙"跑到另一边去。所以我们还需要额外的 pos % 3 检查。

neighbours.py
MOVES = [(-3, "u"), (3, "d"), (-1, "l"), (1, "r")]   # (位置变化, 字母)

def neighbours(state):
    pos = state.index("x")
    result = []
    for offset, letter in MOVES:
        npos = pos + offset
        if npos < 0 or npos >= 9:            # 从上边或下边掉出去了
            continue
        if offset == -1 and pos % 3 == 0:    # 在最左列：不能再往左
            continue
        if offset == 1 and pos % 3 == 2:     # 在最右列：不能再往右
            continue
        cells = list(state)                  # 字符串不能修改，列表可以
        cells[pos], cells[npos] = cells[npos], cells[pos]   # 交换空格和方块
        result.append((letter, "".join(cells)))
    return result

for letter, s in neighbours("23415x768"):
    print(letter, s)
# u 23x154768
# d 23415876x
# l 2341x5768
第 3 关

一张画满所有棋盘的地图

现在想象一张巨大的地图。每一种可能的棋盘都是地图上的一个点，如果滑动一次就能把一个棋盘变成另一个，就在这两个点之间连一条线。数学家把这种地图叫作图：点是状态，线是移动。

解谜就是：在这张地图上找一条从你的棋盘到目标棋盘 12345678x 的路线。最短的解法就是经过的线最少的那条路线。

9! = 362,880
8 个方块和 1 个空格在 9 个格子里的排列数
2 到 4
每个棋盘能走的步数（空格在角上 2 种，在边上 3 种，在中心 4 种）

这么多棋盘，靠瞎试是试不完的。如果随便乱走，还可能永远在原地绕圈。我们需要一种有条理的搜索：不重复访问任何棋盘，并且保证找到最短路线。来认识 BFS 吧。

第 4 关

BFS：池塘里的涟漪

往池塘里扔一颗石子，一圈圈涟漪向外扩散：先是 1 步远的地方，然后是 2 步远的，再然后是 3 步远的……广度优先搜索（BFS）探索地图的方式一模一样。

工具 1
一个队列
一条排队的队伍：棋盘从队尾加入，从队头离开。先来先走，就像食堂打饭排队。
工具 2
"见过"记录本
一个字典，记下所有已经找到过的棋盘，这样同一个棋盘绝不会探索两次。
循环
取出、展开、加入
取出队头的棋盘，找出它的邻居，把每个新棋盘加到队尾。

因为队列是先进先出的，所有距离为 1 的棋盘都会在距离为 2 的棋盘之前处理，依此类推。所以 BFS 第一次到达某个棋盘时，走的一定是最短路线。这就是全部的魔法。

从目标棋盘出发，涟漪是这样一圈圈变大的：

第几圈（离目标几步）012345…24…3031
棋盘数量12481620…24,047…2212

最大的一圈在 24 步远的地方，而最后一圈在 31 步，只有 2 个棋盘。它们就是世界上最难的八数码！你会在练习 6 里找到它们。

我们来写 BFS。除了"见过"记录，还要记住每个棋盘是从哪里来的（它的上一个棋盘和用到的移动），这样最后就能从目标往回走，读出整条路线。

bfs_solve.py
from collections import deque

def bfs_solve(start, goal="12345678x"):
    parent = {start: None}                 # 棋盘 -> (上一个棋盘, 移动字母)
    q = deque([start])                     # 排队的队伍
    while q:
        s = q.popleft()                    # 取出队头的棋盘
        if s == goal:
            break                          # 到达目标：停止搜索
        for letter, t in neighbours(s):
            if t not in parent:            # 一个全新的棋盘？
                parent[t] = (s, letter)    # 记住是怎么来的
                q.append(t)                # 排到队尾
    if goal not in parent:
        return None, len(parent)           # 从来没到过目标
    path = ""
    s = goal
    while parent[s] is not None:           # 从目标往回走到起点
        s, letter = parent[s]
        path = letter + path               # 每一步都放到最前面
    return path, len(parent)

print(bfs_solve("1234567x8"))   # ('r', 8)
print(bfs_solve("23415x768"))   # ('ullddrurdllurdruldr', 46289)
print(bfs_solve("21345678x"))   # (None, 181440)

看每个答案里的第二个数：它表示 BFS 一共发现了多少个棋盘。简单的棋盘只需要很少几个；一个 19 步的棋盘大约要 46,000 个。最后那个棋盘呢？BFS 找遍了 181,440 个棋盘之后放弃了：这个棋盘永远解不开。先记住这件事，第 7 关会揭晓答案。

怎么读答案

每个字母都表示空格移动的方向。对于棋盘 1234567x8，"r" 的意思是"空格向右移"，也就是方块 8 向左滑。一步搞定！

第 5 关

妙招：倒着搜，只搜一次

假设比赛给了我们很多个棋盘要解。每个棋盘都跑一遍完整的 BFS 太慢了，遇到无解的棋盘更慢。有个更聪明的想法：所有谜题的终点都是同一个目标。那就只做一次 BFS，从目标出发，扩散到所有能到达的棋盘。

每一次滑动都可以撤销（空格往上移了，再往下移就回来了），所以从目标到某个棋盘的路线，倒过来读就是从这个棋盘到目标的路线。一次 BFS 就能得到一本"答案电话簿"：

bfs_tree["12345678x"]
→ ""（已经解好了）
bfs_tree["12345x786"]
→ "d"
bfs_tree["23415x768"]
→ "ullddrurdllurrdlurd"

答案簿建好之后，回答任何棋盘都只需要查一次字典，几乎是瞬间完成。不在答案簿里的棋盘就是无解的。

为什么字母看起来是反的

这是每个人一开始都会搞糊涂的地方，我们慢慢来。BFS 从目标出发，把空格远离目标移动。可是我们存下来的答案必须把空格移回目标。所以每个字母都要反过来：

→

要解开 12345x786，空格必须往下移回去。所以移动表里把位置变化 −3 和字母 "d" 配成一对：

moves_table.py
moves = [(-3, "d"), (3, "u"), (-1, "r"), (1, "l")]
# BFS 把空格往上移 (-3)  -> 答案要把它往下移 ("d")
# BFS 把空格往下移 (+3)  -> 答案要把它往上移 ("u")
# BFS 把空格往左移 (-1)  -> 答案要把它往右移 ("r")
# BFS 把空格往右移 (+1)  -> 答案要把它往左移 ("l")

为什么新字母要放在最前面

假设 BFS 正在棋盘 A，答案簿里已经写着 A 需要走 "lu" 才能到目标。现在 BFS 从 A 走到一个新棋盘 B。要解开 B，你必须先撤销这一步（回到 A），然后再按 A 的步骤走。所以新字母要放在最前面：

bfs_tree[B] = 回到A的字母 + bfs_tree[A]

如果把它加在末尾，步骤的顺序就错了，空格最后会跑到奇怪的地方去。

eight_puzzle.py（修复版，逐行注释）
from collections import deque     # deque 是一种快速队列：从队尾加入，从队头取出

config = ["1", "2", "3", "4", "5", "6", "7", "8", "x"]   # 目标棋盘，一格一格列出来（"x" 是空格）
target = "".join(config)          # 把它们拼成一个字符串："12345678x"
bfs_tree = {target: ""}           # 答案簿：棋盘 -> 解开它的步骤（"" 表示已经解好）

# each thing in the queue is (state, pos_x)：队列里每一项是（棋盘，空格位置）
q = deque([(target, target.index("x"))])   # BFS 从【目标】出发，它的空格在位置 8
moves = [(-3, "d"), (3, "u"), (-1, "r"), (1, "l")]   # (BFS 怎么移空格, 能【撤销】这一步的字母)

while q:                                        # 只要队伍里还有棋盘在等，就继续
    curr_state, pos = q.popleft()               # 取出排得最久的棋盘（先进先出）
    current_path = bfs_tree[curr_state]         # 解开这个棋盘的步骤
    for offset, solution_char in moves:         # 试着把空格往 4 个方向移
        npos = pos + offset                     # 空格的新位置
        if npos < 0 or npos >= 9:               # 从上边或下边掉出去了？
            continue                            #   那这个方向不能走
        if offset == -1 and pos % 3 == 0:       # ✅ ==  在最左列还想往左？
            continue                            #   不许穿墙！
        if offset == 1 and pos % 3 == 2:        # ✅ ==  在最右列还想往右？
            continue                            #   不许穿墙！
        state_list = list(curr_state)           # ✅ curr_state  字符串 -> 列表，才能交换
        # e.g. ["1", "2", ..., "x"]
        state_list[pos], state_list[npos] = (   # 交换空格和旁边的方块……
            state_list[npos], state_list[pos]   # ……Python 可以一次换两个
        )
        new_state = "".join(state_list)         # 列表 -> 字符串（字符串才能当字典的键）
        if new_state not in bfs_tree:           # ✅ not in  一个从没见过的棋盘？
            bfs_tree[new_state] = (solution_char +    # 先撤销这一步，
                                   current_path)      # 再按旧棋盘的步骤走
            q.append((new_state, npos))         # 以后再探索它：排到队尾

while True:                                     # ✅ 一直回答问题，直到输入结束
    try:
        s = input()                             # 读一行，例如 "2 3 4 1 5 x 7 6 8"
    except EOFError:                            # 没有更多行了？
        break                                   #   那就结束
    s = "".join(s.split())                      # 去掉所有空格："23415x768"
    if s not in bfs_tree:                       # ✅ not in  答案簿里没有？
        print("unsolvable")                     #   那怎么移动都解不开
    else:
        print(bfs_tree[s])                      # 否则直接查出答案

# 输入:  2 3 4 1 5 x 7 6 8
# 输出: ullddrurdllurrdlurd
在棋盘上验证答案

把起始棋盘 2 3 4 1 5 x 7 6 8 输入第 8 关的求解器，然后点"播放"。你会看到 ullddrurdllurrdlurd 这 19 步把方块全部送回家。Python 建答案簿不到一秒，之后每个棋盘都是瞬间回答。

你注意到了吗？第 4 关的 bfs_solve 对同一个棋盘给出的是另一个 19 步答案（ullddrurdllurdruldr）。两个都对！很多棋盘有好几种最短解法，得到哪一种取决于四个方向的尝试顺序。所以这道题的评测系统接受任何一种正确的解法。

第 7 关

奇偶性的秘密：为什么一半的棋盘无解

棋盘一共有 9! = 362,880 种，可答案簿里恰好只有 181,440 条：正好一半。另一半无论你多聪明都解不开。为什么？

按阅读顺序写下方块，跳过空格。一个逆序对就是顺序反了的一对方块：大的数排在了小的数前面。

2
1
3
4
5
6
7
8

阅读顺序：2 1 3 4 5 6 7 8
顺序反了的对：只有 (2, 1)
→ 1 个逆序对（奇数）

现在看看每种移动对逆序对有什么影响：

  • 左右移动：空格和同一行的方块交换，方块的阅读顺序完全不变。逆序对：+0。
  • 上下移动：一个方块在阅读顺序里正好跳过了另外 2 个方块。这 2 对的顺序各自翻转一次，所以逆序对的数量变化 −2、0 或 +2。

不管哪种情况，变化量都是偶数，所以逆序对是奇数还是偶数（它的奇偶性）永远不会改变。目标棋盘有 0 个逆序对，是偶数。所以逆序对为奇数的棋盘永远到不了目标！

parity.py
def inversions(state):
    tiles = [c for c in state if c != "x"]   # 阅读顺序，去掉空格
    count = 0
    for i in range(len(tiles)):
        for j in range(i + 1, len(tiles)):
            if tiles[i] > tiles[j]:           # 大的在小的前面：顺序反了
                count += 1
    return count

def solvable(state):
    return inversions(state) % 2 == 0         # 偶数 -> 有解，奇数 -> 无解

print(inversions("23415x768"), solvable("23415x768"))   # 4 True
print(inversions("21345678x"), solvable("21345678x"))   # 1 False

# 和第 6 关的答案簿对照一下：
print(len(bfs_tree))                              # 181440
print(all(solvable(s) for s in bfs_tree))         # True
没人赢得的 1000 美元

萨姆·劳埃德那道著名的挑战题，是一个只把 14 和 15 两块交换了的 15 数码：恰好一个逆序对。类似的奇偶性论证可以证明它无解，所以那笔奖金一直都很安全。我们的 BFS 用"暴力"证明了八数码的版本：362,880 个棋盘里，能到达的恰好是逆序对为偶数的那 181,440 个。

这给了我们一个闪电般的测试：搜索之前先数逆序对。如果是奇数，直接输出 unsolvable，完全不用搜索。

🤖 瞬间求解器

输入 9 个符号（数字 1–8 和一个 x），有没有空格都行；也可以直接用第 1 关游戏里的棋盘。

A*：带着方向感去搜索

BFS 很公平，但它是"瞎"的：它向所有方向平均扩散，连远离目标的方向也不放过。A*（读作"A-star"）更聪明。它会估计每个棋盘离目标还有多远，并且总是先探索最有希望的棋盘。

一个好的估计是曼哈顿距离：对每个方块，数一数它离自己的家差几行加几列，再把它们加起来。每一步只能把一个方块移动一格，所以你需要的步数永远不可能少于这个数。因为这个估计从不高估，A* 仍然保证能找到最短解法。

astar.py
import heapq

def manhattan(state):
    total = 0
    for i, c in enumerate(state):
        if c != "x":
            home = int(c) - 1                 # 方块 1 的家在位置 0，依此类推
            total += abs(i // 3 - home // 3) + abs(i % 3 - home % 3)
    return total

def astar(start, goal="12345678x"):
    best = {start: 0}                         # 到每个棋盘目前找到的最少步数
    heap = [(manhattan(start), 0, start, "")] # (总步数估计, 已走步数, 棋盘, 路线)
    explored = 0
    while heap:
        f, g, s, path = heapq.heappop(heap)   # 最有希望的棋盘
        if g > best[s]:                       # 过时的、更差的记录：跳过
            continue
        explored += 1
        if s == goal:
            return path, explored
        for letter, t in neighbours(s):
            if t not in best or g + 1 < best[t]:
                best[t] = g + 1
                heapq.heappush(heap, (g + 1 + manhattan(t), g + 1, t, path + letter))
    return None, explored

path, explored = astar("23415x768")
print(len(path), explored)        # 19 651

该用哪一个？
  • 棋盘很多、谜题很小（3×3）：做一次倒推 BFS，然后逐个查答案。这就是示例代码的做法。
  • 只有一个棋盘、谜题更大（4×4）：15 数码能到达的棋盘超过 10 万亿个，根本存不下。用带好估计的 A*（或者它省内存的表亲 IDA*）才是正道。
小测验

概念快问快答

1. 为什么 BFS 第一次找到某个棋盘的路线一定是最短的？

因为队列是先进先出的。所有 1 步远的棋盘都会在 2 步远的棋盘之前取出，2 步远的又在 3 步远的之前，依此类推。所以 BFS 第一次到达某个棋盘时，所有更短的路线都已经探索完了。如果真有更短的路线，BFS 早就该更早找到这个棋盘了。

2. 示例代码里为什么是 solution_char + current_path，而不是 current_path + solution_char？

新棋盘比当前棋盘离目标更远一步。要解开它，你必须先走回到当前棋盘的那一步（solution_char），然后再按当前棋盘的步骤走（current_path）。先做的事放在前面。

3. 1 2 3 / 4 5 6 / 8 7 x 能解开吗？不许运行任何搜索来回答。

阅读顺序（跳过空格）：1 2 3 4 5 6 8 7。唯一顺序反了的对是 (8, 7)，所以有 1 个逆序对，是奇数。奇偶性永远不会改变，而目标有 0 个逆序对，所以这个棋盘无解。

1. 位置侦探 ★

写一个 to_rc(pos)，把位置（0–8）变成 (row, col)，再写一个 to_pos(row, col) 做相反的事。检查一下，对全部 9 个格子，这两个函数都能互相还原。

💡 提示

正着算用 // 和 %。反着算：每一行占 3 个位置，所以 pos = row * 3 + col。

✅ 答案
ex1_positions.py
def to_rc(pos):
    return pos // 3, pos % 3

def to_pos(row, col):
    return row * 3 + col

print(to_rc(5), to_rc(7))                                 # (1, 2) (2, 1)
print(to_pos(1, 2), to_pos(2, 1))                         # 5 7
print(all(to_pos(*to_rc(p)) == p for p in range(9)))      # True

💡 提示

3. 答案检查器 ★★

写一个 apply_moves(state, moves)，按照 "ullddr" 这样的步骤字符串移动（每个字母是空格移动的方向），返回最后的棋盘；如果某一步会走出棋盘，就返回 None。用它验证示例代码的答案真的能解开 23415x768。

💡 提示

把 neighbours(state) 变成字典 {字母: 新棋盘}。如果字母不在字典里，这一步就不合法。

✅ 答案
ex3_apply.py
def apply_moves(state, moves):
    for m in moves:
        options = dict(neighbours(state))   # 例如 {"u": "...", "d": "...", "l": "..."}
        if m not in options:
            return None                     # 这一步会走出棋盘
        state = options[m]
    return state

print(apply_moves("23415x768", "ullddrurdllurrdlurd"))   # 12345678x
print(apply_moves("23415x768", "r"))                     # None  (空格在最右列)

5. 涟漪普查 ★★

用 bfs_tree 数一数恰好需要 0、1、2……步的棋盘各有多少个。（每个答案字符串的长度就是它的步数。）哪个距离的棋盘最多？

💡 提示

collections.Counter 会帮你计数：Counter(len(p) for p in bfs_tree.values())。

✅ 答案
ex5_census.py
from collections import Counter

census = Counter(len(path) for path in bfs_tree.values())
print([census[d] for d in range(6)])         # [1, 2, 4, 8, 16, 20]
print(max(census))                           # 31  (最远的一圈)
print(max(census, key=census.get))           # 24  (最大的一圈)

7. 五数码（2×3） ★★★

一个更小的版本有 2 行 3 列：方块 1–5 和一个空格，目标是 12345x。改一改倒推 BFS，让它能处理这个谜题。有多少个棋盘有解？最难的棋盘是哪个？

💡 提示

只有棋盘大小变了：位置是 0–5 而不是 0–8。每行还是 3 个格子，所以上下还是 ±3，用 % 3 的边界检查也不变。

✅ 答案
ex7_five_puzzle.py
from collections import deque

goal = "12345x"
book = {goal: ""}
q = deque([(goal, goal.index("x"))])
moves = [(-3, "d"), (3, "u"), (-1, "r"), (1, "l")]
while q:
    s, pos = q.popleft()
    for offset, ch in moves:
        npos = pos + offset
        if npos < 0 or npos >= 6:                 # 现在只有 6 个格子
            continue
        if offset == -1 and pos % 3 == 0:
            continue
        if offset == 1 and pos % 3 == 2:
            continue
        cells = list(s)
        cells[pos], cells[npos] = cells[npos], cells[pos]
        t = "".join(cells)
        if t not in book:
            book[t] = ch + book[s]
            q.append((t, npos))

print(len(book))                                  # 360  (= 6! / 2)
far = max(book, key=lambda s: len(book[s]))
print(far, len(book[far]))                        # 45x123 21

8. BFS 对决 A* ★★★

对下面三个有解的棋盘，比较第 4 关的 bfs_solve() 和第 8 关的 astar()。它们找到的解法长度总是一样吗？哪一个探索的棋盘更少？

for board in ["23415x768", "8134x2765", "x87654321"]:
    p1, n1 = bfs_solve(board)

每次长度都一样，因为两者都保证找到最优解。但 A* 只做了很小一部分工作，因为曼哈顿距离的估计一直把它指向目标。
