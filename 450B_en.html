Jzzhu's Echo Machine: A Sequence That Repeats Every 6 Steps

Jzzhu built a number machine with a strange rule: each new number is the difference of the two numbers before it. Feed it a starting pair, and something surprising happens — the whole sequence starts echoing itself every 6 steps, forever. Codeforces 450B asks you to find the n-th number the machine ever prints, even when n is 2 billion.

For curious 13-year-olds One new trick: the 6-step echo Interactive
LEVEL 1

Meet the machine

Jzzhu's sequence starts with two numbers you get to pick: f₁ = x and f₂ = y. After that, every new number follows one strict rule:

fi = fi−1 − fi−2    (for every i > 2)

In plain words: to get the next number, take the number right before it and subtract the number before that. Your job: given x, y, and a step number n, print fn — but since these numbers can get huge (or very negative), print it modulo 1,000,000,007.

Straight from the judge

x=2, y=3, n=3 → 1. The note explains it as f₂ = f₁ + f₃, so 3 = 2 + f₃, so f₃ = 1 — which is exactly y − x.
x=0, y=−1, n=2 → 1000000006. We just want f₂, which is y itself: −1. Since we can't print a negative number as "the answer," we report it modulo 1,000,000,007, and −1 becomes 1,000,000,006 (one step before wrapping back around to 0).

Why should you care?

n can be as large as 2,000,000,000 — two billion! x and y can be up to a billion in size (positive or negative) too. A machine that prints one number per step and computes two billion of them, one at a time, is not going to finish in the 1-second time limit this problem gives you.

LEVEL 2

This smells like a clock

Think about the hour hand on a clock. It doesn't count forever upward — 1, 2, 3… 47, 48… — it counts to 12 and then wraps back around to 1. If you know the clock repeats every 12 hours, you don't need to simulate every single hour since the beginning of time to know what it'll show at "hour 9,000." You just need to know the pattern, and where in the pattern hour 9,000 lands.

Jzzhu's sequence has the exact same personality. It won't literally repeat the number 12 — but as you'll see in a moment, the whole pattern of six numbers repeats forever. Once we find that pattern, we never need to compute f1000 by grinding through 998 subtractions. We just figure out where step 1000 falls in the 6-step loop.

LEVEL 3

Why "just compute every step" fails

The rule fi = fi−1 − fi−2 is easy to code as a loop: keep two numbers in memory, subtract, shift, repeat, n times. The catch is that n. With n up to 2 billion, a loop that does one tiny subtraction per step still has to run 2 billion times — and most judges, including this one, expect your program to finish in about 1 second. Computers are fast, but not "2 billion careful steps in one second, with room to spare" fast, especially once you add in reading input and other overhead.

LEVEL 4

The key insight: crank the handle and watch it echo

Let's not skip ahead — let's just turn the crank by hand and see what happens. We know f₁ = x and f₂ = y. Apply the rule fi = fi−1 − fi−2 again and again:

steprule appliedvalue
f₁givenx
f₂giveny
f₃f₂ − f₁y − x
f₄f₃ − f₂ = (y−x) − y−x
f₅f₄ − f₃ = −x − (y−x)−y
f₆f₅ − f₄ = −y − (−x)x − y
f₇f₆ − f₅ = (x−y) − (−y)x ← same as f₁!
f₈f₇ − f₆ = x − (x−y)y ← same as f₂!

Look at that — f₇ = f₁ and f₈ = f₂. And since every future number only depends on the two numbers right before it, the moment two consecutive numbers repeat, the entire rest of the sequence is forced to repeat too. The machine has looped back to its own starting pair, so from here it just echoes the same six numbers forever.

The one sentence that matters most

Only six different values ever exist: x, y, y−x, −x, −y, x−y, and then it repeats forever. To find fn, we don't need n steps — we just need to know which of the six position n lands on. And "which of six" is exactly what remainders (mod 6) are for.

LEVEL 5

Reading the code, line by line

Here's the entire solution. Read the code on the left, then the plain-English translation on the right.

jzzhu_sequence.py
MOD = 1000000007

x, y = map(int, input().split())
n = int(input())

cycle = [x, y, y - x, -x, -y, x - y]   # the 6 values, in order
answer = cycle[(n - 1) % 6]        # which of the 6 does step n land on?

print(answer % MOD)
cycle = [x, y, y - x, -x, -y, x - y]
The six values we hand-derived in Level 4, stored in order starting from f₁. This list is index 0 through 5, holding f₁ through f₆.
cycle[(n - 1) % 6]
Step n corresponds to list index n−1 (since f₁ is index 0). Taking that % 6 wraps any huge n back into the range 0–5 — instant lookup, no matter how big n is.
print(answer % MOD)
Python's % always returns a non-negative result for a positive modulus, even when answer is negative — so this one line handles both the modulo and the "no negative answers allowed" rule at once. (More on this surprising fact in the next Level!)

LEVEL 6

A Python gotcha worth knowing: negative numbers and %

Let's trace both judge examples by hand, because one of them hides a neat surprise.

xyn(n−1) mod 6cycle valueanswer mod 1e9+7
2332 → y−x3−2 = 11
0−121 → y−11000000006

The second row is the interesting one. In Python, -1 % 1000000007 is not -1 — it's 1000000006, automatically. Python's % operator was designed so the result always has the same sign as the divisor (here, a positive number), so a negative input quietly gets nudged into the correct positive range. Try it yourself in a Python shell:

python shell
>>> -1 % 1000000007
1000000006
>>> -8 % 6
4
Careful if you ever switch languages

This is a Python-specific kindness! In languages like JavaScript, C++, or Java, -1 % 1000000007 gives you -1 back, not 1000000006. In those languages you have to fix it yourself with a pattern like ((answer % MOD) + MOD) % MOD. The interactive tool below is written in JavaScript, so peek at its code and you'll spot exactly that pattern in action.

LEVEL 8

Practice: crack these before you check with the tool

Work each one out on paper first — then verify with the widget above.

Exercise 1: x=5, y=8. What is f₃, f₄, and f₇? What do you notice about f₇?

f₃ = y − x = 8 − 5 = 3. f₄ = −x = −5. f₇ is always equal to f₁, so f₇ = x = 5. That's the echo in action — six steps later, we're right back where we started.

Exercise 2: x=1, y=1, n=1000000. Which of the 6 cycle values is the answer? (Hint: you don't need a calculator that can subtract a million things.)

We need (n−1) % 6 = 999999 % 6. Since 999999 = 6 × 166666 + 3, the remainder is 3, which is index 3 in our list [x, y, y-x, -x, -y, x-y] — that's -x = -1. Mod 1,000,000,007, that's 1000000006.

Exercise 3: Why exactly 6, and not some other number? Could it ever be a shorter loop, like 3?

The loop length is forced by algebra: starting from (f₁, f₂) = (x, y), applying the subtraction rule six times always produces (x, y) again, no matter what x and y are — we proved that by hand in Level 4. It can "close early" in special cases: if x=0 and y=0, every term is 0, so the sequence trivially repeats with period 1 (which technically also divides 6, so it's not really a contradiction — 6 is just an upper bound on how long the echo can take to return).

Exercise 4: Modify the code so it prints all 6 cycle values (f₁ through f₆) modulo 1,000,000,007, instead of just fn.
jzzhu_sequence_all.py
MOD = 1000000007

x, y = map(int, input().split())

cycle = [x, y, y - x, -x, -y, x - y]
for value in cycle:
    print(value % MOD)
Exercise 5 (challenge): x=1000000000, y=-1000000000, n=2000000000. Work out the answer by hand, then check it in the widget.

(n−1) % 6 = 1999999999 % 6. Since 1999999999 = 6 × 333333333 + 1, the remainder is 1, meaning the answer is y = -1000000000. Modulo 1,000,000,007, a negative number this size becomes 1000000007 - 1000000000 = 7.
