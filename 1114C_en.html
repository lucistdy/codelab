Trailing Loves: Counting Zeros at the End of a Giant Factorial

n! for n as big as 1018 has so many digits it couldn't fit on every hard drive on Earth — and you're asked to write it in some strange base b and count how many zeros sit at the very end. You will never build the actual number. You'll count its zeros anyway, in well under a second.

LEVEL 1

The mission, straight from the judge

You're given two whole numbers: n (up to 1018) and a base b (from 2 up to 1012). Compute n! = 1 × 2 × 3 × \cdots × n — the factorial of n — write it out in base b instead of the usual base 10, and count how many zeros appear at the end of that write-up.

Straight from the judge

n=6, b=9 → 1  (because 6! = 720, and 720 in base 9 is written 880 — one trailing zero)
n=5, b=2 → 3  (because 5! = 120, and in binary that's 1111000 — three trailing zeros)
n=5, b=10 → 1  (same 120, but ordinary base 10 only has one trailing zero)

Why you can't just compute n! directly

n can be a billion billion. n! for even a modest n like 106 already has millions of digits — for n = 1018, the actual number would need more digits than there are atoms in the observable universe to write down. We need a way to count trailing zeros without ever building the number itself.

LEVEL 2

What a trailing zero actually means

In any base b, a number's digits represent how many 1's, b's, b²'s, b³'s, and so on it's built from. A trailing zero in the last digit means "zero 1's." A trailing zero in the last two digits means "zero 1's and zero b's" — which is exactly the same as saying the whole number is a clean multiple of b².

In general: a number has at least k trailing zeros in base b exactly when it's evenly divisible by bk. So "count the trailing zeros of n! in base b" is really asking: what is the largest power of b that divides n! evenly? That's a question about divisibility, not about writing out any digits at all.

LEVEL 3

Warm-up: the classic base-10 version of this puzzle

You may already know a famous puzzle: how many trailing zeros does n! have in ordinary base 10? Since 10 = 2 × 5, a trailing zero needs one factor of 2 and one factor of 5. Multiples of 2 are everywhere in 1×2×3×\cdots×n (every other number!), but multiples of 5 are rarer — so the number of 5's is always the bottleneck.

To count how many times the prime 5 divides into n!, we can't just count multiples of 5 — numbers like 25 contribute two factors of 5, not one, and 125 contributes three. The clean way to count all of them is called Legendre's formula:

⌊n/p⌋
+
⌊n/p²⌋
+
⌊n/p³⌋
+ …

⌊n/p⌋ counts every multiple of p up to n — each contributes at least one factor of p. ⌊n/p²⌋ counts multiples of p², each of which contributes one extra factor beyond the first (that's why we add it separately, instead of double-counting from scratch). And so on for p³, p⁴, \ldots until the powers of p exceed n and the terms become 0.

Quick check: how many trailing zeros does 12! have in base 10?

Count 5's in 12!: ⌊12/5⌋ + ⌊12/25⌋ = 2 + 0 = 2. Count 2's: ⌊12/2⌋+⌊12/4⌋+⌊12/8⌋ = 6+3+1=10. The 5's run out first, so 12! has exactly 2 trailing zeros in base 10. (Check: 12! = 479001600 — yes, two zeros at the end.)

LEVEL 4

Generalizing: what if b isn't prime?

Level 3 worked because 10 = 2 × 5 happens to be a product of two primes, each to the power 1. But our base b could be anything — a prime, a prime squared, a product of five different primes with weird exponents, whatever. We need the general version of the "5's are the bottleneck" idea.

Every whole number b breaks down uniquely into primes: b = p₁e₁ × p₂e₂ × \cdots × pₖeₖ. For n! to be divisible by bk, it needs to contain at least k × eⁱ copies of every prime pⁱ in b's recipe. If n! contains Eⁱ copies of pⁱ in total (found with Legendre's formula from Level 3), then the largest k that still works for that one prime is ⌊Eⁱ / eⁱ⌋.

The bottleneck is whichever prime runs out first

Since every prime in b's recipe has to keep up, the true answer is the smallest of these values across all the primes in b: answer = minⁱ( ⌊Eⁱ / eⁱ⌋ ). This is exactly the same reasoning as "5's are rarer than 2's" from Level 3 — just extended to however many primes (and however large their exponents) happen to make up b.

Sanity check with sample 1: b = 9 = 3², so there's only one prime to worry about, with exponent 2. 6! contains ⌊6/3⌋+⌊6/9⌋ = 2+0 = 2 copies of the prime 3. Answer: ⌊2/2⌋ = 1 trailing zero — matching the judge exactly.

LEVEL 5

Two ingredients we still need to build

Level 4 gives us the plan; now we need two fast tools to actually carry it out.

Ingredient A — factorize b. Since b ≤ 1012, we can find all its prime factors with the same √b trial-division shortcut from the Prime Factorization page: test divisors from 2 upward, dividing out each one fully before moving on, and stop once the candidate divisor passes √b (whatever's left over, if bigger than 1, is one last prime factor).

factorize.py
def factorize(b):
    factors = {}
    d = 2
    while d * d <= b:
        while b % d == 0:
            factors[d] = factors.get(d, 0) + 1
            b //= d
        d += 1
    if b > 1:
        factors[b] = factors.get(b, 0) + 1
    return factors

Ingredient B — Legendre's formula. For any prime p, count how many times it divides n! by summing ⌊n/p⌋ + ⌊n/p²⌋ + \cdots from Level 3:

exponent_in_factorial.py
def exponent_in_factorial(n, p):
    total = 0
    power = p
    while power <= n:
        total += n // power
        power *= p
    return total

Why the Legendre loop is so short

Each trip through the loop multiplies power by p (at least 2), so after roughly log₂(n) steps power blows past n and the loop stops. For n = 1018, log₂(1018) ≈ 60. Doubling grows unbelievably fast — the same idea behind the fast exponentiation trick, just running in reverse here.

Writing it in Python

Combine Levels 4 and 5: factorize b, use Legendre's formula on each of its prime factors, divide each exponent by how many copies b needs, and take the minimum.

Here's the complete program:

trailing_zeros.py
def factorize(b):
    factors = {}
    d = 2
    while d * d <= b:
        while b % d == 0:
            factors[d] = factors.get(d, 0) + 1
            b //= d
        d += 1
    if b > 1:
        factors[b] = factors.get(b, 0) + 1
    return factors

def exponent_in_factorial(n, p):
    total = 0
    power = p
    while power <= n:
        total += n // power
        power *= p
    return total

def trailing_zeros(n, b):
    factors = factorize(b)
    return min(
        exponent_in_factorial(n, p) // e
        for p, e in factors.items()
    )

n, b = map(int, input().split())
print(trailing_zeros(n, b))

LEVEL 9

Your turn: practice challenges

Work these out with pencil and paper first, then check yourself with the tool above.

Challenge 1: How many trailing zeros does 10! have in base 10?

Count 5's: ⌊10/5⌋ = 2. Count 2's: ⌊10/2⌋+⌊10/4⌋+⌊10/8⌋ = 5+2+1=8. The 5's run out first: answer 2. (Check: 10! = 3628800.)

Challenge 2: How many trailing zeros does 10! have in base 4 (4 = 2²)?

Only one prime, 2, with exponent 2 in b. From Challenge 1, 10! has 8 copies of the prime 2. Answer: ⌊8/2⌋ = 4.

Challenge 3: Why does the algorithm take the minimum across b's prime factors, rather than, say, the sum or the average?

Because n! is only divisible by bk if it has enough copies of every single prime in b's recipe, all at the same time — it's an "all must succeed" requirement, not "on average, close enough." If even one prime in b can only support k=1 while the others could support k=100, the whole number b2 still fails to divide n!, because that one scarce prime isn't there twice. The minimum is exactly the rule for "the weakest link decides."

Challenge 4 (harder): Could the answer ever be 0? Give a concrete example of n and b where it is.

Yes — whenever some prime factor of b doesn't appear in n! at all, or doesn't appear often enough for even one full copy of b. For example, n=3, b=25=5²: 3! = 6 contains zero copies of the prime 5 (⌊3/5⌋=0), so ⌊0/2⌋=0 trailing zeros. Makes sense: 6 in base 25 is just the single digit 6 — no trailing zero at all.

Challenge 5: Modify the Python code so it also prints out, for each prime factor of b, exactly how many copies of that prime n! contains and how many are needed — useful for seeing which prime is the bottleneck.
trailing_zeros_debug.py
def trailing_zeros_debug(n, b):
    factors = factorize(b)
    best = None
    for p, e in factors.items():
        available = exponent_in_factorial(n, p)
        k = available // e
        print(f"prime {p}: n! has {available} copies, b needs {e} per zero -> supports {k} zeros")
        if best is None or k < best:
            best = k
    return best
