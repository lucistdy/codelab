第一关

问题所在：一步一步乘，实在太慢

任务是这样的：算出 2 的 1,000,000 次方。也就是把 2 × 2 × 2 × 2… 连续乘上一百万次。

如果电脑老老实实按部就班地算——先乘一次 2，再乘一次，再乘一次——那么每往前推进一步，就要花掉一次乘法。想要 210？那得乘 9 次。想要 21,000,000？那就是连续 999,999 次乘法，一次都省不掉。

这跟你有什么关系？

这可不只是数学课上的花活儿。保护你的密码、消息、网购交易安全的加密技术（案卷后面会认识的 RSA 一类算法）全都要靠把巨大的数字乘到巨大的次方。如果电脑每次都得算上百万步，互联网早就瘫痪了。它没瘫痪，正是因为这一页要讲的技巧。

所以这一课的挑战是：能不能用远远少于一百万次乘法，算出 21,000,000？剧透一下——能，大约 20 次就够了。来看看这是怎么做到的。

第二关

核心思路：平方就是抄近道

这一招你其实早就在别处见过——细胞分裂。一个细胞分裂成 2 个，这 2 个再分裂成 4 个，4 个变 8 个……每一轮数量都会翻倍，数字爆炸得飞快：只要 20 轮，就已经超过一百万个细胞了。

指数运算换个角度看，其实是同一回事。看看只做"平方"（自己乘自己）会发生什么：

仔细看：从 a¹ 一路走到 a⁸（也就是 a 的 8 次方），只用了 3 次乘法——而不是 7 次！每平方一次，指数不是加 1，而是直接翻倍：1 → 2 → 4 → 8。这和细胞分裂的翻倍速度一模一样，也正是数字能爆炸得这么快的原因：只要 20 次平方，指数就能一路冲到 220，也就是超过一百万。

全篇最重要的一句话

乘一次 a，指数加 1。平方一次，指数直接翻倍。翻倍比一步步加快得多得多——这就是整个秘密。

第三关

可指数是 13 这种数字怎么办？认识一下二进制

光靠平方，只能到达 2 的整数次幂：1、2、4、8、16、32… 可我们要的不只是 a8，说不定还要 a13。13 不是 2 的整数次幂。那只用平方，怎么凑到 13 呢？

秘诀在这里：任何一个整数，都能由若干个 2 的次幂相加拼出来。这正是"二进制"的含义。以 13 为例：

13 = 8 + 4 + 1。写成"二进制"就是 1101——用到的那几个次幂（8、4、1）底下写 1，跳过的那个（2）底下写 0。

这为什么对指数运算有用呢？幂运算有条基本规则：同一个数的几个幂相乘，指数会直接相加：a8 × a4 × a1 = a8+4+1 = a13。所以与其把 a 自己乘上 12 次，不如：

  1. 靠平方造出 a¹、a²、a⁴、a⁸——只需要 3 次乘法
  2. 把和 1101 里"1"对应的那几项乘起来：也就是 a⁸、a⁴、a¹——再加 2 次乘法

一共 5 次乘法就能算出 a13，而不是 12 次。而且指数越大，省下来的比例就越夸张——因为二进制数字的"位数"增长，比数字本身慢得多得多。这就是整套魔术的全部秘密。

第四关

顺带聊聊"取余"（钟表算术）

真正的代码不只是算巨大的幂，还会做一件事，叫"mod m"，意思是"除以 m，求余数"。其实你一辈子都在用这一招，只是没人给它起过这么正式的名字——它就是钟表算术。

一个钟表只有 12 个数字。现在是 10 点，再过 5 个小时，你不会说"15 点"，而是绕回去说 3 点。这正是 15 mod 12 = 3。一旦超过顶点，就绕回起点重新数。

在我们的代码里，每一次乘法后面都紧跟着"% m"（取余）。这能让计算过程中的每一个数字都保持很小、很好管理——永远介于 0 和 m − 1 之间——哪怕"真实"的答案（不取余的话）会有成百上千位数字。这正是为什么这个技巧能应付像一百万这么大的指数：数字根本没机会爆炸式增长。

第五关

逐行读代码

下面是案卷里真正用到的函数。不用一下子全部看懂——先看左边的代码，再看右边的大白话翻译。

fast_power.py
def fast_power(a, b, m):
    # 计算 (a 的 b 次方) % m，但绝不会真的把那个巨大的数字算出来
    result = 1
    base = a % m
    while b:                      # b 变成 0 就停下
        if b % 2 == 1:
            result = result * base % m
        base = base * base % m    # 这一行就是"翻倍"
        b = b // 2
    return result

print(fast_power(2, 1000000, 1000000007))
result = 1 base = a % m
result 一开始是空的（乘以 1 不会改变任何东西）。base 一开始就是我们的第一个幂，也就是 a¹——而且已经先做过取余了。
while b:
只要指数还没处理完，就继续循环。每绕一圈，处理的都是 b 的二进制里的一位。
if b % 2 == 1: result = result * base % m
看看当前这一位是不是 1？如果是，说明这个幂要用在最终答案里——把它乘进去。如果是 0，就跳过，用不上。
base = base * base % m
这就是第二关讲的翻倍动作：把 base 平方一下，变成下一级的幂——a¹ 变 a²，a² 变 a⁴，a⁴ 变 a⁸…
b = b // 2
把指数砍掉一半（丢掉刚用过的那一位）。这样只要大约 log₂(b) 轮，b 就能归零——对一百万来说，大约只要 20 轮。
冷知识档案

其实 Python 早就把这个超能力内置好了，你都不用自己写：pow(a, b, m) 是一个自带函数，第三个参数的意思正是"顺便取余"，底层用的正是你刚学的快速幂技巧！

挑战三：为什么循环只要大约 log₂(b) 轮，而不是 b 轮？

每一轮都会把 b 除以 2（b = b // 2）。从一个大数字开始不断对半砍，直到砍到 0 为止——这正是"log₂"衡量的东西：它问的是"这个数能被对半砍多少次？"对 b = 1,000,000 来说，答案大约是 20，因为 220 已经超过一百万了。这就是为什么 20 轮就够了——每一轮做的事情，都相当于把上一轮能覆盖的范围再翻一倍。
