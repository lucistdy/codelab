Magic Five: Only the Last Digit Matters

Iahub has a long strip of digits — a string a, copy-pasted k times back to back — and he wants to erase some digits (not all of them) so the leftover number is divisible by 5. Codeforces 271C asks: in how many different ways can he choose which digits to erase? The strip can hold up to 100,000,000,000,000 digits, so counting one erasure at a time is out of the question.

LEVEL 1

The mission

You're given a digit string a, and a number k. The full "plate" s is just a written out k times in a row (so if a = "12" and k = 3, the plate is "121212"). You get to erase any digits you like from the plate — but you can't erase every digit; at least one must survive. Whatever's left, read left to right, forms a number (leading zeros are okay — 007 just means 7, and here it's fine if it looks like 007).

Count how many different ways there are to erase digits so that the surviving number is divisible by 5. Two ways are "different" if the set of positions you erased is different — even if the leftover numbers happen to look identical. Print the count modulo 1,000,000,007.

Straight from the judge

a="1256", k=1 → 4. The plate is just 1256. The four winning erasures leave behind 5, 15, 25, and 125 — all divisible by 5.
a="555", k=2 → 63. The plate is 555555 (six 5's). Any non-empty selection of those six 5's is divisible by 5, and there are 2⁶ − 1 = 63 non-empty subsets.
a="13990", k=2 → 528. The plate is 1399013990 — remember, it's two copies of a glued together, not just a itself!

Why should you care?

a can be up to 100,000 digits long, and k can be up to 1,000,000,000. That means the plate can have up to 100,000,000,000,000 digits — 100 trillion! You could never even print that string, let alone loop over every digit in it one at a time within a 1-second time limit.

LEVEL 2

The one fact that cracks this whole problem open

Here's something you probably already know, even if you never said it out loud: a number is divisible by 5 exactly when its last digit is 0 or 5. 2,847,530? Divisible — ends in 0. 2,847,533? Not divisible — ends in 3. It doesn't matter how long the number is, or what any of the earlier digits are. Only the very last digit decides.

Why does this work? Every digit except the last one is sitting in the tens place, the hundreds place, the thousands place, and so on — and 10, 100, 1000… are all multiples of 5 (since 10 = 2×5). So every digit except the last one contributes a multiple of 5 to the total, which can never change whether the number is divisible by 5. The last digit is the only one that isn't automatically "safe" — it's the one and only tiebreaker.

Cold Case File

This "only the remainder matters" way of thinking is exactly the clock-face math from the Prime Number Detective Agency page. Here, the "clock" has just 5 positions (0, 1, 2, 3, 4), and only digits ending in 0 or 5 land on position 0.

LEVEL 3

Why "try every erasure" is hopeless

If the plate has n digits, there are 2n ways to choose which digits to keep (each digit is either kept or erased — two choices, multiplied together). With n up to 100 trillion, that number isn't just big, it's unimaginably big — far more than the number of atoms in the observable universe. No computer will ever list them all. We need a way to count the winning erasures using a formula, without generating a single one of them.

LEVEL 4

The key insight: fix the last surviving digit

From Level 2, we know exactly what makes a surviving number divisible by 5: its last surviving digit must be a 0 or a 5. So let's flip the question around: instead of asking "which erasure works?", let's ask, for each position in the plate that holds a 0 or a 5: "how many erasures make this the last digit left standing?"

Say that position has exactly i digits sitting before it (counting from the very start of the plate). To make it the last survivor:

  • Every digit after it must be erased — no choice, exactly 1 way.
  • Every digit before it can be kept or erased, it doesn't matter which — that's 2 choices for each of the i digits, giving 2i combinations.
  • The digit itself is always kept (that's the whole point).

So a single good position contributes exactly 2i winning erasures. Add up 2i over every position holding a 0 or 5, and you've counted every winning erasure exactly once — because every winning erasure has exactly one "last surviving digit," so it gets counted at exactly one position.

The one sentence that matters most

Answer = the sum of 2i over every position i (0-indexed from the start of the plate) whose digit is 0 or 5.

LEVEL 5

Using the k copies: a geometric series

The formula from Level 4 is correct, but summing 2i one position at a time still means visiting up to 100 trillion positions. Here's the shortcut: the plate is just k back-to-back copies of the same short string a (length L). A position at "copy number j (starting from 0), offset p inside a" sits at global position i = j×L + p, so its contribution is 2jL+p = 2jL × 2p.

Group all the good positions by which copy of a they're in. Every copy has the same good offsets p, so every copy contributes the same inner sum — let's call it S = sum of 2p over good offsets p in one copy of a. Copy j's total contribution is then S × 2jL, or S × rj where r = 2L. Adding up all k copies:

answer = S × (r⁰ + r¹ + r² + … + rk−1)

That parenthesized sum is a classic geometric series. There's a closed-form shortcut for it: (rk − 1) / (r − 1) (when r ≠ 1; if r = 1 the sum is just k, since every term equals 1). Computing rk takes only O(log k) multiplications using fast exponentiation, and "dividing" modulo a prime means multiplying by a modular inverse.

Cold Case File

Computing rk mod M quickly is exactly the Fast Exponentiation trick. And the modular inverse (r−1)−1 is computed as pow(r−1, M−2, M) — which works because of Fermat's Little Theorem, the very same fact that powers the tests on the Fermat Lie Detector page.

LEVEL 6

Reading the code, line by line

Here's the entire solution. Read the code on the left, then the plain-English translation on the right.

magic_five.py
MOD = 1000000007

a = input().strip()
k = int(input())
L = len(a)

S = 0
power = 1
for ch in a:
    if ch == '0' or ch == '5':
        S = (S + power) % MOD
    power = power * 2 % MOD

r = pow(2, L, MOD)              # 2^L mod MOD, via fast exponentiation
if r == 1:
    geo = k % MOD
else:
    geo = (pow(r, k, MOD) - 1) * pow(r - 1, MOD - 2, MOD) % MOD

print(S * geo % MOD)

LEVEL 9

Practice: crack these before you check with the tool

Work each one out on paper first — then verify with the widget above.

Exercise 1: a="5", k=1. Why must the answer be exactly 1?

The plate is just the single digit 5. You're not allowed to erase every digit, and there's only one digit to begin with — so the only legal move is to keep it. S = 2⁰ = 1, r = 2¹ = 2, and with k=1 the geometric sum is just r⁰ = 1. Answer: 1 × 1 = 1.

Exercise 2: a="05", k=1. There are 3 non-empty ways to erase digits from "05" — why are all 3 of them winners?

The three non-empty subsequences are "0", "5", and "05" (which is just the number 5 with a leading zero). Every single one ends in 0 or 5, so by the Level 2 rule, all three are divisible by 5. Using the formula: position 0 ('0') contributes 2⁰=1, position 1 ('5') contributes 2¹=2, total S=3. With k=1, the geometric sum is 1, so the answer is 3.

Exercise 3: a="20", k=3 (so the plate is "202020"). Work out the answer using the geometric series shortcut, not by listing all 63 subsequences.

Only offset p=1 (the digit 0) is good, so S = 2¹ = 2. L=2, so r = 2² = 4. The geometric sum for k=3 is 4⁰+4¹+4² = 1+4+16 = 21. Answer: S × 21 = 2 × 21 = 42. (You can sanity-check this by noticing the zeros sit at positions 1, 3, and 5 in "202020", contributing 2¹+2³+2⁵ = 2+8+32 = 42 — same answer, the slow way.)

Exercise 4: Why doesn't it matter which digits appear before a good position — couldn't some earlier choices somehow break divisibility by 5?

No — and that's the whole magic of Level 2's fact. Divisibility by 5 depends only on the last surviving digit. Once that last digit is locked in as a 0 or 5, every digit before it just shifts the number by a multiple of 10 (adding more tens, hundreds, thousands…), and since 10 is itself a multiple of 5, none of that can ever change whether the whole number is divisible by 5. That's exactly why those earlier digits are "free" — keep them or erase them, it doesn't affect the answer at all.

Exercise 5 (challenge): Modify the code to instead count erasures that leave a number divisible by 2. What changes, and what stays exactly the same?

Divisibility by 2 also depends only on the last digit (10 is a multiple of 2 as well!) — so the whole strategy carries over unchanged. The only change is which digits count as "good": instead of ch == '0' or ch == '5', you'd check ch in '02468'. Everything else — the per-copy sum S, the geometric series over k copies, the modular inverse — stays exactly the same.

magic_two.py
MOD = 1000000007

a = input().strip()
k = int(input())
L = len(a)

S = 0
power = 1
for ch in a:
    if ch in '02468':
        S = (S + power) % MOD
    power = power * 2 % MOD

r = pow(2, L, MOD)
if r == 1:
    geo = k % MOD
else:
    geo = (pow(r, k, MOD) - 1) * pow(r - 1, MOD - 2, MOD) % MOD

print(S * geo % MOD)
