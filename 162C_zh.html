质因数分解：每个数字自己的独家配方

每一个大于 1 的整数，背后都偷偷藏着一份由质数相乘组成的"配方"——而且这份配方是唯一的。你的任务：给定一个数 n，把它的配方原原本本地打印出来，从最小的质数开始。

不需要数学基础 循环与质数 可以互动
第一关

任务目标，原样来自题目

给你一个整数 n（在 2 到 10,000 之间）。每一个这样的数字都能写成若干个质数相乘的形式——这就是它的质因数分解。你的任务是把这个乘积打印出来，因子按从小到大排列，用 * 隔开，重复出现的质数就重复打印。

题目原样给出的例子

n = 245 → 5*7*7  （因为 245 = 5 × 7 × 7）
n = 19 → 19  （19 本身就是质数，配方里只有它自己这一种"原料"）

值得记住的事实：算术基本定理

这里有件很了不起的事：对任何大于 1 的整数来说，把它写成若干质数相乘的形式，只有唯一一种方法（不算乘的顺序）。不是两种，也不是零种——正好一种。数学家把这个叫作算术基本定理，正是因为这条定理，"n 的质因数分解"才是一个有明确答案、值得去问的问题。

第二关

再复习一下：什么是质数？

质数是大于 1 的整数中，除了 1 和它自己之外没有别的因数的数——没办法把它拆成两个更小整数相乘。2、3、5、7、11、13、17、19……都是质数。而像 12 = 3 × 4 这样能被拆开的数，就叫作合数。

可以把质数想象成"数字世界的元素周期表"——所有其他数字都是靠这些"原子"相乘搭出来的。12 = 2 × 2 × 3，100 = 2 × 2 × 5 × 5，245 = 5 × 7 × 7。不管怎么拆，只要拆到底，最后剩下的永远是同一组质数"原子"。

第三关

简单的方法：一直用能整除的最小数字去除

这里有一个简单到有点不好意思的办法，但它完全管用：从 2 开始，逐个测试候选除数。只要当前的除数 d 能整除 n 剩下的部分，就把 d 记为一个因子并把它除掉——而且要用同一个 d 一直除下去，直到除不动了，才换到下一个候选数字。

手动推演一下 n = 245：

  • 试 d=2：245 是奇数，除不尽。换下一个。
  • 试 d=3：245 ÷ 3 不是整数。换下一个。
  • 试 d=4：不行。换下一个。
  • 试 d=5：245 ÷ 5 = 49，正好整除！记下一个 5，现在要分解的变成了 49。
  • 再用 d=5 试 49：49 ÷ 5 不是整数。换下一个除数。
  • 试 d=6：不行。试 d=7：49 ÷ 7 = 7，正好整除！记下一个 7，现在要分解的变成了 7。
  • 再用 d=7 试 7：7 ÷ 7 = 1，正好整除！再记下一个 7。没有剩下的可以分解了。

按找到的顺序记下的因子：5、7、7——已经是从小到大排好的，正好对上题目要求的输出 5*7*7。

为什么这不会不小心记下一个非质数的因子

注意我们总是先试最小的还没试过的除数，而且要把它彻底除干净才换下一个。这就保证了记下的每一个数字都一定是质数：如果剩下的部分还能被 4 或 6 这样的合数整除，那么这个合数更小的质因子（比如 2 或 3）早就应该已经把它除掉了——因为我们从来不跳过任何数字。

第四关

更聪明的捷径：检查到 √n 就能停

这个方法的朴素版本会一直检查除数 d = 2, 3, 4, … 直到 n 本身。但这里有个捷径：一旦 d × d 已经比当前剩下的 n 还大，就可以停下来了——剩下的部分（如果还大于 1）本身一定就是最后一个质因子。

为什么呢？如果剩下的 n 有两个都比 √n 大的因子，它们的乘积就已经比 n 还大了——这不可能。所以 n 最多只能有一个比 √n 大的因子，而如果这样的因子存在，它就一定是 n 本身（已经被彻底化简过，不会再有更小的质因子了）。

这个技巧是不是很眼熟？

这正是质数侦探事务所案卷里用来判断单个数字是不是质数的那个 √n 捷径——一旦你开始留意，会发现它在各种分解问题里反复出现。

第五关

用 Python 把它写出来

下面把第三关和第四关的整个算法写成代码。先看左边的代码，再看右边的大白话注解。

prime_factorization.py
n = int(input())

factors = []
d = 2
while d * d <= n:
    while n % d == 0:
        factors.append(d)
        n //= d
    d += 1

if n > 1:
    factors.append(n)

print("*".join(map(str, factors)))

第八关

该你练习了

先自己在纸上算出来，再用上面的工具验证。

挑战一：手动求出 n=360 的质因数分解。

360 ÷ 2 = 180，180 ÷ 2 = 90，90 ÷ 2 = 45（45 是奇数，2 用完了——一共三个 2）。45 ÷ 3 = 15，15 ÷ 3 = 5（5 不能被 3 整除——一共两个 3）。d=4 除不动 5，d=5 时 5×5=25 > 5，循环停止，剩下 n=5。最终答案：2*2*2*3*3*5。验证一下：8 × 9 × 5 = 360。✓

挑战二：最小可能的输入 n=2，输出会是什么样？

循环条件是 d*d ≤ n，也就是 4 ≤ 2，一开始就不成立——循环体一次都不会执行。因为最后 n=2 > 1，所以直接把它加进去。输出：就是 2。

挑战三：为什么需要内层循环（while n % d == 0）？为什么不能每个 d 只检查一次就换下一个？

因为质数在分解结果里可能不止出现一次——比如 245 = 5 × 7 × 7 里的两个 7，或者 16 = 2×2×2×2 里的四个 2。如果每个 d 只检查一次就立刻换成 d+1，每个质数就只会被记一次，输出里就会漏掉重复的部分。内层循环会一直用同一个 d 除下去，直到除不动为止，这正是正确统计重复质因子的关键。

挑战四：修改代码，让它不再打印重复的因子（比如 2*2*2*5*5*5*5），而是用指数的形式打印，比如 2^3 * 5^4。
prime_factorization_exponents.py
n = int(input())

parts = []
d = 2
while d * d <= n:
    if n % d == 0:
        count = 0
        while n % d == 0:
            count += 1
            n //= d
        parts.append(f"{d}^{count}")
    d += 1

if n > 1:
    parts.append(f"{n}^1")

print(" * ".join(parts))

核心循环跟之前一样，只是现在会数清楚每个 d 到底除了多少次，再换下一个，而不是每除一次就记一次。

挑战五（较难）：对 n = 9409 = 97 × 97 来说，为什么循环里 d 最多只会到 97（正好是 √9409），却还是能把两个 97 都找出来？

循环条件是 d*d ≤ n。当 d=97 时，97 × 97 = 9409 ≤ 9409——成立，所以循环体还会再执行一次。里面检查 9409 % 97 == 0，成立，于是记下一个 97，n 变成 9409 // 97 = 97。内层循环再检查一次：97 % 97 == 0，于是又记下一个 97，n 变成 1。这时外层循环才停止（因为 n 已经是 1，d*d 必然会超过它）。两个 97 都被正确找到了，正好卡在 √n 捷径的边界上。
