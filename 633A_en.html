Ebony and Ivory: Build the Exact Tower

Dante has two guns, Ebony and Ivory. Every Ebony bullet deals a damage, every Ivory bullet deals b damage, and he needs to deal exactly c damage — no more, no less. We'll figure this out the way an engineer would: by stacking blocks, not by guessing wildly.

No math background needed Loops & remainders Interactive
LEVEL 1

The mission, straight from the judge

Dante is standing in front of a shield he needs to shatter. He fires bullets from two guns — Ebony deals a damage per bullet, Ivory deals b damage per bullet — and he can fire any number of bullets from each gun, including zero. The shield only breaks if the total damage is exactly c.

So the real question is: can you find two whole numbers x ≥ 0 (Ebony shots) and y ≥ 0 (Ivory shots) so that a × x + b × y = c?

Straight from the judge

a=4, b=6, c=15 → No — nothing works.
a=3, b=2, c=7 → Yes — 1 Ebony + 2 Ivory: 1×3 + 2×2 = 7.
a=6, b=11, c=6 → Yes — 1 Ebony + 0 Ivory: 1×6 + 0×11 = 6.

Why not just guess?

c can be as big as 10,000, and both a and b can be as small as 1. Randomly trying bullet combinations and hoping one lands on exactly c is not a strategy — we need a search that's guaranteed to find the answer if one exists, and to know for sure when one doesn't.

LEVEL 2

Forget the guns — think LEGO bricks

Here's the exact same puzzle with the demon-hunting removed: you have an unlimited pile of red bricks that are a studs tall and blue bricks that are b studs tall. Can you stack some number of each (maybe zero of one color) to build a tower that is exactly c studs tall?

Try it in your head with red = 3 studs and blue = 2 studs. Can you build height 1? No brick is that short and you can't use a negative number of bricks, so 1 is impossible. Can you build height 4? Yes — two blue bricks. Height 5? One red + one blue. Height 7? One red + two blue, which is exactly sample 2 above.

A pattern worth noticing

With red = 3 and blue = 2, the only height you can never build is 1. Every height from 2 upward is reachable somehow. Not every pair of brick sizes is this generous, though — you'll see one that leaves gaps forever in Level 6.

LEVEL 3

The wasteful way: try every pair

The most obvious plan: try every possible red-brick count x from 0 up to c, and for each one, try every possible blue-brick count y from 0 up to c, checking whether a×x + b×y lands exactly on c.

That plan works, but it's slow. If a = b = 1 and c = 10,000, that's roughly 10,001 × 10,001 pairs to check — around 100 million — just for one test case. We can do dramatically better.

LEVEL 4

The trick: only guess the red bricks

You never actually need to guess y. Once you've picked how many red bricks (x) to use, the equation a×x + b×y = c tells you exactly how many blue bricks you'd need:

y = (c − a×x) / b

So for each x, there's only one thing to check: is that division exact (no leftover), and is the result a whole number that's ≥ 0? If yes, you're done. If not, move to the next x.

(c − a×x) % b == 0?

Since a ≥ 1, x can only ever range from 0 to c ÷ a — at most c+1 values, ever, no matter how large b is.

The one sentence that matters most

Turning a two-number guessing game into a one-number guessing game (with the second number computed instead of guessed) is the whole trick. You'll see this exact move — fix one variable, derive the rest — again and again once you start solving more of these problems.

Bonus shortcut (optional but slick)

Before looping at all, you can check one thing: if c isn't a multiple of gcd(a, b), the answer is instantly No — there is no way to combine a's and b's to reach c, ever. For example, gcd(4, 6) = 2, and 15 isn't a multiple of 2, so sample 1 fails before checking a single x. Curious why this rule is always true? The Maximum GCD page explores the gcd side of this idea further.

LEVEL 5

Writing it in Python

Here's a clean way to write the Level 4 idea using a for loop over the range of possible x values. Read the code on the left, then the plain-English note on the right.

tower_height.py
a, b, c = map(int, input().split())

found = False
for x in range(c // a + 1):
    remainder = c - a * x
    if remainder % b == 0:
        found = True
        break

print("Yes" if found else "No")
found = False
Assume it's impossible until we prove otherwise.
for x in range(c // a + 1):
Try every red-brick count from 0 up to c // a (integer division). Any higher and a×x alone would already overshoot c.
remainder = c - a * x if remainder % b == 0:
This is the height Ivory/blue bricks alone would need to cover. If it divides evenly by b, we've found a matching y.
found = True break
Success — no need to try any more x values.
Bonus: the same logic in one line

Once the idea clicks, you can write the entire search as a single expression using Python's any():

tower_height_oneline.py
a, b, c = map(int, input().split())
ok = any((c - a * x) % b == 0 for x in range(c // a + 1))
print("Yes" if ok else "No")

any(...) checks a whole list of true/false conditions and returns True the moment it finds one that's true — which is exactly the "stop as soon as we find a working x" behavior from the loop above, just written more compactly.

LEVEL 8

Your turn: practice challenges

Work these out on paper first, then check yourself with the tool above.

Challenge 1: Can a=5, b=7 build a tower of exactly c=24? Find x and y.

x=0: remainder 24, 24 % 7 = 3, no. x=1: remainder 19, 19 % 7 = 5, no. x=2: remainder 14, 14 % 7 = 0, yes! So y = 14 / 7 = 2. Check: 5×2 + 7×2 = 10 + 14 = 24. Answer: Yes, with 2 red bricks and 2 blue bricks.

Challenge 2: Without checking a single x, can you tell whether a=4, b=6, c=13 is possible?

Yes, using the gcd shortcut from Level 4: gcd(4, 6) = 2. Every tower built from 4s and 6s is automatically a multiple of 2, because both bricks are even. But 13 is odd — not a multiple of 2 — so the answer is instantly No, no loop required.

Challenge 3: Why is it safe to search only over x, and never separately over y?

Because once a, c, and a chosen x are fixed, the equation a×x + b×y = c leaves exactly one possible value for y: y = (c − a×x) / b. There's nothing left to guess — either that value is a non-negative whole number, or it isn't. Searching y on its own would just recompute the same single number over and over.

Challenge 4: The judge only wants "Yes"/"No". Can you modify the code to also print the winning x and y?
tower_height_pair.py
a, b, c = map(int, input().split())

for x in range(c // a + 1):
    remainder = c - a * x
    if remainder % b == 0:
        y = remainder // b
        print("Yes", x, y)
        break
else:
    print("No")

The else attached to the for loop only runs if the loop never hit break — a neat Python feature for exactly this "did we find it, or did we search everything and come up empty?" pattern.

Challenge 5 (harder): For a=6, b=9, what's the largest height you can never build, no matter how many bricks you use?

Trick question — there isn't one! Since gcd(6, 9) = 3, every tower you can build is a multiple of 3, and no non-multiple of 3 (like 1, 2, 4, 5, 7, 8, 10…) is ever reachable, no matter how tall you're allowed to go. The "largest impossible height" trick (the Chicken McNugget / Frobenius idea) only applies when gcd(a, b) = 1 — otherwise, infinitely many heights stay permanently out of reach.
