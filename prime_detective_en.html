Case 01 / 08 Beginner Clue

The Clock's Secret: What Is a Remainder?

Let's start with something you use every day — a clock.

If it's 10 o'clock now, what time is it 5 hours later? You'd blurt out: 3 o'clock. But 10 + 5 equals 15 — so why is the answer 3? Because clocks don't go past 12. Every time it hits 12, it "wraps around" and starts counting from 0 again.

This "wrap around and count what's left" move has an official name in math and coding: the remainder operation, written as %. It answers the question "what's left over after dividing?":

ExpressionWhat it meansResult
15 % 1215 divided by 12 — what's left?3
7 % 37 divided by 3: quotient 2, remainder?1
20 % 520 divided by 5, divides evenly0

Now in Python

clock.py
now_hour = 10
hours_to_add = 5
new_hour = (now_hour + hours_to_add) % 12
print(new_hour)   # prints 3, because 15 % 12 == 3
Cold Case File

Python's remainder is exactly as friendly as you'd hope: -7 % 3 gives 2 in Python (never negative). But in a language like C++, -7 % 3 gives -1! Same expression, different languages, different answers — which is exactly why real programmers always check how their language handles "remainder" before writing a single line of code.

negative_mod.py
print(-7 % 3)     # 2 -- Python's remainder is never negative
print(-7 // 3)    # -3 -- // is integer division, rounded down
Case 02 / 08 Beginner Clue

The Loop Game: Addition on a Clock

The remainder operation shows up everywhere something loops back around: days of the week, months, turns in a game, letters in a cipher…

Example: today is Wednesday. What day of the week is it 100 days from now? You don't need to count day by day — just treat the week as a 7-slot clock:

weekday.py
# 0 = Sunday, 1 = Monday, 2 = Tuesday, 3 = Wednesday ...
today = 3
days_later = 100
future_day = (today + days_later) % 7
print(future_day)   # 5, meaning day 100 falls on a Friday!

Pretty neat, right? 100 days sounds like forever to count, but the remainder operation solves it in one step. That's why programmers, faced with anything "looping" — schedules, game turns, cipher alphabets — instantly think: find the right "clock" (that's the number after mod).

Detective Tip

Any time you see "every N repeats," alarm bells should go off: this needs mod N! "Every 7 days is a week," "every 24 hours is a day," "every 26 letters the cipher wraps around" — it's all the same trick.

Case 03 / 08 Intermediate Investigation

The Doubling Superpower: Fast Exponentiation

The case just leveled up. New assignment: compute 2 to the power of 1,000,000, then take the remainder against a huge number. Multiplying one step at a time would take a million multiplications — will the computer be stuck until the end of time? Actually, no. With the right trick, it takes fewer than 30 steps.

The secret is "doubling." Think of cell division: 1 becomes 2, 2 becomes 4, 4 becomes 8… each step squares the last one, and in about 20 steps you blow past a million. This trick is called fast exponentiation (binary exponentiation): keep dividing the exponent by 2, and each round square the base — if that bit is odd, multiply it into the result too.

fast_power.py
def fast_power(a, b, m):
    # computes (a to the power of b) % m, without ever building that giant number
    result = 1
    base = a % m
    while b:                      # stop once b hits 0
        if b % 2 == 1:
            result = result * base % m
        base = base * base % m    # this line is the "doubling"
        b = b // 2
    return result

print(fast_power(2, 1000000, 1000000007))
Cold Case File

Python already has this doubling superpower built in — you don't even need to write it yourself: pow(a, b, m) is a built-in function, and that third argument means "take the remainder along the way," using exactly the fast exponentiation trick you just learned under the hood! We'll lean on it often in the cases ahead.

Case 04 / 08 Intermediate Investigation

Who's Prime? Who's Faking It?

Alright, time for the heart of this case: prime numbers.

A prime is a number greater than 1 that can only be divided evenly by 1 and itself — like 2, 3, 5, 7, 11, 13… A composite number is an "impostor" that can be broken down into smaller numbers multiplied together — like 91 = 7 × 13. It looks harmless, but it's secretly hiding two accomplices.

The agency's number-one job: given a number, quickly tell whether it's an "innocent prime" or a "composite hiding accomplices."

Detective Tip

1 is neither prime nor composite — it's too special. Mathematicians officially benched it; it doesn't play this game.

Case 05 / 08 Intermediate Investigation

Eratosthenes's Net: Catching Every Prime at Once

If you need to find every prime from 1 to 100, the ancient Greek mathematician Eratosthenes worked out a brilliant method over 2,000 years ago, now called the Sieve of Eratosthenes — like casting a net that scoops up every number "with accomplices," leaving only the true primes behind.

Here's how: start at 2, and cross out every multiple of 2 (4, 6, 8…) since they all have 2 as an accomplice. Then look at 3, cross out its multiples. The next number left standing is prime — use it to cross out its own multiples, and so on, all the way to 100. Whatever survives the net is genuinely prime.

sieve.py
def sieve_of_eratosthenes(limit):
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False   # 0 and 1 are out
    for p in range(2, limit + 1):
        if is_prime[p]:
            # p is prime -- mark all its multiples as composite
            for multiple in range(p * p, limit + 1, p):
                is_prime[multiple] = False
    return [n for n in range(limit + 1) if is_prime[n]]

print(sieve_of_eratosthenes(100))

This method is lightning fast — finding every prime under a million takes an ordinary computer barely a blink, far faster than checking each number one by one.

Case 06 / 08 Hardcore Cold Case

Big Numbers: From Brute Force to Smart Search

The net method is great, but if you only want to know whether one huge number (say, 999999999989) is prime, casting a net with a billion slots is overkill. Time for a different interrogation method.

The most direct idea: try dividing by 2, 3, 4, 5… all the way up to n-1. The moment one divides evenly, you've caught an accomplice.

is_prime_slow.py
def is_prime_slow(n):
    if n == 0 or n == 1:
        return False
    for i in range(2, n):
        if n % i == 0:
            return False   # caught an accomplice!
    return True

print(is_prime_slow(97))    # True

Checking a number in the millions this way means looping millions of times — fine for a computer, but if the number is dozens of digits long, this brute-force approach would take forever. Here's a smarter shortcut:

You only ever need to check up to √n. Why? If n can be split into a × b, then at least one of a and b must be no bigger than √n — think of two people splitting a plot of land; they can't both be bigger than half. So if you search from 2 to √n and find no accomplice, n is definitely innocent.

is_prime_fast.py
def is_prime_fast(n):
    if n == 0 or n == 1:
        return False
    for i in range(2, int(n ** 0.5) + 1):   # only check up to the square root
        if n % i == 0:
            return False
    return True

print(is_prime_fast(999999937))   # True, and it comes back almost instantly

Going from "check up to n" to "only check up to √n" — how big a speed-up is that? If n is 100 million, the old way loops 100 million times; the new way loops only 10,000 times. That's ten thousand times faster!

Case 07 / 08 Hardcore Cold Case

The Fermat Lie Detector

But what if n isn't 100 million — what if it's dozens of digits long? Even checking up to √n is still astronomical. The agency needs a "lie detector": no need to interrogate everyone, just a few "witnesses" can settle the case with high confidence.

In the 17th century, the mathematician Fermat discovered a remarkable pattern, now known as Fermat's Little Theorem:

Fermat's Little Theorem

If p is prime, then for any number a (a "witness") that shares no common factor with p, it must be true that:

ap−1 mod p = 1

Flip this around and you get a lie detector: pick a few witnesses a, compute a to the (n-1) power mod n. If the result isn't 1, that's 100% proof — n is definitely not prime!

fermat_test.py
import random

def fermat_test(n, witness_count=5):
    if n == 0 or n == 1:
        return False
    for _ in range(witness_count):
        a = random.randrange(2, n - 1)      # pick a random witness
        if pow(a, n - 1, n) != 1:
            return False                     # the witness blew the whistle -- n is not prime
    return True                              # every witness let it slide -- n is probably prime

Notice the wording — the Fermat lie detector can only say "n is probably prime," never a guarantee. That's because it's only airtight proof when it catches a counterexample; if every witness lets it slide, there's still a tiny chance of being fooled. Whether it actually gets fooled… keep reading.

Case 08 / 08 Hardcore Cold Case

Miller-Rabin: Cross-Examination Exposes the Fake

If an impostor can beat one lie-detector question, ask a few trickier follow-ups. That's the idea behind the Miller-Rabin primality test — beyond checking a to the (n-1) power, it also inspects a subtler tell that shows up along the way.

Here's the key mathematical clue:

The Theorem That Cracks the Case

If p is prime, then the equation x² ≡ 1 (mod p) has exactly two solutions: x = 1 or x = p − 1 (that is, −1).
In other words: if you find a third solution, p is definitely not prime!

The Miller-Rabin test deliberately hunts for that "third solution." Here's how, step by step:

  1. Write n − 1 as u × 2l (u is odd — pull out every factor of 2 from the even part)
  2. Pick a witness a and compute v = a to the u power mod n
  3. Square v repeatedly, up to l times
  4. While squaring, if v suddenly jumps from "not ±1" to 1, you've caught that "solution that shouldn't exist" — airtight proof: n is not prime
  5. If nothing suspicious ever shows up, this witness lets n go — for now, treat n as a "probable prime"
miller_rabin.py
import random

def is_probably_prime(n, tries=8):
    if n == 0 or n == 1:
        return False
    for small_prime in [2, 3, 5, 7, 11, 13]:
        if n == small_prime:
            return True
        if n % small_prime == 0:
            return False

    # Step 1: write n-1 as u * 2^l
    u, l = n - 1, 0
    while u % 2 == 0:
        u = u // 2
        l = l + 1

    # Steps 2-5: cross-examine several witnesses
    for _ in range(tries):
        a = random.randrange(2, n - 1)
        v = pow(a, u, n)
        if v == 1 or v == n - 1:
            continue                 # this witness found nothing suspicious, for now
        caught = False
        for _ in range(l - 1):
            v = v * v % n
            if v == n - 1:
                caught = False
                break
            caught = True
        if caught:
            return False              # caught a flaw -- n is not prime
    return True                       # no witness ever caught a flaw

print(is_probably_prime(561))            # False -- the impostor is caught!
print(is_probably_prime(999999999989))   # True, and it comes back almost instantly

For any impostor number, at most 1/4 of possible witnesses can be fooled by the Miller-Rabin test. That means with just a few more witnesses (say, 8), the odds of fooling every single one drop lower than your odds of being struck by lightning — which is why it's called a "probabilistic" test, even though in practice it's just about as reliable as a guaranteed one.

Case-Closed Extras

Two more fun number-theory facts before you go: a prime like 31 that becomes a different prime when its digits are reversed (31 → 13) is called an emirp (that's "prime" spelled backwards). And a number with more divisors than any smaller number is called a highly composite number — also nicknamed an anti-prime, because it's basically the opposite of a prime: practically nothing but accomplices.
