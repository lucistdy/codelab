Jzzhu 的回声机器：每 6 步就重复一次的数列

Jzzhu 造了一台奇怪的数字机器：每个新数字，都等于前两个数字相减。给它喂进一对起始数字，神奇的事情发生了——整条数列会每隔 6 步就"回声"一次，一直重复下去。Codeforces 450B 要求你算出机器打印的第 n 个数字，哪怕 n 大到 20 亿。

写给爱思考的 13 岁少年 一个新技巧：6 步回声 可互动
第一关

认识这台机器

Jzzhu 的数列从两个你自己选的数字开始：f₁ = x，f₂ = y。从此以后，每个新数字都严格遵守一条规则：

fi = fi−1 − fi−2   （对所有 i > 2 成立）

说人话：要算下一个数字，就拿"紧挨着它前面的那个数"，减去"再往前一个数"。你的任务：给定 x、y 和步数 n，求出 fn——但因为这些数字可能变得非常大（或者非常负），所以要对 1,000,000,007 取模后再输出。

题目原话

x=2, y=3, n=3 → 1。题目提示写道 f₂ = f₁ + f₃，也就是 3 = 2 + f₃，所以 f₃ = 1——这正好等于 y − x。
x=0, y=−1, n=2 → 1000000006。我们要的其实就是 f₂，也就是 y 本身：−1。因为答案不能是负数，我们要把它对 1,000,000,007 取模，−1 就变成了 1,000,000,006（刚好在绕回 0 的前一步）。

为什么要在意速度？

n 最大可以到 2,000,000,000——整整 20 亿！x 和 y 的绝对值也可能高达十亿。如果机器每一步都老老实实打印一个数字，一步一步算完 20 亿次，是绝对无法在这道题 1 秒的时间限制内跑完的。

第二关

这闻起来很像一个时钟

想想钟表上的时针。它不会一直往上数——1、2、3……47、48……——而是数到 12 就绕回去重新从 1 开始。如果你知道时钟每 12 小时循环一次，那你根本不需要从盘古开天地开始，一小时一小时地模拟，才能知道"第 9000 小时"指针指向哪里。你只需要知道循环规律，以及第 9000 小时落在规律里的哪个位置。

Jzzhu 的数列脾气一模一样。它不会真的重复出现数字 12——但你马上就会看到，整整六个数字组成的规律会永远重复下去。一旦我们找到这个规律，就再也不需要靠 998 次减法硬算出 f1000。我们只需要弄清楚第 1000 步落在这个 6 步循环里的哪个位置。

还没接触过这种"绕圈子"的钟表数学（也叫模运算）？质数侦探社这一页从零开始搭建了余数的概念，正是这里用到的同一种"钟面思维"。

第三关

为什么"老老实实算每一步"会失败

规则 fi = fi−1 − fi−2 写成循环很容易：在内存里存两个数字，做减法，往后移一位，重复 n 次。问题就出在这个 n 上。n 最大能到 20 亿，即便循环每一步只做一次微不足道的减法，也得跑 20 亿次——而大多数评测系统（包括这道题）期望你的程序在大约 1 秒内跑完。计算机确实很快，但还没快到"20 亿次小心翼翼的运算、1 秒内轻松搞定"的程度，更别说还要算上读入数据等额外开销了。

第四关

关键发现：摇动手柄，看它回声

我们别急着抄近道——先老老实实动手摇几下手柄，看看会发生什么。我们知道 f₁ = x，f₂ = y。反复套用规则 fi = fi−1 − fi−2：

步骤套用的规则结果
f₁已知x
f₂已知y
f₃f₂ − f₁y − x
f₄f₃ − f₂ = (y−x) − y−x
f₅f₄ − f₃ = −x − (y−x)−y
f₆f₅ − f₄ = −y − (−x)x − y
f₇f₆ − f₅ = (x−y) − (−y)x ← 和 f₁ 一样！
f₈f₇ − f₆ = x − (x−y)y ← 和 f₂ 一样！

看到了吧——f₇ = f₁，f₈ = f₂。既然每个数字都只取决于它前面紧挨着的那两个数字，那么一旦连续两个数字重新出现，后面整段数列也必然会跟着重复。机器已经绕回了自己最初的那一对起点，从这里开始，它就会永远地回声播放同样的六个数字。

最重要的一句话

从头到尾只存在六个不同的取值：x, y, y−x, −x, −y, x−y，之后就永远重复。要求出 fn，我们不需要走 n 步——只需要知道第 n 步落在这六个位置中的哪一个。而"落在六个里的哪一个"，正是余数（mod 6）擅长回答的问题。

第五关

逐行读代码

下面是完整的解法。先看左边的代码，再看右边的大白话翻译。

jzzhu_sequence.py
MOD = 1000000007

x, y = map(int, input().split())
n = int(input())

cycle = [x, y, y - x, -x, -y, x - y]   # 按顺序排列的 6 个取值
answer = cycle[(n - 1) % 6]        # 第 n 步落在这 6 个里的哪一个？

print(answer % MOD)
cycle = [x, y, y - x, -x, -y, x - y]
这就是我们在第四关手算出来的六个值，从 f₁ 开始按顺序存好。这个列表的下标 0 到 5，分别对应 f₁ 到 f₆。
cycle[(n - 1) % 6]
第 n 步对应列表下标 n−1（因为 f₁ 是下标 0）。对它取 % 6，就能把任意巨大的 n 瞬间"折叠"回 0–5 的范围——不管 n 有多大，都是一次查表搞定。
print(answer % MOD)
即便 answer 是负数，Python 的 % 在除数为正时也总是返回非负结果——所以这一行代码同时完成了"取模"和"不允许出现负数答案"这两件事。（下一关会详细讲这个有趣的现象！）

第六关

一个值得知道的 Python 小陷阱：负数和 %

让我们手动走一遍两道题目样例，因为其中一个藏着一个有趣的小惊喜。

xyn(n−1) mod 6循环取值对 1e9+7 取模后
2332 → y−x3−2 = 11
0−121 → y−11000000006

第二行才是重点。在 Python 里，-1 % 1000000007 得到的不是 -1，而是自动变成 1000000006。Python 的 % 运算符被设计成结果的符号总是和除数一致（这里除数是正数），所以负数输入会被悄悄"挪"到正确的正数范围内。自己在 Python 命令行里试试看：

python 命令行
>>> -1 % 1000000007
1000000006
>>> -8 % 6
4
换一种语言时要小心

这是 Python 特有的贴心之处！在 JavaScript、C++、Java 这类语言里，-1 % 1000000007 得到的还是 -1，而不是 1000000006。在那些语言里，你得自己动手用类似 ((answer % MOD) + MOD) % MOD 的写法来修正。下面的互动小工具就是用 JavaScript 写的，翻翻它的代码，你就能在里面看到这个写法真实登场。

第八关

练习题：先自己算，再用工具核对

每一题都先在纸上算一遍，再用上面的小工具验证答案。

练习 1：x=5, y=8。求 f₃、f₄ 和 f₇。你发现 f₇ 有什么特别之处吗？

f₃ = y − x = 8 − 5 = 3。f₄ = −x = −5。f₇ 永远等于 f₁，所以 f₇ = x = 5。这正是回声在起作用——六步之后，我们又回到了出发的地方。

练习 2：x=1, y=1, n=1000000。答案落在 6 个循环取值中的哪一个？（提示：你不需要一个能减一百万次的计算器。）

我们需要算 (n−1) % 6 = 999999 % 6。因为 999999 = 6 × 166666 + 3，余数是 3，对应我们列表 [x, y, y-x, -x, -y, x-y] 里下标为 3 的位置——也就是 -x = -1。对 1,000,000,007 取模后，结果是 1000000006。

练习 3：为什么循环周期正好是 6，而不是其他数字？有没有可能循环周期更短，比如 3？

循环周期是由代数关系强制决定的：从 (f₁, f₂) = (x, y) 出发，套用六次减法规则，无论 x 和 y 是多少，一定会重新得到 (x, y)——这正是我们在第四关手算证明的。在特殊情况下，它确实可能"提前闭合"：比如 x=0 且 y=0 时，每一项都是 0，数列的周期实际上是 1（而 1 恰好能整除 6，所以这并不算矛盾——6 只是回声最晚需要多久才能返回的一个上限）。

练习 4：修改代码，让它输出全部 6 个循环取值（f₁ 到 f₆）对 1,000,000,007 取模后的结果，而不只是 fn。
jzzhu_sequence_all.py
MOD = 1000000007

x, y = map(int, input().split())

cycle = [x, y, y - x, -x, -y, x - y]
for value in cycle:
    print(value % MOD)
练习 5（挑战题）：x=1000000000, y=-1000000000, n=2000000000。先手算出答案，再用小工具核对。

(n−1) % 6 = 1999999999 % 6。因为 1999999999 = 6 × 333333333 + 1，余数是 1，也就是说答案是 y = -1000000000。对 1,000,000,007 取模后，这么大的负数会变成 1000000007 - 1000000000 = 7。
