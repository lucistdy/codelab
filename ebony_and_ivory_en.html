Ebony and Ivory: Hit the Number Exactly

Dante has two guns, Ebony and Ivory. Every Ebony bullet deals a damage, every Ivory bullet deals b damage. Codeforces 1036A asks: can he fire some combination of bullets that deals exactly c damage? Let's hunt down the answer, bullet by bullet.

No math background needed Simple search Interactive
LEVEL 1

The mission

Dante is up against The Savior's shield, and he only breaks through by dealing exactly c damage — not one point more, not one point less. He has two guns: Ebony deals a damage per bullet, Ivory deals b damage per bullet. He can fire any number of bullets from each gun, including zero.

In other words: can you find two whole numbers x ≥ 0 (Ebony shots) and y ≥ 0 (Ivory shots) so that a × x + b × y = c?

Straight from the judge

a=4, b=6, c=15 → No (no combination works).
a=3, b=2, c=7 → Yes (1 Ebony + 2 Ivory: 1×3 + 2×2 = 7).
a=6, b=11, c=6 → Yes (1 Ebony + 0 Ivory: 1×6 + 0×11 = 6).

Why should you care?

c can be as large as 10,000. Guessing random combinations of bullets and hoping one works isn't a plan — it's a prayer. We need a search that's guaranteed to check every possibility that could actually matter, and nothing more.

LEVEL 2

This is really a "making change" puzzle

Strip away the demon-hunting theme, and here's the puzzle underneath: can you pay exactly $7 using only $3 bills and $2 bills? That's precisely sample 2 (a=3, b=2, c=7) — and yes, one $3 bill plus two $2 bills does it.

Some totals are payable, some aren't. Can you pay exactly $1 with only $3 and $2 bills? No — every combination is either 0, 2, 3, 4, 5, 6… and 1 never shows up. That's exactly the kind of "possible or not" question this problem is asking, just dressed up with guns and a demon shield.

Cold Case File

This exact style of puzzle — which totals you can make using only two denominations — is nicknamed the Chicken McNugget problem, because McDonald's used to sell nuggets in boxes of 6, 9, and 20, and mathematicians immediately started asking which nugget counts you could never order exactly. (Fun fact: with only 6 and 9, you could never order exactly 43.)

LEVEL 3

Why not just try every (x, y) pair?

The most obvious plan: try every possible x from 0 up to c, and for each one, try every possible y from 0 up to c, checking whether a×x + b×y lands exactly on c.

That works, but it's wasteful. If a = b = 1 and c = 10,000, you'd be checking roughly 10,001 × 10,001 pairs — about 100 million checks, for one single test case. There's a much smaller search hiding in plain sight.

LEVEL 4

The key insight: only guess x, then solve for y

You don't actually need to guess y at all — once you've picked a value for x, the equation a×x + b×y = c tells you exactly what y would have to be:

y = (c − a×x) / b

So the only real question for each x is: does that division come out even, with no remainder, and is the result ≥ 0? If yes, you've found your answer. If not, try the next x.

pick
x = 0, 1, 2…
→solve
check
(c − a×x) % b == 0?

Since a ≥ 1, x can only ever range from 0 to c ÷ a — at most c+1 values to try, ever.

The one sentence that matters most

Turning a 2-number guessing game into a 1-number guessing game (with the 2nd number computed, not guessed) is the whole trick — it's the same move you'll see again and again in competitive programming: fix one variable, derive the rest.

Bonus insight

Here's a shortcut that can save you time before you even start looping: if c isn't a multiple of gcd(a, b), the answer is instantly No — no combination of a's and b's can ever add up to c. (Curious why that's true? That's exactly the question the Maximum GCD page digs into.) For example, gcd(4, 6) = 2, and 15 isn't a multiple of 2 — so sample 1 fails before we even need to check a single x.

LEVEL 5

Reading the code, line by line

Here's the entire solution. Don't worry about understanding it all at once — read the code on the left, then the plain-English translation on the right.

ebony_and_ivory.py
a, b, c = map(int, input().split())

possible = False
x = 0
while a * x <= c:
    remainder = c - a * x
    if remainder % b == 0:
        possible = True
        break
    x += 1

print("Yes" if possible else "No")

LEVEL 8

Quick challenges (no peeking until you've tried)

Test the search on paper before you check with the tool above.

Challenge 1: Can a=5, b=3 deal exactly c=11 damage? Find the x and y.

x=0: remainder 11, 11 % 3 = 2, no. x=1: remainder 6, 6 % 3 = 0, yes! So y = 6 / 3 = 2. Check: 5×1 + 3×2 = 5 + 6 = 11. The answer is Yes, with 1 Ebony bullet and 2 Ivory bullets.

Challenge 2: Sample 3 says a=6, b=11, c=6 is Yes. Why does the search find it on the very first try?

x=0: remainder is 6, and 6 % 11 = 6 — not divisible, so x=0 alone (0 Ebony bullets) doesn't work. x=1: a×x = 6, remainder = 6 − 6 = 0, and 0 % 11 = 0 — divisible! So y = 0. One Ebony bullet does the whole job, with zero Ivory bullets needed. The loop only needed 2 tries.

Challenge 3: Why is it safe to only search over x, and never separately search over y?

Because once a, c, and a chosen x are fixed, the equation a×x + b×y = c has exactly one possible value left for y: y = (c − a×x) / b. There's nothing left to guess — either that value is a non-negative whole number, or it isn't. Searching y separately would just be re-deriving the same single number over and over, for no benefit.

Challenge 4: The judge only wants "Yes"/"No". Can you change the code to also print the winning x and y when the answer is Yes?
ebony_and_ivory_pair.py
a, b, c = map(int, input().split())

x = 0
while a * x <= c:
    remainder = c - a * x
    if remainder % b == 0:
        y = remainder // b
        print("Yes", x, y)
        break
    x += 1
else:
    print("No")
