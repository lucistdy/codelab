最大公约数：一眼锁定最佳搭档

Codeforces 1370A 问了一个看似简单的问题：在 1 到 n 之间的所有数对里，哪一对的公因数最大？其实根本不用一个个去试——一行代码就能秒出答案。我们来看看为什么。

不需要数学基础 一行公式搞定 可以互动
第一关

任务目标

题目会给你一个数 n。在 1 到 n 之间所有可能的数对里，有一对的最大公约数（GCD）是所有数对里最大的。你的任务：尽快把这个最大值找出来。

规则很简单：选两个不同的整数 a 和 b，满足 1 ≤ a < b ≤ n。算出 gcd(a, b)。在所有可能的数对里，报告你能找到的最大 gcd。

题目原样给出的例子

n = 3 → 最大的 GCD 是 1（1、2、3 这几个数两两之间只共享因数 1）。
n = 5 → 最大的 GCD 是 2，来自数对 (2, 4)。

这跟你有什么关系？

Codeforces 一次能给你多达 100 组不同的 n，而每个 n 本身可以大到 1,000,000。如果你的做法是一个个检查所有数对，程序还没跑完，评测系统早就等不及了。真正的技巧能让每组测试数据都在一步之内得出答案。

第二关

快速复习：什么是"最大公约数"？

在解开这道题之前，先确认一下"GCD"没那么可怕。GCD 全称 Greatest Common Divisor（最大公约数）——能同时整除两个数、且不留余数的那个最大的数。

以 12 和 18 为例。能整除 12 的数有 1, 2, 3, 4, 6, 12。能整除 18 的数有 1, 2, 3, 6, 9, 18。两份列表里都出现的数字有哪些？1, 2, 3, 和 6。它们之中最大的是 6——所以 gcd(12, 18) = 6。

冷知识档案

Python 有个现成的捷径 math.gcd(a, b)，用的是两千多年前欧几里得发明的算法，瞬间就能算出答案。不过对付 1370A 这道题，我们连它都用不上——接下来要发现一个更聪明的办法。

第三关

为什么不能挨个检查每一对？

最直接的做法：把每一对 (a, b) 都试一遍，算出各自的 gcd(a, b)，记录最大的那个。这样做肯定管用——只是得等很久。

问题在于 n 最大可以到 1,000,000，而且测试数据最多可能有 100 组。挨个检查每一对，意味着每组测试数据都要检查大约 n²/2 对——这个数字爆炸的速度比想象中快得多。

第四关

关键洞察：让一个数正好翻倍

秘诀在这里：如果 b 正好是 a 的两倍（也就是 b = 2 × a），那么 a 能把 b 整除——所以 gcd(a, b) = a，每次都自动成立。

选
a = n // 2
→×2
得到
b = 2 × a

因为 b 正好是两份 a，a 能把 b 整除干净——所以 gcd(a, b) = a，稳赢。

所以要让这个公共因数尽量大，只需要找到最大的 a，让 2 × a 依然不超过 n。这正是 a = n // 2（整除：除以 2，扔掉余数）。

全篇最重要的一句话

在 1..n 范围内，一对数能拿到的最大 GCD 正好是 n // 2——只要选 a = n // 2，b = 2 × a，每次都能拿到。

但为什么没有别的组合能超过 n // 2？假设胜出的一对数共享公因数 g。因为 g 同时整除这两个数，而这两个数又不相等，较大的那个至少要比较小的那个多"跨出一整步 g"——也就是说，较大的数至少是 2 × g。既然较大的数不能超过 n，就必然有 2g ≤ n，也就是 g ≤ n // 2。拿 n = 10 来试着打破这个结论：g = 6 行不行？我们需要两个不同的 6 的倍数、都不超过 10——可 6 的倍数里只有 6 本身，12 已经超了。所以 g = 6 不可能，而 10 // 2 = 5 才是真正的答案（数对是 5 和 10）。

第五关

逐行读代码

下面就是完整的解法。不用一下子全懂——先看左边的代码，再看右边的大白话翻译。

max_gcd.py
def max_gcd(n):
    # n 除以 2 向下取整，就是这一对能拿到的最大 gcd(a, b)
    return n // 2

t = int(input())
for _ in range(t):
    n = int(input())
    print(max_gcd(n))
def max_gcd(n): return n // 2
这就是全部算法。n // 2 表示整除：除以 2，然后扔掉余数。
t = int(input()) for _ in range(t):
Codeforces 的题目经常把好几组测试数据打包在一次运行里。先读出一共有多少组（t），再循环这么多次。
n = int(input()) print(max_gcd(n))
每组测试数据都读入 n，然后输出答案。全程没有真的构造任何数对，甚至连 gcd() 函数都没调用——公式早就知道答案。

第八关

课后挑战（先自己试，别偷看答案）

在用上面的工具验证之前，先自己在纸上把这个技巧试一遍。

挑战一：n = 7 时答案是多少？是哪一对数达到的？

a = 7 // 2 = 3，b = 2 × 3 = 6。验证一下：gcd(3, 6) = 3。有没有别的组合能超过 3？剩下的数对像 (1,7)=1、(2,5)=1、(4,6)=2、(5,7)=1、(6,7)=1——都够不到 3。所以答案是 3，来自数对 (3, 6)。

挑战二：这道题里 n 最小能是多少？这种情况下答案又是多少？

题目规定的最小 n 是 2（至少要有两个数才能凑出一对）。当 n = 2 时，唯一能选的数对是 (1, 2)，所以 gcd(1, 2) = 1 是唯一可能的答案——这也正好符合公式：2 // 2 = 1。

挑战三：为什么答案永远不可能超过 n // 2？

假设胜出的一对数共享公因数 g。因为 g 同时整除这两个数，而两个数又不相等，较大的那个至少要比较小的那个多"跨出一整步 g"——也就是说较大的数至少是 2 × g。既然较大的数不能超过 n，就得到 2g ≤ n，也就是 g ≤ n // 2。而 a = n // 2，b = 2a 正好达到这个上限——所以它不只是一个不错的答案，而是最好的答案。

挑战四：评测系统只要最大的 GCD，不要求输出具体的数对。你能不能把 max_gcd(n) 改成同时返回数对 (a, b)？
max_gcd_pair.py
def max_gcd_pair(n):
    a = n // 2
    b = 2 * a
    return a, b

print(max_gcd_pair(13))  # (6, 12)
