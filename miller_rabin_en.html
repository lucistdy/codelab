The Miller–Rabin Cross-Examination

The Fermat Lie Detector catches almost every impostor — except the professional con artists. Here's the follow-up interrogation trick that catches those too, worked out slowly with small numbers and a tool you can interrogate suspects with yourself.

Builds on the Fermat Lie Detector (Case 07) Uses fast exponentiation (Case 03) Interactive
LEVEL 1

The weak spot in our lie detector

In the Fermat Lie Detector (Case 07), you met a fast trick for catching fake primes: pick a random witness a, check whether an−1 mod n equals 1. If it doesn't, n is guilty, guaranteed.

But you also met the one criminal who beats it almost every time: 561 (= 3 × 11 × 17), a Carmichael number. Witnesses 2, 5, 7, and 13 all vouch for it. In fact, almost every witness vouches for it. The Fermat test alone just can't tell it apart from a real prime.

The detective's next move

If a suspect can beat one lie-detector question, you don't give up — you ask a trickier follow-up. That's exactly the idea behind the Miller–Rabin test. It still checks an−1 mod n, but along the way, it also inspects a much subtler tell that a Carmichael number can't hide.

LEVEL 2

A new kind of clue: square roots of 1

Here's a question that sounds strange at first: on a clock with n hours, which numbers x give you x2 mod n = 1? In other words, which numbers "square back around" to exactly 1?

The pattern

A real prime only ever has two square roots of 1: 1 and n − 1. A composite number can have extra, "illegal" ones hiding inside. Finding an illegal square root of 1 is an even sneakier way to unmask a fake than the plain Fermat check — and it's exactly what lets Miller–Rabin catch Carmichael numbers.

LEVEL 3

The theorem that cracks the case

The theorem

If p is prime, then the equation x2 ≡ 1 (mod p) has exactly two solutions: x = 1 or x = p − 1.

Why is this always true? Here's the single most useful fact about prime numbers, and it's simpler than it sounds: if a prime number divides a product of two numbers, it must divide at least one of them — it can never be satisfied by splitting the blame between both. Since x2 − 1 factors into (x − 1)(x + 1), if a prime p divides that product, it has to fully divide (x − 1) or fully divide (x + 1) — giving you x = 1 or x = p − 1, and nothing else. A composite number doesn't play by that rule, which is exactly why 15 could sneak in the extra impostors 4 and 11.

FLIP IT AROUND ↓

The rule that catches liars

If you're checking a mystery number n, and you find a third solution to x2 ≡ 1 (mod n) — some x that isn't 1 and isn't n − 1 — then n is definitely, 100% not prime. No exceptions, not even for Carmichael numbers.

LEVEL 4

Turning the clue into an algorithm

So we need to go hunting for illegal square roots of 1. Here's the clever part: we don't need to check every number — we can find them for free, hiding inside the same repeated-squaring calculation from Case 03 that computes an−1 mod n.

  1. Write n − 1 as u × 2l (u is odd — pull every factor of 2 out of the even part).
  2. Pick a witness a and compute v = au mod n.
  3. Square v repeatedly, up to l times — each squaring doubles the exponent, so this walks v step by step from au all the way up to au·2l = an−1.
  4. If n is really prime, Fermat guarantees the last value in that chain has to be 1. So somewhere along the way, the chain flips from "not 1" to "1" for the very first time. By Level 3's theorem, the value right before that flip is only allowed to be 1 or n − 1. If it's anything else, that's an illegal square root — airtight proof n is not prime.
  5. If nothing suspicious ever shows up, this witness lets n go — for now, treat it as a "probable prime."
miller_rabin.py
import random

def is_probably_prime(n, tries=8):
    if n == 0 or n == 1:
        return False
    for small_prime in [2, 3, 5, 7, 11, 13]:
        if n == small_prime:
            return True
        if n % small_prime == 0:
            return False

    # Step 1: write n-1 as u * 2^l
    u, l = n - 1, 0
    while u % 2 == 0:
        u = u // 2
        l = l + 1

    # Steps 2-5: cross-examine several witnesses
    for _ in range(tries):
        a = random.randrange(2, n - 1)
        v = pow(a, u, n)
        if v == 1 or v == n - 1:
            continue                 # this witness found nothing suspicious, for now
        caught = False
        for _ in range(l - 1):
            v = v * v % n
            if v == n - 1:
                caught = False
                break
            caught = True
        if caught:
            return False              # caught a flaw -- n is not prime
    return True                       # no witness ever caught a flaw

print(is_probably_prime(561))            # False -- the impostor is caught!
print(is_probably_prime(999999999989))   # True, and it comes back almost instantly

Cold Case File

This is the whole trick in one sentence: Miller–Rabin computes the exact same power as Fermat, but instead of only checking the final answer, it also checks every "stepping stone" square root along the way — and a Carmichael number can rig the final answer, but it can't rig every stepping stone too.

LEVEL 6

Why it's nearly impossible to fool

Mathematicians have proven something remarkable: for any impostor number, at most 1/4 of all possible witnesses can be fooled by the Miller–Rabin test (compare that to the Fermat test, where a Carmichael number can fool almost all of them). That means calling in a few more witnesses shrinks the danger extremely fast.

By the time you've called in just 8 witnesses (the default in the code above), the odds of every single one being fooled are already lower than your odds of being struck by lightning. That's why the Miller–Rabin test is technically called "probabilistic" — but in practice, real software (and real cryptography) treats it as good as certain.

LEVEL 8

Quick challenges (no peeking until you've tried)

Work these out before you check with the tool above.

Challenge 1: Write n − 1 as u × 2l for n = 13.

n − 1 = 12. Divide by 2 repeatedly: 12 → 6 → 3 (3 is odd, stop). That's 2 divisions, and 3 is left over. So u = 3, l = 2, and indeed 3 × 22 = 3 × 4 = 12. ✓

Challenge 2: Mod 11 (a real prime), which x from 1 to 10 satisfy x² ≡ 1 (mod 11)?

Only x = 1 (since 12 = 1) and x = 10 (since 102 = 100 = 9 × 11 + 1). Exactly two solutions — exactly what the theorem in Level 3 guarantees, since 11 really is prime.

Challenge 3: In your own words, why does finding a third square root of 1 mod n prove n isn't prime?

Because Level 3's theorem says a genuine prime can only ever have exactly two numbers that square to 1: 1 and n − 1. If you find any other number that also squares to 1, n has broken a rule that every real prime obeys without exception — so n cannot be a real prime. It's the same "flip the always-true rule around" logic from the Fermat test, just applied to a sneakier, harder-to-fake clue.

Challenge 4 (use the tool above): Cross-examine n = 1105 = 5 × 13 × 17 with witnesses 2, 3, 7. What happens, and how is it different from what you'd have seen with the plain Fermat test?

1105 is another Carmichael number — it fools the plain Fermat test almost completely, just like 561. But Miller–Rabin catches every one of those witnesses (2, 3, and 7 all expose an illegal square root along the way). It's the same story as 561: the final Fermat answer can be rigged, but the stepping-stones on the way there give it away.

Challenge 5 (hardcore, no tool needed): The case file's code prints is_probably_prime(999999999989) and gets an answer almost instantly. Why doesn't the size of this 12-digit number slow it down much, compared to trial division?

Every step of Miller–Rabin — factoring out the 2s from n−1, and computing each au mod n — relies on the fast exponentiation trick from Case 03, which only needs about log2(n) squarings, not n of them. For a 12-digit number that's still only around 40 squarings per witness, times a handful of witnesses — a few hundred multiplications total, instead of trial-dividing by billions of candidates.
