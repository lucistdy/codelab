Codeforces 1139D · 题目精讲

逃脱之路：GCD 逃脱机

维维克不断拉动一台机器的拉杆，每次都会吐出一个 1 到 m 之间的随机数，加进一个列表里。一旦列表里所有数字的最大公约数变成 1，他就成功逃脱。平均下来，他需要拉多少次才能逃出去？

不需要数学基础 概率 & 数论 可以互动
第一关

任务目标，原样来自题目

维维克手上有一个空列表和一个固定的数字 m。他不断重复下面这个循环：

1. 拉拉杆
随机得到 x，1 ≤ x ≤ m
→
2. 加入 x
列表长度 +1
→
3. 检查 gcd
gcd == 1？逃脱！ : 继续

他想知道：平均下来，成功逃脱时列表会有多长？这就叫作期望长度。

题目原样给出的例子

m=1 → 期望长度 1（唯一能拉到的数字就是 1，立刻 gcd=1）。
m=2 → 期望长度 2。
m=4 → 输出 333333338（一个看起来很奇怪的数字——马上就来揭晓！）。

等等，m=4 为什么答案这么奇怪、这么大？

m=4 时真正的期望长度其实是分数 7/3——根本不是整数！由于计算机一般没办法直接打印分母巨大的精确分数，题目要求把这个分数用模运算编码成一个整数（第八关会完整揭晓这个技巧）。先记住这个分数 7/3，本页后面会手把手把它算出来。

第二关

热身：什么是"期望值"？

想象反复抛一枚硬币，直到抛出正面为止。有时候第一次就正面朝上（走运！）。有时候要抛 2 次、3 次，甚至更多。期望值的意思就是：如果你把这个游戏玩上成千上万次，把每次用掉的次数求平均，会落在哪个数字上？

对于这种"一直重复直到成功"的经典情形，答案是有名的结论：用一枚公平的硬币（每次正面概率 50%），期望的抛掷次数正好是 2。这可不是巧合——它正好和上面的样例二一模一样！当 m=2 时，维维克其实就是在抛硬币：每次拉到的要么是 1（立刻逃脱），要么是 2（继续），概率各占一半。题目的提示原文正好把这个和式写了出来：

1×½ + 2×¼ + 3×⅛ + … = 2

这有什么用

"把每种可能长度乘以对应概率再全部加起来"这种做法当然可行，但它需要你知道每一种可能长度（1、2、3、4……一直到无穷）各自的概率，加起来的项数太多了。第三关会介绍一条完全绕开这个麻烦的捷径。

第三关

捷径：数一数有多少轮"还在继续"

对付这类"一直重复直到发生某件事"的游戏，有一个很妙的技巧。与其直接问"最终长度到底是多少"，不如反复问一个更简单的问题："拉了 k 次之后，游戏还在继续吗？"然后把这个答案（继续记 1，结束记 0）从 k=0 开始一直加起来。

期望长度 = P(拉0次后还在继续) + P(拉1次后还在继续) + P(拉2次后还在继续) + …

先用第二关的抛硬币游戏来验证一下这个公式。"抛 0 次后还在继续"永远成立（概率是 1，因为你压根还没抛呢）。"抛 1 次后还在继续"意味着那一次是反面（概率 ½）。"抛 2 次后还在继续"意味着两次都是反面（概率 ¼）。以此类推：

抛0次后
1
抛1次后
1/2
抛2次后
1/4
抛3次后
1/8

1 + ½ + ¼ + ⅛ + … = 2——和之前算出来的答案一样，但用了完全不同的算法！这个"还在继续"的技巧对维维克这道题特别好用，因为"还在继续"用 gcd 的语言描述起来非常干净，这正是接下来要讲的内容。

第四关

维维克的游戏什么时候"还在继续"？

拉了 k 次之后，维维克的游戏还在继续，正好就是这 k 个数字的 gcd 还没变成 1 的时候。而一组数字的 gcd 大于 1，正好就是它们全部共享某个公共因子的时候——存在某个数 d ≥ 2，能整除这 k 个数字中的每一个。

所以："拉了 k 次后还在继续"这个事件，跟"存在某个 d ≥ 2，能整除这 k 个随机拉出来的数字"是同一件事。接下来两关就是要算出这件事的概率。

提前剧透一个具体例子

对 m=4 来说，如果维维克拉到了两个 2 和一个 4，那么 gcd(2,2,4) = 2——还在继续，因为目前拉到的每一个数字都是 2 的倍数。一旦出现一个不是 2 的倍数的数字（比如拉到 1 或 3），共同的因子就被打破了，gcd 就有可能掉到 1。

第五关

每一次都是 d 的倍数的概率

在 1 到 m 之间，有多少个数是 d 的倍数？正好 ⌊m/d⌋ 个（这是整数除法——"d 能在 m 里装下几次"）。所以单单一次随机拉动结果是 d 的倍数的概率是：

pd = ⌊m/d⌋ / m

对于 k 次独立的拉动，每一次都是 d 的倍数的概率，就是把 pd 自己连乘 k 次：pdk。把这个对所有 k ≥ 0 求和，正好是一个经典的等比数列：

1 + pd + pd2 + pd3 + … = 1 / (1 − pd)

如果只有一个可能的公共因子

如果"还在继续"就只是简单地表示"每一次拉动都是这一个特定的 d 的倍数"，那我们其实已经算完了：对期望长度的贡献就是 1/(1−pd)。麻烦在于，"还在继续"其实是"是任意某个 d ≥ 2 的倍数"，而不同的 d 之间会互相重叠——这正是这道题里最棘手、也最有意思的部分。

第六关

重叠的麻烦，以及莫比乌斯函数的修正

陷阱在这里：你可能会以为"gcd 不等于 1 的概率"等于"对每一个 d ≥ 2，把'全部拉动都是 d 的倍数'的概率加起来"。但这样会重复计数。一组全都是 6 的倍数的数字，会在 d=2 时被算一次，在 d=3 时又被算一次，还会在 d=6 时再算一次——一共算了三遍！

你可能在更简单的场景里见过这种重叠问题：要数出 1 到 30 之间能被 2 或者 3 整除的数字，不能直接把"2 的倍数"（15 个）和"3 的倍数"（10 个）加起来——那样会把"6 的倍数"（5 个）重复算了两次，所以要把它们减回去：15 + 10 − 5 = 20。这就是容斥原理。

当可能同时存在很多个（不只是两个）互相重叠的因子时，数学家们用一套很巧妙的修正权重，叫作莫比乌斯函数，写作 μ(n)：

μ(1) = 1
空的情况，永远是 +1
μ(n) = (−1)k
如果 n 是 k 个互不相同的质数相乘（比如 6=2×3，或 30=2×3×5）
μ(n) = 0
如果某个质因数在 n 里重复出现（比如 4=2×2，或 12=2×2×3）

所以 μ(2) = −1，μ(3) = −1，μ(6) = +1（两个不同的质数），μ(4) = 0（2 重复了），μ(12) = 0（2 重复了）。这些正负号，正好就是容斥原理里"先加上，再减掉重叠部分"这套模式，只不过被推广到能自动处理任意多个同时重叠的因子。有了 μ，k 个随机数字的 gcd 不等于 1 的精确概率（不会重复计数！）就是：

P(gcd ≠ 1) = − ∑d=2m μ(d) × pdk

第七关

把它们全部拼起来：最终公式

现在把第三关"还在继续"的求和，和第六关不会重复计数的概率结合起来，再套用第五关的等比数列求和（从 k=1 开始，因为 k=0 那一项已经作为"第一次拉动一定会发生"这个保证的 +1 单独处理过了）：

期望长度 = 1 + ∑d=2m (−μ(d)) × ⌊m/d⌋ / (m − ⌊m/d⌋)

就是这样——一个干净的公式覆盖了所有情况。来验证一下它是否能算出我们已经知道的样例：

dμ(d)⌊m/d⌋m − ⌊m/d⌋贡献
m = 2
2−111+1
期望长度 = 1 + 1 = 2——和题目给出的答案一致！
dμ(d)⌊m/d⌋m − ⌊m/d⌋贡献
m = 4
2−122+1
3−113+1/3
40130（跳过）
期望长度 = 1 + 1 + 1/3 = 7/3——正是第一关提到的那个分数！
第八关

藏起来的分数：333333338 是怎么来的？

我们刚刚算出 m=4 时真正的答案是 7/3。但题目想要的是一个单独的整数，而计算机通常没法精确存下一个分母巨大又不确定的分数。解决办法是：所有运算都对一个大质数取模，P = 1,000,000,007，并且把"除以 3"表示成"乘以能抵消乘以 3 这件事的那个数"，这个数就叫 3 的模逆元。

多亏了一个叫费马小定理的著名捷径，只要 P 是质数，任意数 x（只要不是 P 的倍数）的模逆元就是：

x−1 mod P = xP−2 mod P

在 Python 里，pow(x, P-2, P) 能瞬间算出这个结果（快速幂让即便像 P-2 这样巨大的指数也毫无压力）。所以 7/3 mod P 就变成了 (7 × pow(3, P-2, P)) % P：

python3
>>> P = 1_000_000_007
>>> (7 * pow(3, P - 2, P)) % P
333333338
记住这一点

以后在 Codeforces 上碰到概率/计数类题目输出一个奇怪的大数字，几乎总是一个普通分数披上了伪装：P × Q−1 mod (109+7)。一旦知道这个套路，"奇怪"就完全消失了。

第九关

用 Python 把它写出来

需要两样东西：能算出每个 d（从 2 到 m）的 μ(d) 的方法，以及第七关的最终求和公式。下面是最简单的版本，用试除法分解每个数字来判断它的莫比乌斯值：

steps_to_one.py
MOD = 1_000_000_007

def mobius(n):
    result = 1
    p = 2
    while p * p <= n:
        if n % p == 0:
            n //= p
            if n % p == 0:
                return 0  # p 在 n 里出现了两次 -> mu 是 0
            result = -result
        p += 1
    if n > 1:
        result = -result  # 还剩一个质因子
    return result

m = int(input())
answer = 1
for d in range(2, m + 1):
    mu = mobius(d)
    if mu == 0:
        continue
    fd = m // d
    term = (-mu * fd) % MOD
    term = term * pow(m - fd, MOD - 2, MOD) % MOD
    answer = (answer + term) % MOD

print(answer)

正好就是第七关每个 d 的贡献：(−μ(d)) × ⌊m/d⌋ / (m−⌊m/d⌋)，只是把真正的除法换成了模逆元。
关于"变大"的提醒

m 最大可以到 100,000。对每个数字都做一次试除是可行的，但会重复做很多分解工作。更快的做法是用一种"线性筛"，一次性把 m 以内所有 μ(d) 都算出来——这跟埃拉托斯特尼筛法是同一类技巧，只是用来跟踪质因子的重复次数，而不只是标记合数。

加餐：一次性筛出所有莫比乌斯值的线性筛
steps_to_one_sieve.py
MOD = 1_000_000_007
m = int(input())

mu = [1] * (m + 1)
is_composite = [False] * (m + 1)
primes = []
for i in range(2, m + 1):
    if not is_composite[i]:
        primes.append(i)
        mu[i] = -1
    for p in primes:
        if i * p > m:
            break
        is_composite[i * p] = True
        if i % p == 0:
            mu[i * p] = 0
            break
        mu[i * p] = -mu[i]

answer = 1
for d in range(2, m + 1):
    if mu[d] == 0:
        continue
    fd = m // d
    term = (-mu[d] * fd) % MOD
    term = term * pow(m - fd, MOD - 2, MOD) % MOD
    answer = (answer + term) % MOD

print(answer)

这样只需要一次遍历，就能把从 2 到 m 的每一个莫比乌斯值都算出来，而不用对每个数字都从头分解一遍——正是这个区别，让它在 m = 100,000 时也能轻松跑得很快。

第十一关

该你练习了

先自己在纸上算出来，再用上面的工具验证。

挑战一：用第七关的公式手算 m=3 时的期望长度。

要检查的因子是 d=2 和 d=3。μ(2)=−1，⌊3/2⌋=1，贡献 = 1 × 1/(3−1) = 1/2。μ(3)=−1，⌊3/3⌋=1，贡献 = 1 × 1/(3−1) = 1/2。总和：1 + 1/2 + 1/2 = 2。m=3 的期望长度正好是 2。

挑战二：为什么公式会完全跳过所有 μ(d)=0 的 d，比如 d=4、8、9、12？

μ(d)=0 正好发生在 d 有重复质因子的时候（比如 4=2×2 或 12=2×2×3）。在容斥的过程里，这样的 d 所代表的"是 d 的倍数"这个事件，早就已经被它的无平方因子除数（也就是不重复的质因子组合）完全考虑进去了——再把它加进来只会重复修正，把总数算错。莫比乌斯函数很巧妙地把这种情况的权重直接设成 0，所以求和时完全不需要特殊处理——直接跳过就行。

挑战三：第七关里，为什么等比数列的贡献是从 k=1 开始，而不是从 k=0 开始，尽管第三关"还在继续"的求和本身是从 k=0 开始的？

k=0 这一项（"拉0次后还在继续"）不管怎样都必然成立，概率是 1——它压根不依赖 gcd 或任何因子，因为根本还没拉过数字。这正是公式最前面那个必然出现的 +1。莫比乌斯求和只需要描述 k=1, 2, 3, ……（至少拉过一次之后）发生的事情，这就是为什么它的等比数列要从 k=1 开始算。

挑战四：计算 μ(30)。（提示：先把 30 分解质因数。）

30 = 2 × 3 × 5——三个互不相同的质因子，没有重复。所以 μ(30) = (−1)3 = −1。

挑战五（较难）：题目保证 m ≤ 100,000。第九关那个线性筛大概要做多少次"质因子检查"，为什么比对每个数分别做试除快得多？

线性筛的外层循环把 2 到 m 的每个数字恰好访问一次，而每个合数在内层循环里都恰好被它的最小质因子标记一次——所以总工作量跟 m 本身成正比（严格说是 O(m)），最大输入时大约是 10 万次操作。相比之下，试除法要独立地从头分解每一个数字，对每个数字 d 大约要做 √d 次工作——大约 √100,000 ≈ 316 次每个数字，总共大约 3000 万次操作。这两种方法在这道题的数据范围内都能轻松跑进时间限制，但如果 m 以后被出到更大，线性筛的优势会明显得多。

Codeforces 1139D — Steps to One。这道题把期望值（借助"尾部概率求和"这个恒等式）、莫比乌斯函数 / 因子上的容斥原理、等比数列，以及模逆元结合在了一起——非常适合体会几种看似不相关的想法是怎么拼成一个干净公式的。
