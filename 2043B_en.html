Digits: Cracking a Number With a Factorial's Worth of Copies

Artem writes a single digit d on the board, over and over, exactly n! times in a row. For n as small as 8, that's already 40,320 copies — and n can be as large as a billion. Codeforces 2043B asks: which of the odd digits 1, 3, 5, 7, 9 divide that gigantic number evenly? You'll never build the number itself — you'll out-think it instead.

For curious 13-year-olds Builds on Magic Five & Jzzhu's Echo Machine Interactive
LEVEL 1

The mission

You're given a digit d (from 1 to 9) and a number n. Artem writes d on the board n! ("n factorial") times in a row, forming one enormous number made entirely of the digit d repeated over and over. Recall that n! = 1 × 2 × 3 × … × n — it grows unbelievably fast.

Your job: figure out which of the odd digits — 1, 3, 5, 7, 9 — evenly divide that giant number, and print them in increasing order. You'll be asked this for up to 100 different (n, d) pairs in one run.

Straight from the judge

n=2, d=6 → the board reads 66 (since 2! = 2). 1 3 divide it (66 = 2×3×11).
n=7, d=1 → the board reads 111…1 with 7! = 5040 ones. 1 3 7 9 divide it.
n=8, d=5 → the board reads 555…5 with 8! = 40320 fives. 1 3 5 7 9 — every odd digit divides it!

Why should you care?

n can be as large as 1,000,000,000. n! for even a modest n is already a monster: 20! has 19 digits, and n! for n in the billions has billions upon billions of digits. You could never store that number, let alone check it digit by digit within a 1-second time limit.

LEVEL 2

Dust off your divisibility toolkit

Before we touch the giant number, let's remember the tricks we already know for checking divisibility without doing long division:

  • Divisible by 1: always true. Every number is divisible by 1 — free point!
  • Divisible by 5: true exactly when the last digit is 0 or 5. We used this exact idea on the Magic Five page.
  • Divisible by 3 or 9: add up all the digits. If that sum is divisible by 3 (or 9), so is the original number.
  • Divisible by 7: …there's no cute digit-sum shortcut for 7. We'll need a different trick, and it's the most interesting part of this problem.

LEVEL 3

Why "just build the number" fails

The most honest approach would be: compute n!, write out d that many times, and check divisibility directly. That's totally fine for tiny n — but n can be up to a billion, and n! explodes far faster than n itself. There isn't enough storage in every computer on Earth combined to hold a number with that many digits, and there certainly isn't enough time to scan through them one at a time in 1 second.

LEVEL 4

Digit 5: the freebie we already solved

Every digit of the giant number is d — including the very last one. So the last digit of the whole number is just d itself. Using the Level 2 rule: 5 divides the number exactly when d = 5. That's it — no factorial math required at all for this one!

The one sentence that matters most

5 is in the answer if and only if d == 5. Full stop, regardless of n.

LEVEL 5

Digits 3 and 9: the digit-sum trick, supercharged by n!

The digit sum of our giant number is easy: it's d repeated n! times, so the sum is just d × n!. From Level 2: 3 divides the number iff 3 | (d × n!), and 9 divides it iff 9 | (d × n!).

Here's the beautiful part: factorials collect factors of 3 automatically. The moment n ≥ 3, the product n! = 1×2×3×…×n already includes the number 3 itself as one of its factors — so 3 | n!, which means 3 | (d × n!) no matter what d is. For 9, we need two factors of 3 hiding inside n! (since 9 = 3×3) — and that first happens once n ≥ 6, because 6! is the first factorial to contain both the factor 3 and the factor 6 (which itself is a multiple of 3).

So: for n ≥ 3, digit 3 divides our number no matter what d is. For n ≥ 6, digit 9 divides it too, no matter what d is. Only the small leftover cases (n = 3, 4, 5 for the digit 9 check) actually depend on d.

Sound familiar? Powers of 10, remainder mod 7, echo back to themselves every 6 steps — exactly the same "echoes forever" personality as the sequence on the Jzzhu's Echo Machine page, just with a different cast of numbers. This period-6 echo is the whole secret to digit 7.

Here's why it matters: a block of m repeated digits can be written as d × Rm, where Rm is the "repunit" 111…1 (m ones). It turns out 7 | Rm exactly when 6 | m — a direct consequence of that period-6 echo. And just like with the factor of 3 in Level 5, the moment n ≥ 3, the factorial n! already contains both a factor of 2 and a factor of 3, which together guarantee 6 | n!. So for n ≥ 3, m = n! is automatically a multiple of 6, the echo lands exactly back on 1, and 7 divides our number no matter what d is.

LEVEL 7

Putting it all together: one clean rule for big n

Let's collect everything we found. The thresholds where each digit's fate stops depending on d are: 3 and 7 lock in at n ≥ 3, and 9 locks in at n ≥ 6. Once n ≥ 6, all three thresholds have been crossed, giving one beautifully simple rule:

The one sentence that matters most

For n ≥ 6: the answer is always {1, 3, 7, 9}, plus 5 exactly when d = 5. The value of d otherwise makes zero difference!

That leaves only n = 2, 3, 4, 5 as special cases — and here's the fun twist: those factorials are 2, 6, 24, and 120. All tiny! For these, there's no need for any cleverness at all — just build the actual number (at most 120 digits, no problem for Python's built-in big integers) and check divisibility for real.

LEVEL 8

Reading the code, line by line

Here's the entire solution. Read the code on the left, then the plain-English translation on the right.

digits.py
import math

def solve(n, d):
    if n >= 6:
        divisors = {1, 3, 7, 9}
        if d == 5:
            divisors.add(5)
    else:
        m = math.factorial(n)          # n < 6, so m is at most 120 — tiny!
        number = int(str(d) * m)     # actually build the number
        divisors = {x for x in [1,3,5,7,9] if number % x == 0}
    return sorted(divisors)

t = int(input())
for _ in range(t):
    n, d = map(int, input().split())
    print(*solve(n, d))
if n >= 6: divisors = {1, 3, 7, 9} if d == 5: divisors.add(5)
Level 7's fast rule. No factorial ever gets computed here — the answer is figured out purely from whether n crossed the threshold and whether d equals 5.

Only reached when n < 6, so m ≤ 120. Python happily builds a 120-digit integer and stores it exactly — no overflow, ever.
divisors = {x for x in [1,3,5,7,9] if number % x == 0}
With the real number in hand, just ask Python directly: does it divide evenly? No cleverness needed for such a small case.

LEVEL 11

Practice: crack these before you check with the tool

Work each one out on paper first — then verify with the widget above.

Exercise 1: n=2, d=9. The board reads "99". Which odd digits divide it?

99 = 9 × 11. Check each: 99/1=99 yes, 99/3=33 yes, 99/5=19.8 no, 99/7≈14.14 no, 99/9=11 yes. Answer: 1 3 9.

Exercise 2: n=3, d=2. Without building the number, explain why 3 and 7 must divide it, and why 9 does not.

Since n=3 ≥ 3, both the "3 locks in" and "7 locks in" thresholds from Levels 5 and 6 have been crossed, so 3 and 7 divide the number no matter what d is. But n=3 < 6, so 9 is not automatic — it needs d to be a multiple of 3, and d=2 isn't. The board reads 222222 (6 twos, since 3!=6): digit sum is 12 (divisible by 3, not 9), confirming 1 3 7 and no 9.

Exercise 3: n=5, d=6. Which odd digits divide the board?

n=5 ≥ 3 locks in 3 and 7. For 9, we need n ≥ 6 OR d a multiple of 3 — here n=5 < 6 but d=6 is a multiple of 3, so 9 divides too! For 5, we need d=5, and d=6≠5, so no 5. Answer: 1 3 7 9.

Exercise 4 (challenge): n=1,000,000,000, d=5. You obviously can't build this number — find the answer using the Level 7 shortcut.

n ≥ 6, so the answer is {1, 3, 7, 9} automatically, and since d = 5, we add 5 too. Answer: 1 3 5 7 9 — every single odd digit, worked out instantly with no factorial in sight.

Exercise 5 (challenge): Modify the code to also report whether the board's number is divisible by 6. (Hint: 6 = 2 × 3, and you already know how to check divisibility by 2 and by 3 for this problem.)

Divisibility by 2 just needs the last digit to be even — and since every digit here is d, that means d itself must be even. Divisibility by 3 is exactly what we already solved: true whenever n ≥ 3, or (for smaller n) whenever the built number's digit sum works out. So the number is divisible by 6 exactly when both conditions hold at once:

digits_with_six.py
import math

def solve(n, d):
    if n >= 6:
        divisors = {1, 3, 7, 9}
        if d == 5:
            divisors.add(5)
        divisible_by_6 = (d % 2 == 0)   # 3 already guaranteed when n>=6
    else:
        m = math.factorial(n)
        number = int(str(d) * m)
        divisors = {x for x in [1,3,5,7,9] if number % x == 0}
        divisible_by_6 = (number % 6 == 0)
    return sorted(divisors), divisible_by_6
