SPOJ VECTAR8 · 题目精讲

惊悚质数：从头被一刀刀砍掉却依然活下来的数字

找一个质数。把它最左边那一位数字砍掉。剩下的还是质数吗？再砍一次。还是质数吗？一直砍下去，直到只剩最后一位数字。一个质数如果能扛过这整个"凌迟"过程——而且自始至终没有出现过一个数字 0——就能获得"惊悚质数"的称号。你的任务：数出不超过某个数字 N 的惊悚质数一共有多少个，而且要不慌不忙地回答多达 10 万次这样的问题。

不需要数学基础 埃拉托斯特尼筛法与预处理 可以互动
第一关

任务目标，原样来自题目

题目会问你最多 T = 100,000 个问题，每个问题就是一个数字 N（1 ≤ N < 1,000,000）。对每一个问题，你要回答：不超过 N 的惊悚质数一共有多少个？

一个数字要成为惊悚质数，必须同时满足下面所有条件：

  • 它本身是质数。
  • 它的每一位数字里都没有 0。
  • 如果把它最左边的一位数字删掉，剩下的数字依然是惊悚质数——而且你可以不断重复"删掉新的最左边一位"这个动作，一路删到只剩下最后一位数字为止，每一个中间阶段都必须始终保持是质数。
题目原样给出的例子

输入：3（三个问题），然后是 2、3、4——每行一个。
输出：1、2、2。
为什么？不超过 2 的惊悚质数只有 2 自己——那就是 1 个。不超过 3 时，又多了一个 3——变成 2 个。3 到 4 之间没有新的惊悚质数出现（4 甚至都不是质数），所以还是 2。

再看一个更大的例子，把整个过程看清楚

七位数 4632647 就是一个惊悚质数。看看从左边一位一位往下砍时，都留下了什么：4632647 → 632647 → 32647 → 2647 → 647 → 47 → 7。这七个数字全都是质数，而且原来那七位数字里，没有一个是 0。要拿到"惊悚"这个头衔，就得做到这个地步。

为什么砍着砍着就不灵了？

随便拿一个质数试试，比如 29：把最前面的 2 砍掉，剩下 9——而 9 不是质数（9 = 3 × 3）。所以 29 立刻就不合格了，尽管 29 本身是一个完全合格的质数。绝大多数质数几乎一上来就会在这个测试里败下阵来——惊悚质数很稀少，而这正是"数清它们一共有多少个"变成一道有趣谜题的原因。

第二关

复习一下：质数与埃拉托斯特尼筛法

质数是大于 1 的整数中，除了 1 和它自己之外没有别的因数的数。要快速找出某个范围内的所有质数，我们用埃拉托斯特尼筛法：一开始假设每个数字都是质数，然后每找到一个质数，就把它所有的倍数全部划掉（2 划掉 4、6、8……；3 划掉 6、9、12……；以此类推）。每一轮划掉之后，还活着的那些数字，就是质数。

sieve.py
LIMIT = 1_000_000
is_composite = bytearray(LIMIT + 1)
is_composite[0] = is_composite[1] = 1

for i in range(2, int(LIMIT**0.5) + 1):
    if not is_composite[i]:
        for j in range(i * i, LIMIT + 1, i):
            is_composite[j] = 1
已经见过筛法了吗？

如果你看过质数侦探事务所那份案卷，这段代码应该很眼熟——这正是同一个筛法。不过在这里，找出质数只是第一步，真正的谜题在后面。

第三关

为什么一个一个数字单独检查会慢得离谱

最直接的想法是：对每一个问题里的 N，从 2 循环到 N，每个数字都检查一遍"它是不是质数、有没有数字 0、反复砍掉最左边一位之后是不是始终保持质数？"这个想法完全正确——但慢得让人绝望。

解决办法，一句话说清

把所有费脑子的活儿提前做一次，赶在任何问题到来之前——把 999,999 以内的每一个数字都先算清楚是不是惊悚质数，再建一份累计统计表，这样任何问题都能靠查一次数组瞬间答出来。

第四关

核心技巧：先把小答案算好

这里是让整道题豁然开朗的关键洞察。要知道一个数字 n 是不是惊悚质数，我们需要知道砍掉它最左边一位之后剩下的那个数字——姑且叫它后缀——是不是也是惊悚质数。但这个后缀永远比 n 小（它的位数更少，就算 n 只有一位数，最坏情况也不过是数值相同）。这意味着：只要我们按从小到大的顺序，从 2 一路处理到 999,999，等我们需要用到某个后缀的答案时，它早就已经算好、等在那里了。

4632647
→ 后缀
632647
← 已经算过了！

这正是"先解决小块，再把小块的答案拿来拼出大块的答案"这套动态规划思想在各处的应用——你可能在计算斐波那契数列或者数路径条数时见过类似的想法。在这里，一个数字的"小块"就是它自己的后缀，而我们恰好会因为按顺序从小数到大数，提前访问到它。

"后缀"到底是什么？

如果 n 有 k 位，那么它砍掉最左边一位之后的后缀，就是 n % 10k-1——也就是除以合适的 10 的幂之后的余数。对于 4632647（7 位数）来说，后缀就是 4632647 % 1000000 = 632647。不断用越来越小的 10 的幂去取余（% 100000、% 10000、……、% 10），你就走过了"每次砍剩" 的每一个阶段，从"只砍掉最前面一位"一路走到"只剩最后一位数字"。

第五关

唯一的陷阱：算术运算根本不知道"前导零"这回事

这里有一个几乎每个人第一次都会踩的坑。假设一个数字中间某个位置藏着一个 0，比如 907。如果我们用 907 % 100 来砍掉最前面一位，得到的是 7——而不是 "07"。算术运算会悄无声息地把前导零吞掉。可是 907 本来就应该因为含有数字 0 而被淘汰——而如果我们只检查"这个余数是不是质数"，我们根本不会发现问题，因为 7 确确实实是质数！

修补办法：提前单独检查有没有 0

在做任何砍数字的逻辑之前，先直接看这个数字的每一位（可以把它转成字符串，或者反复用 n % 10 检查），只要哪一位出现了 0，就立刻淘汰它。只有通过了这道关卡的数字，才有资格进入"砍数字"测试。

一个有趣的数学事实

像这样"从左边一位一位砍下去依然保持质数"的数字，在数学上叫做左可截断质数。事实证明，在整个无穷无尽的数字世界里，这样的数字总共只有 4,260 个——最大的那一个有 24 位。一旦数字大到一定程度，想要扛过每一次砍削，基本上就变得不可能了。

第六关

把"是不是惊悚"变成秒答

一旦我们知道了 999,999 以内每一个数字是不是惊悚质数，回答查询还差最后一小步。查询问的是"不超过 N 的惊悚质数有多少个？"——而不是"N 本身是不是惊悚质数？"所以我们再建一个数组：累计计数，其中第 i 项记录的是从 0 到 i 之间一共有多少个惊悚质数。

count[i]

count[i-1]
+
如果 i 是惊悚质数就是 1，否则是 0

建这份累计计数表只需要把所有数字扫一遍，之后每一个查询——哪怕全部 10 万个——都只需要查一次数组就能答出来。不管问题来多少个，费功夫的那部分工作永远只做一次。

用 Python 写出来

第五关的零位陷阱：在考虑"砍数字"之前，先淘汰含有 0 的数字。非质数也在这里被立刻跳过。
ten = 10 ok = True while ten <= n: suffix = n % ten if suffix < 2 or not scary[suffix]: ok = False break ten *= 10 scary[n] = ok
第四关的砍数字检查：依次走过每一个后缀（最后 1 位、最后 2 位……），确认每一个都已经被标记为惊悚——因为每个后缀都是我们更早之前访问过的更小的数字，这一点是有保证的。

第六关的累计计数：扫一遍，之后每一次查询都变成瞬间完成的数组查找。

完整程序如下：

vectar8.py
import sys

LIMIT = 1_000_000

# 第一步：埃拉托斯特尼筛法
is_composite = bytearray(LIMIT + 1)
is_composite[0] = is_composite[1] = 1
for i in range(2, int(LIMIT**0.5) + 1):
    if not is_composite[i]:
        for j in range(i * i, LIMIT + 1, i):
            is_composite[j] = 1

# 第二步：判断哪些质数是"惊悚"的
scary = bytearray(LIMIT + 1)
for n in range(2, LIMIT + 1):
    if is_composite[n]:
        continue
    if '0' in str(n):
        continue
    ten = 10
    ok = True
    while ten <= n:
        suffix = n % ten
        if suffix < 2 or not scary[suffix]:
            ok = False
            break
        ten *= 10
    scary[n] = ok

# 第三步：前缀累计计数，让每次查询都是 O(1)
count_upto = [0] * (LIMIT + 1)
running = 0
for n in range(LIMIT + 1):
    if scary[n]:
        running += 1
    count_upto[n] = running

# 第四步：瞬间回答每一次查询
data = sys.stdin.read().split()
t = int(data[0])
out = []
for i in range(1, t + 1):
    n = int(data[i])
    out.append(str(count_upto[n]))
print("\\n".join(out))
为什么要一次性读完全部输入？

最多有 10 万次查询，如果每次查询都单独调用一次 Python 的 input()，累积起来的开销就会变得很可观。用一次 sys.stdin.read() 把所有输入读进来、提前拆成一个列表，最后把所有答案拼在一起一次性打印出来，就能完全避开这份开销——这是面对"大量查询"这类题目时的标准技巧。

第十关

轮到你练习了

先用纸笔自己算一遍，再用上面的工具检查答案。

练习 1：373 是惊悚质数吗？把砍数字的过程写出来。

373 没有数字 0。它是质数吗？是的。砍成 73：是质数吗？是的。砍成 3：是质数吗？是的。全部检查通过——373 是惊悚质数。

练习 2：103 是惊悚质数吗？用第五关的陷阱来解释。

103 含有数字 0，所以立刻被淘汰——不是惊悚质数——不管砍数字的结果本来会怎样。（事实上 103 确实是质数，103 % 10 = 3 也确实是质数，这正是那个陷阱：单靠算术运算根本发现不了那个零，这正是第五关坚持要直接检查每一位数字的原因。）

练习 3：为什么算法要严格按从小到大的顺序（2、3、4、5……）处理数字，而不是反过来从大到小？

因为判断 n 是不是惊悚质数，需要事先知道 n 的后缀是不是惊悚质数——而后缀永远是一个更小的数字。如果按从大到小的顺序处理，我们就会在还没算出某个更小数字的答案之前，就需要用到它——这是一个鸡生蛋蛋生鸡的死循环。从小到大处理，就能保证我们需要查的每一个后缀，都早已经算好了。

练习 4（较难）：为什么惊悚质数不可能以数字 5 结尾（5 本身除外）？

任何比 5 大、又以 5 结尾的数字，都能被 5 整除（因为 5 本身就能整除它），所以除非它就是 5，否则它不可能是质数。因为最后剩下的那一位数字，本身就是必须独立成为质数的"后缀"之一，所以任何位数超过一位的惊悚质数都不可能以 5 结尾——那最后一步的单位数检查会立刻失败。同样的道理，也排除了以偶数结尾的惊悚质数（2 本身除外）。
