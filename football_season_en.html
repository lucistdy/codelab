The Football Season: Rebuild the Scoreboard

A team played n games and scored p points, but every scoresheet got lost. All you know is how many points a win and a draw were worth. Codeforces 1244C asks: can you reconstruct a believable record of wins, draws, and losses? And can you do it even when n is a trillion and p is a hundred quadrillion?

Builds on Ebony & Ivory One new trick: mod d Interactive
LEVEL 1

The mission

A team played n games and finished with p points. Every win is worth w points, every draw is worth d points, and every loss is worth 0. Find non-negative whole numbers x (wins), y (draws), and z (losses) such that:

x×w + y×d = p   and   x + y + z = n

Any valid triple is accepted — there's no single "correct" answer. If no triple works, report -1.

Straight from the judge

n=30, p=60, w=3, d=1 → 17 9 4 (17×3 + 9×1 = 60, and 17+9+4 = 30). Other valid answers exist too, like 20 wins, 0 draws, 10 losses.
n=10, p=51, w=5, d=4 → -1 (the most points possible in 10 games is 10×5 = 50, and 51 is already too many).
n=20, p=0, w=15, d=5 → 0 0 20 (zero points means every single game was a loss).

Why should you care?

n can be as large as 1,000,000,000,000 (a trillion!) and p can be as large as 100,000,000,000,000,000. Any plan that tries out possibilities one game at a time is going to run out of time long before it runs out of games to check.

LEVEL 2

You've basically solved half of this already

Look closely at that first equation: x×w + y×d = p. That's exactly the shape of the puzzle from Ebony and Ivory (Codeforces 1036A) — two "denominations" (here, win-points and draw-points) that need to add up to an exact total.

The twist this time: it's not enough for x and y to exist. You also need x + y ≤ n, because every win and draw uses up one of your n games, and whatever's left over (z = n − x − y) has to be zero or more — you can't have a negative number of losses!

Cold Case File

If the idea of searching for x and y in x×w + y×d = p feels unfamiliar, the Ebony and Ivory page builds it up from scratch. This page assumes you've got that part down and focuses on the new twist: the games budget.

LEVEL 3

Why the old trick alone is too slow here

In Ebony and Ivory, the winning move was to loop x from 0 upward and check whether the leftover damage divided evenly by b. That worked because the target was never bigger than 10,000, so the loop was tiny.

Here, x could need to run all the way up to n, which is up to a trillion. A loop that runs a trillion times, even doing almost nothing each step, will not finish inside a 1-second time limit. We need a way to skip straight to the useful values of x, without visiting the useless ones in between.

LEVEL 4

The key insight: only d starting points actually matter

Here's the trick, in two parts.

Part 1 — remainders repeat every d steps. Take any value of x and add d to it. The points from wins change by d×w — and since that's a multiple of d, it doesn't change the remainder when you divide by d at all (just like how 3 o'clock and 15 o'clock point to the same spot on a 12-hour clock, because 12 is a multiple of the clock's size). So x×w mod d only depends on x mod d — meaning there are only d genuinely different starting points to try, not n of them.

Part 2 — once you're on a working remainder, push x as high as it'll go. Compare two ways of scoring the same w×d points: d wins (d×w points) or w draws (w×d points) — same score, since multiplication doesn't care about order. But d wins only take d games, while w draws take w games — and w > d is guaranteed by the problem. So trading draws for wins (same score!) always frees up games.

Same points, but d wins use only d games while w draws use w games — and w > d, so wins are the more "efficient" way to bank the same score.

The one sentence that matters most

Check only the d possible remainders for x. For each one that can reach the score, push x as high as possible (using the trade above) — that uses the fewest total games, giving you the best shot at fitting inside n.

LEVEL 5

Reading the code, line by line

Here's the entire solution. Don't worry about understanding it all at once — read the code on the left, then the plain-English translation on the right.

football_season.py
n, p, w, d = map(int, input().split())

best_m = min(n, p // w)   # the most wins you could ever afford
answer = None

for r in range(d):
    if (r * w) % d == p % d and r <= best_m:
        x = r + d * ((best_m - r) // d)   # push x as high as it'll go
        y = (p - x * w) // d
        if x + y <= n:
            answer = (x, y, n - x - y)
            break

if answer is None:
    print(-1)
else:
    print(*answer)

Remainder r=0 didn't even match, so we skipped straight past it — no need to compute anything else for it. The very next remainder, r=1, worked on the first try. In the worst case we'd check all d remainders, but d is at most 100,000 — nowhere near a trillion.

LEVEL 8

Quick challenges (no peeking until you've tried)

Test the search on paper before you check with the tool above.

Challenge 1: n=20, p=0, w=15, d=5. What's the answer, and why does the loop find it immediately at r=0?

best_m = min(20, 0 // 15) = 0. At r=0: 0×15 mod 5 = 0, and p mod 5 = 0 — matches! Since best_m is already 0, x can't be pushed any higher: x = 0. Then y = (0 − 0) / 5 = 0, and 0 + 0 = 0 ≤ 20. Answer: 0 0 20 — with 0 points on the board, there's no way any game was a win or a draw.

Challenge 2: n=10, p=51, w=5, d=4. Walk through why every remainder eventually fails.

best_m = min(10, 51 // 5) = 10. p mod 4 = 3. Checking remainders: r=0 gives 0, r=1 gives 1, r=2 gives 2, r=3 gives 3×5 mod 4 = 3 — matches! Push x up: x = 3 + 4×((10−3)//4) = 3 + 4 = 7. Then y = (51−35)/4 = 4, and 7+4=11 > 10 — too many games needed. No other remainder matched, so the answer is -1.

Challenge 3: Why do we only need to check d different remainders instead of every x from 0 to n?

Because x×w mod d only depends on x mod d (Level 4, Part 1) — adding d to x always adds a multiple of d to x×w, which never changes the remainder. So every value of x shares its "match or no match" verdict with exactly one of the d possible remainders. Checking all n values of x would just mean re-checking the same d verdicts over and over, up to n/d times each — pure repeated work.

Challenge 4: The problem accepts any valid triple. Can you change the code to instead find the triple with the most wins possible, out of all valid remainders?
football_season_max_wins.py
n, p, w, d = map(int, input().split())

best_m = min(n, p // w)
best_answer = None

for r in range(d):
    if (r * w) % d == p % d and r <= best_m:
        x = r + d * ((best_m - r) // d)
        y = (p - x * w) // d
        if x + y <= n:
            if best_answer is None or x > best_answer[0]:
                best_answer = (x, y, n - x - y)

print(-1 if best_answer is None else " ".join(map(str, best_answer)))
