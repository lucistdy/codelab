Moodular Arithmetic: How Many Functions Survive the Herd?

Farmer Ivan's star pupil Kevin Sun is stuck on a strange rule: a function f, defined on the numbers 0 through p−1, must obey f(kx mod p) ≡ k·f(x) (mod p) for every single x. Some choices of f work. Most don't. Codeforces 603B asks: exactly how many different f's survive this rule, out of every possible way to fill in the table?

For curious 13-year-olds Builds on the "echo" idea from earlier pages Interactive
LEVEL 1

The mission

You're given an odd prime p and a number k (with 0 ≤ k ≤ p−1). Imagine building a lookup table — a function f — that assigns to each number x in {0, 1, …, p−1} some output f(x), also in {0, 1, …, p−1}. That table is only "allowed" if it satisfies this rule for every single x in that range:

f(kx mod p) ≡ k · f(x)  (mod p)

In plain words: if you take any input x, multiply it by k and wrap around mod p to get a new input kx mod p, then the table's output there must equal k times the original output, also wrapped mod p. Your job: count how many different valid tables f exist, modulo 1,000,000,007.

Straight from the judge

p=3, k=2 → 3 valid tables. The judge's note lists all three: f = [0,1,2], f = [0,2,1], and f = [0,0,0] (reading f(0), f(1), f(2) in order).
p=5, k=4 → 25 valid tables.

Why should you care?

p can be as large as 1,000,000. There are pp possible ways to fill in a lookup table of that size in the first place — an astronomically large number, far too many to try one at a time. We need to figure out how many of them are valid without checking each one.

LEVEL 2

Studying the three survivors

Let's understand why those three tables work for p=3, k=2, by checking the rule at every x. Remember, we need f(2x mod 3) ≡ 2f(x) (mod 3) to hold for x = 0, 1, and 2.

table fx=0 checkx=1 checkx=2 check
[0, 1, 2]f(0)=0 =2×0 ✓f(2)=2 =2×1 mod3=2 ✓f(1)=1 =2×2 mod3=1 ✓
[0, 2, 1]f(0)=0 =2×0 ✓f(2)=1 =2×2 mod3=1 ✓f(1)=2 =2×1 mod3=2 ✓
[0, 0, 0]f(0)=0 =2×0 ✓f(2)=0 =2×0 mod3=0 ✓f(1)=0 =2×0 mod3=0 ✓

Notice something every single one of them shares: f(0) is always 0. And look at the other two entries — in every valid table, whatever you pick for f(1), the value of f(2) gets completely determined for you (either equal to f(1), doubled, or forced by the pattern). It's as if the values 1 and 2 are chained together, and 0 stands alone. That's exactly the structure we're about to uncover.

LEVEL 3

Two easy special cases first

Before tackling the general case, let's knock out the two edge values of k.

If k = 1: the rule becomes f(x) ≡ f(x) (mod p) — always true, no matter what! There's no constraint at all, so f can be any function whatsoever: each of the p inputs can map to any of the p outputs, giving pp valid tables.

If k = 0: then kx mod p = 0 for every single x, and the rule becomes f(0) ≡ 0 × f(x) = 0 (mod p) for every x. That's really just one constraint, repeated p times: f(0) = 0. Every other output, f(1) through f(p−1), is completely free — giving pp−1 valid tables.

The one sentence that matters most

k=1: zero constraints, so pp tables. k=0: one constraint (f(0)=0), so pp−1 tables. Now, what about every value of k in between?

LEVEL 4

The general case: multiplying by k is an echo machine

Now suppose 2 ≤ k ≤ p−1. Since p is prime and k isn't a multiple of it, multiplying by k (mod p) turns out to be a shuffle: it rearranges the nonzero numbers 1, 2, …, p−1 among themselves, with no two numbers ever landing on the same spot. And just like the powers-of-10 pattern from the Digits page and the sequence from Jzzhu's Echo Machine, repeatedly multiplying by k eventually echoes back to where you started — every nonzero number belongs to a repeating loop.

Let's watch it happen for p=5, k=4. Start at 1 and keep multiplying by 4, wrapping mod 5:

That's a loop of length 2: {1, 4}. What about starting at 2?

Another loop of length 2: {2, 3}. So all four nonzero numbers, 1 through 4, split perfectly into two loops of length 2 each. And 0? Multiplying 0 × 4 = 0, so 0 always sits by itself in its own private loop of length 1, no matter what k is.

Cold Case File

This loop length has an official name: the multiplicative order of k modulo p — the smallest positive L with kL ≡ 1 (mod p). It's the exact same "how many steps until it echoes back to the start" question that powered the period-6 pattern on the Digits page, just with a different k and p each time.

LEVEL 5

Why each loop is worth exactly p choices

Here's the key move. Pick any loop of nonzero numbers, say {1, 4} from our example. The rule says f(4) = f(1×4 mod5) ≡ 4×f(1) (mod 5) — so the moment you choose f(1), the value of f(4) is completely forced. You don't get to choose it separately.

So how many free choices does this loop actually give us? Exactly one — whatever we pick for f(1), out of p possible values (0 through p−1). Once f(1) is chosen, the rule marches around the entire loop and hands you every other value automatically. And because the loop echoes perfectly back to 1 after L steps (that's the definition of the order L!), there's never a contradiction waiting at the end — the chain of forced values always comes back around and agrees with your original choice.

What about the lonely loop {0}? The rule there says f(0) ≡ k×f(0) (mod p), which rearranges to (k−1)×f(0) ≡ 0 (mod p). Since p is prime and k ≠ 1 here (we already handled k=1 separately), k−1 is not a multiple of p, which forces f(0) = 0 as the only valid choice. Zero freedom — just like we found by hand back in Level 2!

The one sentence that matters most

Every nonzero loop contributes a factor of p (one free choice, then everything else is forced). The {0} loop contributes a factor of 1 (no freedom at all). Multiply those factors together across all the loops, and you've counted every valid table exactly once.

LEVEL 6

Counting the loops

The p−1 nonzero numbers split into loops that are all the same length, L (the multiplicative order of k). So the number of nonzero loops is simply (p−1) / L. Combining with Level 5's "each nonzero loop contributes a factor of p":

answer = p(p−1)/L  (mod 1,000,000,007)

Let's double-check against p=5, k=4: we found L=2 (two loops of length 2), so (p−1)/L = 4/2 = 2, giving 5² = 25. That matches the judge's answer exactly!

LEVEL 7

Reading the code, line by line

Here's the entire solution. Read the code on the left, then the plain-English translation on the right.

moodular.py
MOD = 1000000007

p, k = map(int, input().split())

if k == 0:
    print(pow(p, p - 1, MOD))
elif k == 1:
    print(pow(p, p, MOD))
else:
    L = 1
    cur = k % p
    while cur != 1:      # walk the echo until it lands back on 1
        cur = (cur * k) % p
        L += 1
    print(pow(p, (p - 1) // L, MOD))
if k == 0: print(pow(p, p - 1, MOD)) elif k == 1: print(pow(p, p, MOD))

LEVEL 10

Practice: crack these before you check with the tool

Work each one out on paper first — then verify with the widget above.

Exercise 1: p=7, k=6. Note that 6 ≡ −1 (mod 7). What's the order of −1, and what's the answer?

(−1)¹ = −1 ≠ 1, but (−1)² = 1. So the order is L=2. Number of nonzero loops: (7−1)/2 = 3. Answer: 7³ = 343.

Exercise 2: p=7, k=2. Trace the loop starting at 1 by hand (multiply by 2, mod 7, until you echo back to 1).

1 → 2 → 4 → 8 mod7=1. That's 3 steps, so L=3. Number of nonzero loops: (7−1)/3=2. Answer: 7² = 49. (The two loops are {1,2,4} and {3,6,5} — check that 3×2=6, 6×2=12mod7=5, 5×2=10mod7=3, echoing back!)

Exercise 3: p=11, k=10. Same trick as Exercise 1 — 10 ≡ −1 (mod 11). Find the answer without a computer.

(−1)²=1, so L=2 again. Nonzero loops: (11−1)/2=5. Answer: 11⁵ = 161051.

Exercise 4 (challenge): p=1,000,003 (a large prime) and k=1. What's the answer, and why can you give it instantly without any loop-finding at all?

k=1 is the special case from Level 3 — the rule imposes zero constraints, so every function works. The answer is simply pp mod 1{,}000{,}000{,}007, computed with one call to fast modular exponentiation. No loop-walking needed, because there's nothing to trace — every input is its own trivial "loop" of length 1 once k=1.
