阶乘末尾的爱：数清任意进制下 n! 末尾有多少个零

当 n 大到 1018 时，n! 的位数多到地球上所有硬盘加起来都装不下——而你还要把它写成某种奇怪的进制 b，数出末尾一共有多少个零。你永远不会真的把这个数字造出来，但依然能在远小于一秒的时间里，把它末尾的零数清楚。

不需要数学基础 质数、进制与 Legendre 公式 可以互动
第一关

任务目标，原样来自题目

给你两个整数：n（最大 1018）和一个进制 b（从 2 到 1012）。计算 n! = 1 × 2 × 3 × \cdots × n（n 的阶乘），把它写成 b 进制（而不是我们常用的十进制），然后数一数这个写法末尾一共有多少个零。

题目原样给出的例子

n=6, b=9 → 1（因为 6! = 720，而 720 写成 9 进制是 880——末尾一个零）
n=5, b=2 → 3（因为 5! = 120，二进制写法是 1111000——末尾三个零）
n=5, b=10 → 1（同样是 120，但普通十进制下末尾只有一个零）

为什么不能直接算出 n!

n 可以大到十亿的十亿倍。哪怕 n 只有 106 这么"小"，n! 就已经有几百万位数字了——如果 n = 1018，把这个数字真正写下来所需要的位数，比可观测宇宙里的原子总数还多。我们需要一种完全不用真正造出这个数字就能数清末尾零的办法。

第二关

末尾的零究竟意味着什么

在任意进制 b 下，一个数字的每一位，代表着它由多少个 1、多少个 b、多少个 b²、多少个 b³……组成。最后一位是零，意味着"没有 1"。最后两位都是零，意味着"没有 1，也没有 b"——这恰好等价于说整个数字能被 b² 整除，一点余数都不剩。

一般来说：一个数字在 b 进制下至少有 k 个末尾零，当且仅当它能被 bk 整除。所以"数清 n! 在 b 进制下有多少个末尾零"，本质上问的是：能整除 n! 的、最大的 b 的幂次是多少？这是一个关于整除性的问题，完全不需要真的把任何一位数字写出来。

第三关

热身：经典的十进制版本

你可能已经见过一个经典的谜题：普通十进制下，n! 末尾有多少个零？因为 10 = 2 × 5，一个末尾零需要一个因子 2加上一个因子 5。在 1×2×3×\cdots×n 里，2 的倍数到处都是（每隔一个数就有一个！），但 5 的倍数要稀少得多——所以 5 的数量永远是瓶颈。

要数清质数 5 在 n! 里出现了多少次，不能只数 5 的倍数个数——像 25 这样的数字，贡献的是两个因子 5，而不是一个，125 贡献三个。干净利落地把它们全部数清的方法，叫做 Legendre 公式：

⌊n/p⌋
+
⌊n/p²⌋
+
⌊n/p³⌋
+ …

⌊n/p⌋ 数出了 n 以内 p 的每一个倍数——每一个都至少贡献一个因子 p。⌊n/p²⌋ 数出了 p² 的倍数，其中每一个都比第一次多贡献一个额外的因子（这正是为什么要单独加上它，而不是从头重新数一遍）。p³、p⁴……以此类推，直到 p 的幂超过 n，这些项就变成 0 了。

小测验：12! 在十进制下有多少个末尾零？

数 12! 里的 5：⌊12/5⌋ + ⌊12/25⌋ = 2 + 0 = 2。数 2：⌊12/2⌋+⌊12/4⌋+⌊12/8⌋ = 6+3+1=10。5 先用完，所以 12! 在十进制下恰好有 2 个末尾零。（验证一下：12! = 479001600——确实末尾两个零。）

第四关

推广：如果 b 不是质数呢？

第三关之所以管用，是因为 10 = 2 × 5 碰巧是两个质数的乘积，而且各自的指数都是 1。但我们题目里的 b 可以是任何数字——一个质数、一个质数的平方、五个不同质数带着奇怪指数的组合，什么都有可能。我们需要把"5 是瓶颈"这个想法推广到一般情况。

任何整数 b 都能唯一地分解成质数：b = p₁e₁ × p₂e₂ × \cdots × pₖeₖ。要让 n! 能被 bk 整除，它需要含有至少 k × eⁱ 份 b 配方里的每一个质数 pⁱ。如果 n! 一共含有 Eⁱ 份质数 pⁱ（用第三关的 Legendre 公式算出来），那么单单对这一个质数来说，能撑住的最大 k 就是 ⌊Eⁱ / eⁱ⌋。

瓶颈就是最先"用完"的那个质数

因为每一个 b 配方里的质数都必须同时跟上，真正的答案就是所有质数里那个最小的值：answer = minⁱ( ⌊Eⁱ / eⁱ⌋ )。这正是第三关"5 比 2 稀少"那套推理的完全推广——不管 b 到底是由多少个质数、带着多大的指数组成的。

用样例 1 验证一下：b = 9 = 3²，只有一个质数需要担心，指数为 2。6! 含有 ⌊6/3⌋+⌊6/9⌋ = 2+0 = 2 份质数 3。答案：⌊2/2⌋ = 1 个末尾零——和题目给出的答案完全一致。

第五关

还需要搭建的两个工具

第四关给出了整体方案；现在需要两个快速的工具来真正把它实现出来。

工具 A——分解 b。因为 b ≤ 1012，我们可以用 质因数分解 那篇里同样的 √b 试除法捷径找出它的全部质因数：从 2 开始逐个测试候选除数，每次把当前候选彻底除干净再往下走，一旦候选除数超过 √b 就停止（剩下的部分，如果大于 1，就是最后一个质因数）。

factorize.py
def factorize(b):
    factors = {}
    d = 2
    while d * d <= b:
        while b % d == 0:
            factors[d] = factors.get(d, 0) + 1
            b //= d
        d += 1
    if b > 1:
        factors[b] = factors.get(b, 0) + 1
    return factors

工具 B——Legendre 公式。对任意质数 p，用第三关的 ⌊n/p⌋ + ⌊n/p²⌋ + \cdots 求和，数出它在 n! 里出现了多少次：

exponent_in_factorial.py
def exponent_in_factorial(n, p):
    total = 0
    power = p
    while power <= n:
        total += n // power
        power *= p
    return total

≤ 约 106 步
分解 b 所需的时间，因为 √(1012) = 106
为什么 Legendre 循环这么短

每跑一次循环，power 都会乘以 p（至少是 2），所以大约 log₂(n) 步之后，power 就会超过 n，循环随之停止。对 n = 1018 来说，log₂(1018) ≈ 60。翻倍增长快得超乎想象——这正是 快速幂 那套技巧背后的同一个道理，只是这里反过来用而已。

第六关

用 Python 写出来

把第四、五关拼在一起：分解 b，对它的每一个质因数用 Legendre 公式，把每个指数除以 b 需要的份数，再取最小值。

factors = factorize(b)
第五关工具 A：把 b 拆解成 {质数: 指数} 的字典。
return min( exponent_in_factorial(n, p) // e for p, e in factors.items() )
第四关的公式：对 b 里每一个指数为 e 的质数 p，看看 n! 里那份 p 的库存，能凑出多少整份的 e——然后在 b 所有质数里取最小值，因为那个最先用完的才是关键。

下面是完整的程序：

trailing_zeros.py
def factorize(b):
    factors = {}
    d = 2
    while d * d <= b:
        while b % d == 0:
            factors[d] = factors.get(d, 0) + 1
            b //= d
        d += 1
    if b > 1:
        factors[b] = factors.get(b, 0) + 1
    return factors

def exponent_in_factorial(n, p):
    total = 0
    power = p
    while power <= n:
        total += n // power
        power *= p
    return total

def trailing_zeros(n, b):
    factors = factorize(b)
    return min(
        exponent_in_factorial(n, p) // e
        for p, e in factors.items()
    )

n, b = map(int, input().split())
print(trailing_zeros(n, b))

第九关

轮到你练习了

先用纸笔自己算一遍，再用上面的工具检查答案。

练习 1：10! 在十进制下有多少个末尾零？

数 5：⌊10/5⌋ = 2。数 2：⌊10/2⌋+⌊10/4⌋+⌊10/8⌋ = 5+2+1=8。5 先用完：答案 2。（验证：10! = 3628800。）

练习 2：10! 在 4 进制（4 = 2²）下有多少个末尾零？

只有一个质数 2，在 b 里的指数是 2。根据练习 1，10! 含有 8 份质数 2。答案：⌊8/2⌋ = 4。

练习 3：为什么算法要在 b 的各个质因数之间取最小值，而不是求和或者取平均？

因为 n! 要能被 bk 整除，必须同时对 b 配方里每一个质数都有足够的份数——这是"全部都要达标"的要求，不是"平均下来差不多就行"。哪怕只有一个质数在 b 里只能撑住 k=1，而其他质数都能撑住 k=100，整个 b² 依然整除不了 n!，因为那个稀缺的质数根本凑不出两份。取最小值，正是"最弱的一环决定整体"这条规则的数学写法。

练习 4（较难）：答案有没有可能是 0？给出一个具体的 n 和 b 的例子。

有——只要 b 的某个质因数在 n! 里根本不出现，或者出现的次数不够凑出哪怕一整份 b。比如 n=3, b=25=5²：3! = 6 里质数 5 出现了 0 次（⌊3/5⌋=0），所以 ⌊0/2⌋=0 个末尾零。这也很好理解：6 在 25 进制下就是单独一位数字 6——根本没有末尾零。

练习 5：修改 Python 代码，让它对 b 的每一个质因数都打印出：n! 里含有多少份这个质数、需要多少份——这样就能直观看出到底是哪个质数成了瓶颈。
trailing_zeros_debug.py
def trailing_zeros_debug(n, b):
    factors = factorize(b)
    best = None
    for p, e in factors.items():
        available = exponent_in_factorial(n, p)
        k = available // e
        print(f"prime {p}: n! has {available} copies, b needs {e} per zero -> supports {k} zeros")
        if best is None or k < best:
            best = k
    return best

和第六关一样的核心逻辑，只是把每个质数的中间结果都打印出来，而不是悄悄取最小值。
