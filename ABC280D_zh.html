阶乘与倍数：把 Legendre 公式反过来用

你已经会检查 N! 能不能被某个数 K 整除了。这道题把问题反过来问：给定 K，找出让这件事成立的最小 N。听起来好像要做一场巨大的搜索——但用来数阶乘末尾有多少个零的那个工具，反过来用、再配上一点二分查找，眨眼间就能把它解决。

不需要数学基础 质因数分解与二分查找 可以互动
第一关

任务目标，原样来自题目

给你一个整数 K（2 ≤ K ≤ 1012）。找出最小的正整数 N，使得 N!（N 的阶乘，也就是 1 × 2 × 3 × \cdots × N）是 K 的倍数。

题目原样给出的例子

K = 30 → N = 5（因为 5! = 120 = 30 × 4，而更小的阶乘都不行：1!, 2!, 3!, 4! 分别是 1, 2, 6, 24，没有一个能被 30 整除）
K = 280 → N = 7（7! = 5040 = 280 × 18）
K = 123456789011 → N = 123456789011（答案正好等于 K 本身！）

为什么不能就从 N = 1, 2, 3, … 一个个试

看看第三个样例：答案可以大到 K 本身那么大，最多 1012。真要去算这么大的 N 的阶乘——哪怕只是一步一步乘上去——完全没有希望。一万亿次乘法，每次都是几百位数字的运算，无论如何也来不及算完。我们需要一种能直接跳到答案的办法。

第二关

把"能被 K 整除"变成一个关于质数的问题

这里是打开整道题的关键想法。任何数字 K 都能唯一地分解成质数：K = p₁e₁ × p₂e₂ × \cdots × pₖeₖ。而 N! 是 K 的倍数，恰好当且仅当 N! 里含有至少 eⁱ 份每一个质数 pⁱ。

于是这道题就拆成了两个小得多的问题：

  • 把 K 分解成质数的幂。
  • 对分解结果里的每一个质数幂 pe，算出让它的阶乘含有至少 e 份 p 的最小 N。
为什么最后要取最大值，而不是求和

一旦我们知道了满足每一个单独质数需求所需的最小 N，那么同时满足所有质数需求的最小 N，就是这些单独答案中最大的那一个。这是因为 N! 里每一个质数的供应量只会随着 N 增大而增多——所以一旦 N 大到足够满足"最难伺候"的那个质数，其他所有质数的需求自然也早就已经满足了。

用样例 1 验证一下：K = 30 = 2 × 3 × 5。让阶乘含有一个 2 所需的最小 N 是 N=2；含有一个 3 是 N=3；含有一个 5 是 N=5。答案是 max(2, 3, 5) = 5——和题目答案完全一致。

第三关

数清 N! 里含有多少份质数 p —— Legendre 公式

我们需要一个快速的办法来回答："质数 p 在 N! 里一共出现了多少次？"不能只数 N 以内 p 的倍数个数——像 p² 这样的数字会贡献两份 p，而不是一份。把它们全部干净利落地数清楚（每一份额外贡献都不漏）的方法，就是 Legendre 公式：

⌊N/p⌋
+
⌊N/p²⌋
+
⌊N/p³⌋
+ …
exponent_in_factorial.py
def exponent_in_factorial(n, p):
    total = 0
    power = p
    while power <= n:
        total += n // power
        power *= p
    return total
这个公式之前见过吗？

这正是 阶乘末尾的爱 那篇里完整搭建（并讲解过）的工具，那里用它来数清 N! 在任意进制下末尾有多少个零。那一次，是给你 N，问某个质数在它的阶乘里出现了多少次。这一次，我们要用同一个函数，去回答一个方向完全相反的问题。

第四关

用二分查找把公式反过来用

Legendre 公式回答的是"给定 N，有多少份 p？"我们需要反过来："如果需要至少 e 份 p，最小的 N 是多少？"这里有一个关键事实，让这一切变得简单：随着 N 增大，Legendre 公式算出来的数量永远不会减少。更大的阶乘只会拥有更多份 p，绝不会更少。

N=3

份数只增不减

每当一个量随着候选值增大而只增不减（或者保持不变），二分查找就是找出那个精确临界点——也就是份数第一次达到目标 e 时最小的 N——的完美工具。不需要把 N = 1, 2, 3, \ldots 一个个试过去，二分查找只需要大约 log₂(N) 次猜测就能找到它。

到底要从哪里开始搜索？

我们需要一个确定够大的上界。这里有一个简单的办法：Legendre 公式的第一项本身，⌊N/p⌋，一旦 N = p × e 就已经达到了 e（因为 ⌊(p×e)/p⌋ = e 正好整除）。所以 N = p × e 保证足够大，可以作为搜索的上界——我们永远不需要猜比这更大的数字。

min_n_for_prime_power.py
def min_n_for_prime_power(p, e):
    lo, hi = 1, p * e  # floor((p*e)/p) = e 恰好成立，所以 hi 永远足够大
    while lo < hi:
        mid = (lo + hi) // 2
        if exponent_in_factorial(mid, p) >= e:
            hi = mid
        else:
            lo = mid + 1
    return lo
第五关

足够快地分解 K

最后一个要用到的工具：先把 K 分解成质数的幂。因为 K ≤ 1012，质因数分解 那篇里同样的 √K 试除法捷径就能胜任——把候选除数一路测试到 √K（大约一百万，因为 √(1012) = 106），每个候选彻底除干净再往下走。

factorize.py
def factorize(k):
    factors = {}
    d = 2
    while d * d <= k:
        while k % d == 0:
            factors[d] = factors.get(d, 0) + 1
            k //= d
        d += 1
    if k > 1:
        factors[k] = factors.get(k, 0) + 1
    return factors

为什么样例 2 的答案正好等于 K 本身

123456789011 碰巧是一个质数——所以它自己的分解就是它本身的一次方。让阶乘含有哪怕一份这个庞大质数的最小 N，就是这个质数本身（比质数 p 小的数字，乘出来的阶乘绝不可能被 p 整除，所以 p 不可能在 N 到达 p 之前出现在任何阶乘里）。这正是答案能大到 K 那么大的原因——也正是暴力计算阶乘从一开始就注定行不通的原因。

第二关的洞察：先单独找出满足每个质数需求的最小 N，再取其中最大的那个——这一个值自动就能同时满足所有质数的需求。

完整程序如下：

abc280d.py
def factorize(k):
    factors = {}
    d = 2
    while d * d <= k:
        while k % d == 0:
            factors[d] = factors.get(d, 0) + 1
            k //= d
        d += 1
    if k > 1:
        factors[k] = factors.get(k, 0) + 1
    return factors

def exponent_in_factorial(n, p):
    total = 0
    power = p
    while power <= n:
        total += n // power
        power *= p
    return total

def min_n_for_prime_power(p, e):
    lo, hi = 1, p * e
    while lo < hi:
        mid = (lo + hi) // 2
        if exponent_in_factorial(mid, p) >= e:
            hi = mid
        else:
            lo = mid + 1
    return lo

def solve(k):
    factors = factorize(k)
    return max(
        min_n_for_prime_power(p, e)
        for p, e in factors.items()
    )

k = int(input())
print(solve(k))

第九关

轮到你练习了

先用纸笔自己算一遍，再用上面的工具检查答案。

练习 1：手动算出让 N! 是 K = 100 的倍数的最小 N。

100 = 2² × 5²。含有两份 2 的最小 N：N=4 给出 ⌊4/2⌋+⌊4/4⌋=3，已经够了（N=3 只给出 1 份，所以需要 N=4，因为我们需要至少 2 份，而 N=4 恰好给出 3 份，N=3 只给出 1 份——所以最小的就是 N=4）。含有两份 5 的最小 N：需要 ⌊N/5⌋+⌊N/25⌋ ≥ 2，第一次达到是在 N=10（⌊10/5⌋=2）。答案：max(4, 10) = 10。验证：10! = 3628800 = 100 × 36288。✓

练习 2：为什么质数幂 p² 所需的最小 N，有时会比 2p 大不少？

因为第一个 p 的倍数（贡献一份）出现之后，下一份并不一定紧跟着来自下一个数字——它来自 p 的第二个倍数，也就是 2p。所以要凑够两份 p，通常需要 N 达到 2p，而不只是比 p 多一点点。指数更大时，这种"摊开"的效应会累积起来，这正是为什么需要用 Legendre 公式（对 p 的每一个幂求和），而不能靠简单猜测。

练习 3：为什么二分查找可以放心地用 hi = p × e 作为初始上界，不管 e 有多大？

Legendre 公式的第一项本身就是 ⌊N/p⌋，其他每一项只会往上加。当 N = p × e 时，这第一项恰好等于 e（因为 p × e 能被 p 整除）。所以在 N = p × e 处，总份数自动至少是 e，不管 e 变得多大——这就保证了真正的答案永远不会比这个初始上界更大。

练习 4（较难）：如果 K 是某个质数的平方，比如 K = p²，答案是不是永远恰好是 2p？

不一定——这取决于 p。对小一点的 p 来说，在 N 到达 2p 之前，额外的 p 份数就可能"免费"提前出现。以 p=2 为例：对 K=4=2²，我们需要 N! 里至少有 2 份 2。在 N=4 时，Legendre 公式给出 ⌊4/2⌋+⌊4/4⌋=2+1=3——已经满足，而 N=3（⌊3/2⌋=1）还不够，所以真正的最小 N 是 4，这里恰好等于 2p。但再试试 p=2, e=3（K=8）：N=4 恰好给出 3 份（正如上面算过的），这已经是最小的 N 了——比某些"2×p×(e/2)"式的猜测公式给出的结果要小。真正的答案总是需要跑一遍 Legendre 公式（或二分查找）才能确定；不存在一个能跳过这一步的通用捷径公式，这正是第四关的二分查找方法之所以可靠的原因。

练习 5：修改 Python 代码，让它不只返回最终答案，还打印出 K 的每一个质因数各自单独需要的最小 N——方便看清到底是哪个质数成了瓶颈。
abc280d_debug.py
def solve_debug(k):
    factors = factorize(k)
    best = 0
    for p, e in factors.items():
        n = min_n_for_prime_power(p, e)
        print(f"prime {p}^{e} needs N >= {n}")
        if n > best:
            best = n
    return best
