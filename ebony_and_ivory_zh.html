Codeforces 1036A · 题目精讲

埃博尼和艾沃丽：刚好打出这个数字

但丁有两把枪，埃博尼（Ebony）和艾沃丽（Ivory）。每一发埃博尼子弹造成 a 点伤害，每一发艾沃丽子弹造成 b 点伤害。Codeforces 1036A 问的是：他能不能打出一套子弹组合，正好造成 c 点伤害？我们一发一发地把答案找出来。

不需要数学基础 简单搜索 可以互动
第一关

任务目标

但丁正面对"救世主"的护盾，只有正好造成 c 点伤害才能击破它——多一点不行，少一点也不行。他有两把枪：埃博尼每发子弹造成 a 点伤害，艾沃丽每发子弹造成 b 点伤害。两把枪各自可以开任意数量的子弹，包括 0 发。

换句话说：能不能找到两个非负整数 x（埃博尼的子弹数）和 y（艾沃丽的子弹数），使得 a × x + b × y = c？

题目原样给出的例子

a=4, b=6, c=15 → No（没有任何组合能凑出来）。
a=3, b=2, c=7 → Yes（1 发埃博尼 + 2 发艾沃丽：1×3 + 2×2 = 7）。
a=6, b=11, c=6 → Yes（1 发埃博尼 + 0 发艾沃丽：1×6 + 0×11 = 6）。

这跟你有什么关系？

c 最大可以到 10,000。瞎猜子弹组合、指望撞上答案可不是办法——那是在赌运气。我们需要一种搜索方式，既能保证检查到所有真正可能有用的组合，又不会多做无用功。

第二关

这其实是个"凑钱"游戏

把恶魔猎人的外壳剥掉，底下藏着的问题是：只用 3 元和 2 元的纸币，能不能刚好凑出 7 元？这正是样例二（a=3, b=2, c=7）——答案是可以，1 张 3 元加 2 张 2 元正好。

有些总数能凑出来，有些不行。只用 3 元和 2 元，能凑出 1 元吗？不行——所有组合只能是 0、2、3、4、5、6……1 永远凑不出来。这正是这道题在问的"到底行不行"，只是换了一层恶魔护盾的外壳。

冷知识档案

这种"只用两种面额，能凑出哪些总数"的问题，有个外号叫炸鸡块问题，因为麦当劳曾经卖过 6 块、9 块、20 块一盒的炸鸡块，数学家们立刻开始琢磨：哪些数量的炸鸡块是永远点不出来的？（冷知识：如果只有 6 块装和 9 块装，你永远点不出正好 43 块。）

第三关

为什么不能挨个试遍每一对 (x, y)？

最直接的办法：把 x 从 0 试到 c，对每一个 x 再把 y 从 0 试到 c，检查 a×x + b×y 是不是正好等于 c。

这样做当然管用，但浪费太多。如果 a = b = 1、c = 10,000，就要检查大约 10,001 × 10,001 对组合——差不多 一亿次检查，而且只是一组测试数据而已。其实藏着一个小得多的搜索方式。

100,020,001
对 (x, y) 组合，用暴力法把每一种可能都试一遍
10,001
个 x 值，用你即将学到的更聪明的搜索方式
第四关

关键洞察：只猜 x，用公式算出 y

其实根本不用去猜 y——一旦选定了 x，方程 a×x + b×y = c 就已经把 y 该是多少算得明明白白：

y = (c − a×x) / b

所以对每一个 x，真正要问的问题只有一个：这个除法能不能除尽（没有余数），而且结果是不是 ≥ 0？如果是，答案就找到了。如果不是，换下一个 x 再试。

选
x = 0, 1, 2…
→求解
检查
(c − a×x) % b == 0？

因为 a ≥ 1，x 的取值范围永远只在 0 到 c ÷ a 之间——最多试 c+1 个值，仅此而已。

全篇最重要的一句话

把一个"猜两个数"的游戏变成"猜一个数、算出另一个数"的游戏，就是整个诀窍——这也是竞赛编程里会反复出现的招式：固定一个变量，推出剩下的。

额外洞察

这里有个技巧，甚至能让你在开始循环之前就省下时间：如果 c 不是 gcd(a, b) 的倍数，答案立刻就是 No——不管怎么组合 a 和 b，都凑不出 c。（好奇这是为什么？最大公约数那一页正好深入讲了这个问题。）比如 gcd(4, 6) = 2，而 15 不是 2 的倍数——所以样例一在我们检查任何一个 x 之前，就已经注定是 No 了。

第五关

逐行读代码

下面就是完整的解法。不用一下子全懂——先看左边的代码，再看右边的大白话翻译。

ebony_and_ivory.py
a, b, c = map(int, input().split())

possible = False
x = 0
while a * x <= c:
    remainder = c - a * x
    if remainder % b == 0:
        possible = True
        break
    x += 1

print("Yes" if possible else "No")

第六关

一起手把手推演一遍：a=4, b=6, c=15

光说不练假把式——用样例一亲手把代码走一遍，这次答案会是 No。留意循环在 a×x 即将超过 15 的那一刻停下来。

x = 4 会让 a×x = 16 > 15，所以循环到此停止。没有一个 x 成立 → 答案是 No

这次只需要检查 4 个 x 值——远远比不上第三关里那个大约 15×15 的暴力网格。再想想第四关的"额外洞察"：gcd(4, 6) = 2，而 15 不是 2 的倍数，所以其实我们什么都不用检查，就能提前猜到答案是 No。

第八关

课后挑战（先自己试，别偷看答案）

在用上面的工具验证之前，先自己在纸上把这个搜索试一遍。

挑战一：a=5, b=3 能不能刚好打出 c=11 点伤害？找出 x 和 y。

x=0：余数 11，11 % 3 = 2，不行。x=1：余数 6，6 % 3 = 0，可以！所以 y = 6 / 3 = 2。验证一下：5×1 + 3×2 = 5 + 6 = 11。答案是 Yes，1 发埃博尼加 2 发艾沃丽。

挑战二：样例三说 a=6, b=11, c=6 的答案是 Yes。为什么搜索第一次就能找到？

x=0：余数是 6，6 % 11 = 6——除不尽，所以 x=0（也就是 0 发埃博尼）不行。x=1：a×x = 6，余数 = 6 − 6 = 0，0 % 11 = 0——除尽了！所以 y = 0。一发埃博尼就能搞定全部，一发艾沃丽都不需要。循环只试了 2 次。

挑战三：为什么只搜索 x 就够了，完全不用单独去搜索 y？

因为一旦 a、c 和选定的 x 固定下来，方程 a×x + b×y = c 就只剩下唯一一个可能的 y：y = (c − a×x) / b。已经没什么好猜的了——这个值要么是非负整数，要么不是。单独再去搜索 y，只是在把同一个数字重新算一遍，没有任何好处。

挑战四：评测系统只要"Yes"/"No"。你能不能把代码改一下，答案是 Yes 时也把找到的 x 和 y 打印出来？
ebony_and_ivory_pair.py
a, b, c = map(int, input().split())

x = 0
while a * x <= c:
    remainder = c - a * x
    if remainder % b == 0:
        y = remainder // b
        print("Yes", x, y)
        break
    x += 1
else:
    print("No")
