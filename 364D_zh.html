Codeforces 364D · 题目精讲

Ghd：只需要一半数字认账的那个约数

你已经认识 GCD 了——那个能整除列表里每一个数字的最大公约数。Ghd 把规则放宽了一点：它只需要整除列表里至少一半的数字就够了。就是这么一个小小的改动，把一道简单题变成了真正的难题——最多一百万个数字，每个都可能大到一万亿，而你只有 4 秒钟。破解它的关键，是一次掷硬币。

不需要数学基础 随机化算法与 GCD 可以互动
第一关

任务目标，原样来自题目

给你 n 个数字（1 ≤ n ≤ 106），每个都在 1 到 1012 之间。你需要找到最大的数字 g，使得列表里至少一半的数字都能被 g 整除。这个特殊的值叫做 Ghd（"greatest half-divisor"，"最大半数公约数"）。

题目原样给出的例子

6 2 3 4 5 6 → 3（3 能整除 6、3、6——6 个数字里有 3 个，正好一半）
5 5 6 10 15 → 5（5 能整除 5、5、10、15——5 个数字里有 4 个，超过一半）

还不熟悉 GCD？

这篇文章默认你已经知道最大公约数（GCD）是什么——能整除一组数字里每一个数的最大数字。如果这对你来说还是新概念，Modified GCD 和 Maximum GCD 这两篇是很好的热身。Ghd 这个名字故意起得跟 GCD很像，因为它本质上是同一个想法，只是把规则放宽了。

第二关

Ghd 和 GCD：为什么"一半"会改变一切

6, 2, 3, 4, 5, 6 这组数字的普通 GCD 只有 1——没有比 1 更大的数能同时整除这全部六个数字（光是 5 这一个数，就会把任何比 1 大的候选值全部否决，因为没有别的数跟它共享因数）。但 Ghd 不需要所有人都同意——它只需要多数票。这正是为什么答案能一下子跳到 3：六个数字里有三个（6、3、6）都愿意被 3 整除，而六选三正好够格。

先看看暴力做法，把我们到底要算什么明确下来：

ghd_brute_force.py
n = int(input())
a = list(map(int, input().split()))
need = (n + 1) // 2  # "至少一半"，向上取整

best = 1
for g in range(1, max(a) + 1):
    count = sum(1 for v in a if v % g == 0)
    if count >= need:
        best = g

print(best)

这段代码百分之百正确——但面对真实的数据规模，也百分之百没有希望跑完。max(a) 可以达到 1012，而每测试一个候选 g，都要扫一遍多达一百万个数字。总共大约是 1012 × 106 = 1018 次操作。就算一台电脑每秒能做十亿次操作，也得算上几十年。

真正的挑战

我们需要在不测试"每一个可能的 g"的前提下找到答案。既要聪明地缩小候选范围，又要有办法飞快地检验每一个候选。

第三关

技巧一：随便一猜，命中率高得惊人

这是让整道题变得可解的火花。假设 g 就是真正的 Ghd。根据定义，数组里至少一半的数字都是 g 的倍数。现在闭上眼睛，随便指向数组里的一个数字。你指中 g 的倍数的概率是多少？

≥ 50%

至少五五开——跟抛一枚均匀硬币出正面的概率一样！而如果你随手挑中的数字 x 正好是 g 的倍数，那么 g 自动就是 x 的一个约数（能整除某个 g 的倍数、并且恰好等于 g 本身的数字，当然就是那个倍数的约数）。所以：随便挑一个数字，看看它有哪些约数，真正的答案有一半的概率就藏在这份约数清单里。

为什么反复"掷硬币"基本能保证成功

抛一次硬币只有 50% 的概率抛中想要的那面，这还不够保险。但如果你抛 20 枚独立的硬币，只要其中一枚抛对了就行呢？全部 20 枚都抛错的概率是 (1/2)20——大约百万分之一。所以：从数组里随机挑出 20 个不同的数字（而不是只挑 1 个），把它们各自的约数都收集起来，逐一检验这些候选值。真正的 Ghd 一个都没出现在这些候选里的概率，小到几乎可以忽略不计。

之前见过类似的随机化技巧吗？

这种"反复随机猜测，直到失败的概率小到可以忽略"的策略，在竞赛编程里随处可见——GCD 逃脱机 和 生日悖论 这两篇用的是相关的概率推理，如果你想多练习一下这种思维方式，可以去看看。

第四关

技巧二：列出一个数字的约数很便宜

第三关把我们的搜索范围，从"一万亿以内的每一个整数"缩小到了"一个特定数字的约数"。一个不超过 1012 的数字，最多能有多少个约数呢？就算是最极端的情况，也不过几千个——相对于一万亿来说，简直微不足道。

divisors_of.py
def divisors_of(x):
    result = []
    d = 1
    while d * d <= x:
        if x % d == 0:
            result.append(d)
            if d != x // d:
                result.append(x // d)
        d += 1
    return result

这就是 质因数分解 那篇里用过的 √x 捷径：约数总是成对出现的，形如 (d, x/d)，所以只需要测试到 √x 为止。当 x = 1012 时，√x 只有 106——这样一个循环，一瞬间就能跑完。

第五关

技巧三：用 GCD 指纹快速计数

现在我们从一个抽样数字 x 那里，得到了大概几千个候选约数。对每一个候选 d，我们都需要知道：整个数组里有多少个数字能被 d 整除？最直接的办法——每个候选都把整个数组扫一遍——总花费是 (x 的约数个数) × n，一旦对 20 个不同的抽样数字都这么做，还是会太慢。

这里有个修正办法：对每个抽样数字，只扫描数组一次，让 GCD 身兼两职。对数组里的每一个数字 v，计算 gcd(x, v)。这个值永远满足两件事：

gcd(x, v)
永远是 x 的一个约数

这正是 GCD 的定义——它同时整除 x 和 v。所以在扫描数组的同时，我们可以把每个 v 直接丢进一个"格子"里，这个格子的标签就是它落在的那个 x 的约数，用一个字典记录每个格子里落了多少个数字。扫一遍整个数组，每个数字就都被分类进了 x 的某个约数格子里。

把格子变成"有多少个数能被 d 整除"

光落在恰好等于 d 的格子里，还不是全部故事——如果 v 落在标签为 10 的格子里，那么 v 也同时能被 5、2、1（10 的每一个约数）整除。所以要算出数组里有多少个数能被某个候选 d 整除，只需要把 d 以及所有同时是 x 约数的 d 的倍数对应的格子数量加起来。因为我们只是在 x 自己那份（不大的）约数清单里求和，这一步依然很快。

为什么这样做完全正确

取 x 的任意一个约数 d，以及数组里任意一个数字 v，它的格子标签是 d2 = gcd(x, v)。如果 d 整除 d2，那么由于 d2 整除 v（根据 gcd 的定义），d 也就整除 v。反过来也成立：如果 d 同时整除 x 和 v，那么 d 必定整除 gcd(x,v) = d2，因为 gcd 是最大的公约数，任何一个公约数都能整除它。所以"d 整除 v"和"d 整除 v 的格子标签"其实是同一件事——不会漏掉，也不会错误地重复计数。

第六关

把三个技巧拼在一起

综合第三到第五关，完整的方案是这样的：

  • 重复大约 20 次：从数组里随机挑一个数字 x（第三关）。
  • 用 √x 捷径列出 x 的所有约数（第四关）。
  • 扫一遍数组，按 gcd(x, v) 把每个数字分进格子（第五关）。
  • 从大到小检查 x 的约数，对每一个都累加它的倍数们的格子数量。第一个达到"至少一半数组"的，就是藏在这个特定 x 里的最佳候选。
  • 在全部 20 次随机抽样里找到的候选中，保留最大的那个——它就是答案。
为什么这样能赶在时限内完成

大约 20 次尝试，每一次都对数组做一遍 O(n) 的扫描（给每个元素算一次 gcd——即便面对 12 位数字，gcd 也只需要几步就能算完），再加上一次只针对 x 自己那份约数清单的小小整理。对一百万个数字扫 20 遍，每次的算术都很便宜，4 秒钟绰绰有余——和第二关那 1018 次操作的暴力法完全不是一个量级。

下面是可以直接运行的完整程序：

ghd.py
import math
import random

def divisors_of(x):
    result = []
    d = 1
    while d * d <= x:
        if x % d == 0:
            result.append(d)
            if d != x // d:
                result.append(x // d)
        d += 1
    return result

def ghd(a, trials=20):
    n = len(a)
    need = (n + 1) // 2
    best = 1

    sample_size = min(trials, n)
    for x in random.sample(a, sample_size):
        divs = divisors_of(x)
        count = {d: 0 for d in divs}
        for v in a:
            g = math.gcd(x, v)
            count[g] += 1

        for d in sorted(divs, reverse=True):
            if d <= best:
                break
            total = sum(count[d2] for d2 in divs if d2 % d == 0)
            if total >= need:
                best = d
                break

    return best

n = int(input())
a = list(map(int, input().split()))
print(ghd(a))

一找到就立刻停止——3 就是藏在 x=6 里的最佳候选。如果随机抽到的是别的数字（2、3、4、5，或另一个 6），要么会重新发现 3，要么找到的不会比它更大，所以只要试的次数够多，最终答案始终是 3——和题目给出的答案完全一致。

第十关

轮到你练习了

先用纸笔自己算一遍，再用上面的工具检查答案。

练习 1：手动算出 8, 12, 18, 25 的 Ghd。

n=4，所以需要至少 2 个数字共享某个约数。试试 g=6：能整除 12 和 18（2 个数字）——成立！再试更大的：g=8 只能整除 8（1 个，不够）。g=9 只能整除 18。g=12 只能整除 12。所以没有比 6 更大的候选能达到 2 个数字。答案：6。

练习 2：为什么算法需要检查抽样数字的约数，而不是直接检查抽样数字 x 本身？

因为 x 本身很可能不是答案——真正的 Ghd 可能是一个更小的数，而 x 碰巧是它的倍数。举例来说，如果 x = 12，而真正的 Ghd 是 6，那么 6 是 12 的一个约数，但 12 本身可能整除不了"至少一半"的数组。我们必须搜遍 x 的全部约数，才能找到真正满足"至少一半"规则的那个最大值。

练习 3：在上面的工具里把试验次数设成 1，对数组 9, 9, 9, 2, 3 多跑几次。你有时会得到一个错误（偏小）的答案，而不是真正的 Ghd。解释一下为什么，并说出真正的 Ghd 是多少。

n=5，需要 ≥ 3。五个数字里有三个（三个 9）能被 9 整除，所以真正的 Ghd 是 9。但如果只做 1 次随机试验，有 2/5（40%）的概率会抽到 2 或 3 而不是 9——如果抽到 x=2，它的约数只有 1 和 2，而 2 只能整除一个数字（它自己），算法就会错误地报告 1。这正是第三关坚持要做大约 20 次试验的原因：一次不走运的抽样就可能完全错过答案，但连续 20 次都不走运的概率，小到几乎不可能发生。

练习 4（较难）：只用 GCD 的定义——不借助任何公式——解释为什么 gcd(x, v) 一定能整除 x。

根据定义，gcd(x, v) 是同时整除 x 和 v 的最大数字。"同时整除 x 和 v"这个要求本身就已经包含了"整除 x"——所以不管 gcd(x,v) 最终算出来是多少，它都必须整除 x，因为这本来就是它一开始就必须满足的条件之一。

练习 5：修改 Python 代码，让它不再只找到第一个满足"至少一半"的 x 的约数就停下，而是把 x 的每一个约数、以及它能整除数组里多少个数字都打印出来——方便手动检查格子逻辑是否正确。
ghd_debug.py
def show_all_counts(a, x):
    divs = divisors_of(x)
    count = {d: 0 for d in divs}
    for v in a:
        count[math.gcd(x, v)] += 1

    for d in sorted(divs, reverse=True):
        total = sum(count[d2] for d2 in divs if d2 % d == 0)
        print(f"d={d}: {total} numbers divisible by it")

和之前一样的格子搭建过程，只是去掉了提前退出——把 x 每一个约数当前的累计总数都打印出来，而不是一找到就停。
