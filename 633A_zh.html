Codeforces 633A · 题目精讲

埃博尼和艾沃丽：搭出刚好那么高的塔

但丁有两把枪，埃博尼（Ebony）和艾沃丽（Ivory）。每一发埃博尼子弹造成 a 点伤害，每一发艾沃丽子弹造成 b 点伤害，他需要打出正好 c 点伤害——多一点不行，少一点也不行。这次我们不瞎猜，而是像搭积木一样，一步步把答案搭出来。

不需要数学基础 循环与余数 可以互动
第一关

任务目标，原样来自题目

但丁站在一面需要击破的护盾前。他用两把枪开火——埃博尼每发子弹造成 a 点伤害，艾沃丽每发子弹造成 b 点伤害——两把枪各自可以开任意数量的子弹，包括 0 发。护盾只有在总伤害正好等于 c 时才会破碎。

所以真正要问的问题是：能不能找到两个非负整数 x（埃博尼的子弹数）和 y（艾沃丽的子弹数），使得 a × x + b × y = c？

题目原样给出的例子

a=4, b=6, c=15 → No——没有任何组合能凑出来。
a=3, b=2, c=7 → Yes——1 发埃博尼 + 2 发艾沃丽：1×3 + 2×2 = 7。
a=6, b=11, c=6 → Yes——1 发埃博尼 + 0 发艾沃丽：1×6 + 0×11 = 6。

为什么不能瞎猜？

c 最大可以到 10,000，而 a 和 b 最小可能只有 1。随便试子弹组合、指望撞上正好等于 c 的答案，那是在赌运气，不是解法。我们需要一种搜索方式：只要答案存在，就一定能找到；答案不存在，也能确定地说"不行"。

第二关

先把枪放一边——想想搭积木

把恶魔猎人的外壳完全剥掉，剩下的题目是这样的：你有无数块红色积木，每块 a 格高；还有无数块蓝色积木，每块 b 格高。能不能各拿一些（也可以某种颜色一块都不用），刚好搭出高度为 c 的一座塔？

先在脑子里用红色 = 3 格、蓝色 = 2 格试试。能搭出高度 1 吗？没有一块积木这么矮，也不能用负数块，所以 1 永远搭不出来。能搭出高度 4 吗？可以——两块蓝色。高度 5 呢？一块红色加一块蓝色。高度 7 呢？一块红色加两块蓝色，这正是上面的样例二。

一个值得注意的规律

红色 = 3、蓝色 = 2 时，唯一永远搭不出来的高度就是 1。从 2 往上的每一个高度都能想办法搭出来。不过不是每一对积木尺寸都这么"大方"——第六关你会看到一对积木，会留下永远填不上的空洞。

第三关

笨办法：把每一对组合都试一遍

最直接的办法：把红色积木数 x 从 0 试到 c，对每一个 x 再把蓝色积木数 y 从 0 试到 c，检查 a×x + b×y 是不是正好等于 c。

这个办法确实管用，但是很浪费。如果 a = b = 1、c = 10,000，大约要检查 10,001 × 10,001 对组合——差不多一亿次，而且只是一组测试数据。我们能做得比这好得多。

第四关

诀窍：只猜红色积木，蓝色积木用算的

其实完全不用去猜 y。一旦选定了要用多少块红色积木（x），方程 a×x + b×y = c 就已经把需要多少块蓝色积木算得明明白白：

y = (c − a×x) / b

所以对每一个 x，只需要检查一件事：这个除法能不能除尽（没有余数），而且结果是不是一个 ≥ 0 的整数？如果是，答案就找到了；如果不是，换下一个 x 再试。

选
x = 0, 1, 2…
→推算
检查
(c − a×x) % b == 0？

因为 a ≥ 1，x 的取值范围永远只在 0 到 c ÷ a 之间——不管 b 多大，最多也只用试 c+1 个值。

全篇最重要的一句话

把一个"猜两个数"的游戏，变成"猜一个数、算出另一个数"的游戏，就是整个诀窍。等你多做几道类似的题，就会发现固定一个变量，推出剩下的这一招会反反复复出现。

额外的捷径（不是必须，但很好用）

在开始循环之前，还有一件事可以先检查：如果 c 不是 gcd(a, b) 的倍数，答案立刻就是 No——不管怎么组合 a 和 b，都永远凑不出 c。比如 gcd(4, 6) = 2，而 15 不是 2 的倍数，所以样例一在我们检查任何一个 x 之前，就已经注定是 No 了。好奇这条规律为什么总是成立？最大公约数那一页深入讲了 gcd 的这一面。

第五关

用 Python 把它写出来

下面是把第四关的想法用 for 循环写出来的一种干净写法。先看左边的代码，再看右边的大白话注解。

tower_height.py
a, b, c = map(int, input().split())

found = False
for x in range(c // a + 1):
    remainder = c - a * x
    if remainder % b == 0:
        found = True
        break

print("Yes" if found else "No")
found = False
先假设不行，除非之后被推翻。
for x in range(c // a + 1):
把红色积木数从 0 试到 c // a（整数除法）。再往上，光是 a×x 就已经超过 c 了。
remainder = c - a * x if remainder % b == 0:
这是单靠蓝色积木还需要补上的高度。如果能被 b 整除，就说明找到了一个可行的 y。
found = True break
成功了——不用再试更多的 x。
加餐：同样的逻辑写成一行

等这个想法真正想明白之后，可以用 Python 的 any() 把整个搜索写成一个表达式：

tower_height_oneline.py
a, b, c = map(int, input().split())
ok = any((c - a * x) % b == 0 for x in range(c // a + 1))
print("Yes" if ok else "No")

any(...) 会检查一整串"对/错"的条件，只要有一个是对的，就立刻返回 True——这正好就是上面那个循环"一找到可行的 x 就停下"的行为，只是写得更紧凑。

第八关

该你练习了

先自己在纸上把答案算出来，再用上面的工具验证。

挑战一：a=5, b=7 能不能刚好搭出高度 c=24 的塔？找出 x 和 y。

x=0：余数 24，24 % 7 = 3，不行。x=1：余数 19，19 % 7 = 5，不行。x=2：余数 14，14 % 7 = 0，可以！所以 y = 14 / 7 = 2。验证一下：5×2 + 7×2 = 10 + 14 = 24。答案：Yes，2 块红色积木加 2 块蓝色积木。

挑战二：不检查任何一个 x，能不能直接判断 a=4, b=6, c=13 行不行？

能，用第四关的 gcd 捷径：gcd(4, 6) = 2。用 4 和 6 搭出来的塔一定是 2 的倍数，因为这两种积木本身都是偶数。但 13 是奇数——不是 2 的倍数——所以答案立刻就是 No，根本不用跑循环。

挑战三：为什么只搜索 x 就够了，完全不用单独去搜索 y？

因为一旦 a、c 和选定的 x 固定下来，方程 a×x + b×y = c 就只剩下唯一一个可能的 y：y = (c − a×x) / b。已经没什么好猜的了——这个值要么是非负整数，要么不是。单独再去搜索 y，只是在把同一个数字重新算一遍。

挑战四：评测系统只要"Yes"/"No"。你能不能把代码改一下，答案是 Yes 时也把找到的 x 和 y 打印出来？
tower_height_pair.py
a, b, c = map(int, input().split())

for x in range(c // a + 1):
    remainder = c - a * x
    if remainder % b == 0:
        y = remainder // b
        print("Yes", x, y)
        break
else:
    print("No")

这里的 for 循环带了一个 else——它只会在循环从头到尾都没有触发 break 时才执行，正好用来回答"到底是找到了，还是找遍了都没找到"这个问题，是 Python 一个很好用的小特性。

挑战五（较难）：对 a=6, b=9 来说，永远搭不出来的最大高度是多少？

这是个陷阱题——根本没有"最大搭不出来的高度"！因为 gcd(6, 9) = 3，用这两种积木搭出来的塔永远是 3 的倍数，任何不是 3 的倍数的高度（比如 1、2、4、5、7、8、10……）不管塔多高，都永远搭不出来。"最大搭不出来的高度"这个说法（也就是炸鸡块问题 / Frobenius 数）只有在 gcd(a, b) = 1 时才成立——否则会有无穷多个高度永远够不到。
