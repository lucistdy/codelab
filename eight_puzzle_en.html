The Sliding Tile Escape Room: Solving the 8 Puzzle with BFS

Eight numbered tiles, one empty hole, and a single rule: you may only slide a tile into the hole. Can you put the tiles back in order? And can you do it in the fewest possible moves? We'll play the puzzle, teach Python to solve every board instantly, catch the bugs in a sample solution, and discover a secret that makes half of all boards impossible.

LEVEL 1

Meet the puzzle

Imagine you're locked in an escape room. The door has a 3×3 panel of sliding tiles, numbered 1 to 8, with one empty square. The door opens only when the tiles read 1 2 3 / 4 5 6 / 7 8, with the hole in the bottom-right corner.

Try it yourself. Click any tile next to the hole to slide it in. Tiles with a dashed outline can move. Green tiles are already in their home square.

🧩 The escape-room door

Press Shuffle for a fresh puzzle. It is mixed up using only legal slides, so it can always be solved.
A puzzle that drove the world crazy

The 8 puzzle is the little brother of the 15 puzzle (4×4, fifteen tiles). In 1880 the 15 puzzle became a worldwide craze: people played it at home, at work and on trains. The famous puzzle writer Sam Loyd later claimed he had offered a $1,000 prize for one particular board. Nobody ever won it, and in Level 7 you'll find out why nobody could.

Playing by hand, you probably solved it in 30, 50, maybe 100 moves. But what is the shortest solution? Guessing won't tell us. We need a system, and that's what computer science is for.

Moving the hole

Here's a clever change of view: instead of thinking "a tile slides into the hole", think "the hole moves" and swaps places with a neighbour. Then there are only four possible moves, and each one just adds a number to the hole's position:

the hole moves…letterposition changenot allowed when…
upu−3it's in the top row (pos − 3 < 0)
downd+3it's in the bottom row (pos + 3 > 8)
leftl−1it's in the left column (pos % 3 == 0)
rightr+1it's in the right column (pos % 3 == 2)
The wrap-around trap

Up and down are easy to check: if the new position is below 0 or above 8, you fell off the board. Left and right are sneaky. If the hole is at position 3 (start of the middle row), then 3 − 1 = 2 is a perfectly valid number, but position 2 is the end of the top row! The hole would teleport around the edge. That's why we need the extra pos % 3 checks.

neighbours.py
MOVES = [(-3, "u"), (3, "d"), (-1, "l"), (1, "r")]   # (position change, letter)

def neighbours(state):
    pos = state.index("x")
    result = []
    for offset, letter in MOVES:
        npos = pos + offset
        if npos < 0 or npos >= 9:            # fell off the top or the bottom
            continue
        if offset == -1 and pos % 3 == 0:    # left column: can't go left
            continue
        if offset == 1 and pos % 3 == 2:     # right column: can't go right
            continue
        cells = list(state)                  # strings can't change, lists can
        cells[pos], cells[npos] = cells[npos], cells[pos]   # swap hole and tile
        result.append((letter, "".join(cells)))
    return result

for letter, s in neighbours("23415x768"):
    print(letter, s)
# u 23x154768
# d 23415876x
# l 2341x5768
LEVEL 3

A map of every possible board

Now picture a giant map. Every possible board is a dot on the map, and two dots are joined by a line if one slide turns one board into the other. Mathematicians call this kind of map a graph: the dots are states, the lines are moves.

Solving the puzzle means: find a route on this map from your board to the goal board 12345678x. The shortest solution is the route with the fewest lines.

9! = 362,880
ways to arrange 8 tiles and a hole on 9 squares
2 to 4
moves from each board (hole in a corner: 2, on an edge: 3, in the centre: 4)

That's far too many boards to explore by trial and error. If we just wander around randomly, we might walk in circles forever. We need a search that is organised, never visits a board twice, and is guaranteed to find the shortest route. Meet BFS.

LEVEL 4

BFS: the ripple in a pond

Drop a stone into a pond. A ring of ripples spreads out: first everything 1 step away, then everything 2 steps away, then 3… Breadth-first search (BFS) explores the map in exactly the same way.

Tool 1
A queue
A waiting line: boards join at the back and leave from the front. First in, first out, like a lunch queue.
Tool 2
A "seen" record
A dictionary of every board we've already found, so we never explore the same one twice.
The loop
Take, expand, add
Take the board at the front, find its neighbours, and add every new one to the back of the queue.

Because the queue is first-in-first-out, all boards at distance 1 are handled before any board at distance 2, and so on. So the first time BFS reaches a board, it got there by a shortest route. That's the whole magic.

Here's how the ripples grow when we start from the goal board:

ring (moves away)012345…24…3031
number of boards12481620…24,047…2212

The biggest ring is 24 moves away, and the very last ring, at 31 moves, has only 2 boards. These are the hardest 8 puzzles in the world. You'll find them in practice problem 6.

Let's write BFS. Along with "seen", we remember where each board came from (its parent and the move used), so at the end we can walk backwards from the goal and read off the route.

bfs_solve.py
from collections import deque

def bfs_solve(start, goal="12345678x"):
    parent = {start: None}                 # board -> (previous board, move letter)
    q = deque([start])                     # the waiting line
    while q:
        s = q.popleft()                    # take the board at the front
        if s == goal:
            break                          # reached the goal: stop searching
        for letter, t in neighbours(s):
            if t not in parent:            # a brand-new board?
                parent[t] = (s, letter)    # remember how we got here
                q.append(t)                # join the back of the line
    if goal not in parent:
        return None, len(parent)           # the goal was never reached
    path = ""
    s = goal
    while parent[s] is not None:           # walk back from goal to start
        s, letter = parent[s]
        path = letter + path               # put each move in front
    return path, len(parent)

print(bfs_solve("1234567x8"))   # ('r', 8)
print(bfs_solve("23415x768"))   # ('ullddrurdllurdruldr', 46289)
print(bfs_solve("21345678x"))   # (None, 181440)

Look at the second number in each answer: it's how many boards BFS had to discover. An easy board needs very few. A 19-move board needs about 46,000. And the last board? BFS searched 181,440 boards, and then gave up: that board can never be solved. Hold that thought for Level 7.

Read the answer

Each letter is the direction the hole moves. "r" for the board 1234567x8 means "the hole moves right", in other words tile 8 slides left. Done in one move!

LEVEL 5

The clever trick: search backwards, once

Suppose a contest gives us many boards to solve. Running a whole BFS for each board is slow, especially for unsolvable ones. Here is a smarter idea: every puzzle ends at the same goal. So let's do a single BFS that starts from the goal and spreads out to every reachable board.

Each slide can be undone (if the hole moved up, moving it down puts it back), so a route from the goal to a board, read backwards, is a route from that board to the goal. One BFS gives us a "phone book" of answers:

bfs_tree["12345678x"]
→ "" (already solved)
bfs_tree["12345x786"]
→ "d"
bfs_tree["23415x768"]
→ "ullddrurdllurrdlurd"

After building the book once, answering any board is a single dictionary lookup, which is practically instant. A board that's not in the book can't be solved.

Why the letters look backwards

This is the part that confuses everyone at first, so let's go slowly. BFS starts at the goal and moves the hole away from it. But the answer we store must move the hole back towards the goal. So every letter is flipped:

→

To solve 12345x786, the hole has to go back down. That's why the move list pairs the offset −3 with the letter "d":

moves_table.py
moves = [(-3, "d"), (3, "u"), (-1, "r"), (1, "l")]
# BFS moves the hole UP (-3)    -> the solution moves it DOWN  ("d")
# BFS moves the hole DOWN (+3)  -> the solution moves it UP    ("u")
# BFS moves the hole LEFT (-1)  -> the solution moves it RIGHT ("r")
# BFS moves the hole RIGHT (+1) -> the solution moves it LEFT  ("l")

Why the new letter goes in front

Suppose BFS is at board A, and the book already says A needs the moves "lu" to reach the goal. Now BFS steps from A to a new board B. To solve B, you must first undo that step (getting back to A), and then follow A's moves. So the new letter goes at the front:

bfs_tree[B] = letter_back_to_A + bfs_tree[A]

If we added it at the end instead, we'd be doing the moves in the wrong order and the hole would end up somewhere strange.

eight_puzzle.py (fixed, every line explained)
from collections import deque     # deque = a fast queue: add at the back, take from the front

config = ["1", "2", "3", "4", "5", "6", "7", "8", "x"]   # the goal board, tile by tile ("x" = hole)
target = "".join(config)          # glue the pieces into one string: "12345678x"
bfs_tree = {target: ""}           # the answer book: board -> moves that solve it ("" = already solved)

# each thing in the queue is (state, pos_x): a board and where its hole is
q = deque([(target, target.index("x"))])   # BFS starts from the GOAL; its hole is at position 8
moves = [(-3, "d"), (3, "u"), (-1, "r"), (1, "l")]   # (how BFS moves the hole, the letter that UNDOES it)

while q:                                        # keep going while boards are waiting in line
    curr_state, pos = q.popleft()               # take the oldest board (first in, first out)
    current_path = bfs_tree[curr_state]         # the moves that solve this board
    for offset, solution_char in moves:         # try moving the hole in all 4 directions
        npos = pos + offset                     # the hole's new position
        if npos < 0 or npos >= 9:               # fell off the top or bottom edge?
            continue                            #   then this direction is impossible
        if offset == -1 and pos % 3 == 0:       # ✅ ==  moving left from the left column?
            continue                            #   no wrapping around the edge!
        if offset == 1 and pos % 3 == 2:        # ✅ ==  moving right from the right column?
            continue                            #   no wrapping around the edge!
        state_list = list(curr_state)           # ✅ curr_state  string -> list, so we can swap
        # e.g. ["1", "2", ..., "x"]
        state_list[pos], state_list[npos] = (   # swap the hole and the tile next to it...
            state_list[npos], state_list[pos]   # ...both at once, Python-style
        )
        new_state = "".join(state_list)         # list -> string again (strings work as dict keys)
        if new_state not in bfs_tree:           # ✅ not in  a board we've never seen?
            bfs_tree[new_state] = (solution_char +    # first undo this step,
                                   current_path)      # then follow the old board's moves
            q.append((new_state, npos))         # explore it later: join the back of the line

while True:                                     # ✅ answer questions until the input ends
    try:
        s = input()                             # read one line, e.g. "2 3 4 1 5 x 7 6 8"
    except EOFError:                            # no more lines?
        break                                   #   then we're done
    s = "".join(s.split())                      # remove every space: "23415x768"
    if s not in bfs_tree:                       # ✅ not in  missing from the book?
        print("unsolvable")                     #   then no sequence of moves can solve it
    else:
        print(bfs_tree[s])                      # otherwise just look up the answer

# output: ullddrurdllurrdlurd

LEVEL 7

The parity secret: why half the boards are impossible

9! = 362,880 boards exist, but the answer book has exactly 181,440 entries: precisely half. The other half can never be solved, no matter how clever you are. Why?

Write the tiles in reading order and skip the hole. An inversion is a pair of tiles in the wrong order, where a bigger number comes before a smaller one.

2
1
3
4
5
6
7
8

Reading order: 2 1 3 4 5 6 7 8
Wrong-order pairs: only (2, 1)
→ 1 inversion (odd)

Now watch what each kind of move does to the inversions:

  • Left or right: the hole swaps with a tile in the same row, so the tiles' reading order doesn't change at all. Inversions: +0.
  • Up or down: one tile jumps over exactly 2 other tiles in reading order. Each of those 2 pairs flips between right and wrong order, so the count changes by −2, 0, or +2.

Either way, the count changes by an even number, so whether it's even or odd (its parity) can never change. The goal has 0 inversions, which is even. So a board with an odd number of inversions can never reach the goal!

parity.py
def inversions(state):
    tiles = [c for c in state if c != "x"]   # reading order, hole removed
    count = 0
    for i in range(len(tiles)):
        for j in range(i + 1, len(tiles)):
            if tiles[i] > tiles[j]:           # bigger before smaller: wrong order
                count += 1
    return count

def solvable(state):
    return inversions(state) % 2 == 0         # even -> solvable, odd -> impossible

print(inversions("23415x768"), solvable("23415x768"))   # 4 True
print(inversions("21345678x"), solvable("21345678x"))   # 1 False

# Check against the answer book from Level 6:
print(len(bfs_tree))                              # 181440
print(all(solvable(s) for s in bfs_tree))         # True
The $1,000 that nobody won

Sam Loyd's famous challenge was a 15 puzzle with only tiles 14 and 15 swapped: exactly one inversion. A similar parity argument shows it's impossible, so the prize money was always safe. Our BFS proves the 8-puzzle version by brute force: of 362,880 boards, exactly the 181,440 with an even number of inversions are reachable.

This gives us a lightning-fast test: before you search, count inversions. If the count is odd, print unsolvable immediately and skip the search entirely.

A*: searching with a sense of direction

BFS is fair but blind: it spreads out equally in every direction, even directions that lead away from the goal. A* (say "A-star") is smarter. For each board it estimates how far it still is from the goal, and it always explores the most promising board first.

A good estimate is the Manhattan distance: for each tile, count how many rows plus columns it is from its home square, and add these up. Each move shifts only one tile by one square, so you can never need fewer moves than this number. Because the estimate never overestimates, A* is still guaranteed to find a shortest solution.

astar.py
import heapq

def manhattan(state):
    total = 0
    for i, c in enumerate(state):
        if c != "x":
            home = int(c) - 1                 # tile 1 belongs at position 0, and so on
            total += abs(i // 3 - home // 3) + abs(i % 3 - home % 3)
    return total

def astar(start, goal="12345678x"):
    best = {start: 0}                         # fewest moves found so far to each board
    heap = [(manhattan(start), 0, start, "")] # (estimate of total, moves so far, board, path)
    explored = 0
    while heap:
        f, g, s, path = heapq.heappop(heap)   # the most promising board
        if g > best[s]:                       # an old, worse entry: skip it
            continue
        explored += 1
        if s == goal:
            return path, explored
        for letter, t in neighbours(s):
            if t not in best or g + 1 < best[t]:
                best[t] = g + 1
                heapq.heappush(heap, (g + 1 + manhattan(t), g + 1, t, path + letter))
    return None, explored

path, explored = astar("23415x768")
print(len(path), explored)        # 19 651

Which one should I use?
  • Many boards, small puzzle (3×3): one backwards BFS, then look up each answer. That's the sample solution's approach.
  • One board, bigger puzzle (4×4): the 15 puzzle has over 10 trillion reachable boards, far too many to store. A* (or its memory-saving cousin IDA*) with a good estimate is the way to go.
CHECKPOINT

Quick concept quiz

1. Why is the first route BFS finds to a board always a shortest one?

Because the queue is first-in-first-out. All boards 1 move away are taken out before any board 2 moves away, those before any board 3 moves away, and so on. So when BFS first reaches a board, every shorter route has already been fully explored. If one existed, BFS would have found the board earlier.

2. In the sample solution, why is it solution_char + current_path and not current_path + solution_char?

The new board is one step further from the goal than the current board. To solve it, you must first make the move that returns to the current board (solution_char), and then follow the current board's moves (current_path). First things go first, at the front.

3. Can 1 2 3 / 4 5 6 / 8 7 x be solved? Answer without running any search.

Reading order (skip the hole): 1 2 3 4 5 6 8 7. The only wrong-order pair is (8, 7), so there is 1 inversion, which is odd. The parity can never change, and the goal has 0 inversions, so this board is unsolvable.

def apply_moves(state, moves):
    for m in moves:
        options = dict(neighbours(state))   # e.g. {"u": "...", "d": "...", "l": "..."}
        if m not in options:
            return None                     # this move would leave the board

Only the board size changes: positions 0–5 instead of 0–8. A row still has 3 squares, so up/down are still ±3, and the edge checks with % 3 stay the same.

✅ Solution
ex7_five_puzzle.py
from collections import deque

goal = "12345x"
book = {goal: ""}
q = deque([(goal, goal.index("x"))])
moves = [(-3, "d"), (3, "u"), (-1, "r"), (1, "l")]
while q:
    s, pos = q.popleft()
    for offset, ch in moves:
        npos = pos + offset
        if npos < 0 or npos >= 6:                 # 6 squares now
            continue
        if offset == -1 and pos % 3 == 0:
            continue
        if offset == 1 and pos % 3 == 2:
            continue
        cells = list(s)
        cells[pos], cells[npos] = cells[npos], cells[pos]
        t = "".join(cells)
        if t not in book:
            book[t] = ch + book[s]
            q.append((t, npos))

print(len(book))                                  # 360  (= 6! / 2)
far = max(book, key=lambda s: len(book[s]))
print(far, len(book[far]))                        # 45x123 21

8. BFS vs A* showdown ★★★

For the three solvable boards below, compare bfs_solve() from Level 4 and astar() from Level 8. Do they always find solutions of the same length? Which one explores fewer boards?

💡 Hint

Both functions return (path, count). Compare len(path) for the length and the second number for the work done.

✅ Solution
ex8_showdown.py
for board in ["23415x768", "8134x2765", "x87654321"]:
    p1, n1 = bfs_solve(board)
    p2, n2 = astar(board)
    print(board, len(p1), len(p2), n1, n2)

# 8134x2765 14 14 9021 77
# x87654321 28 28 180899 727

Same length every time, because both are guaranteed to be optimal. But A* does a tiny fraction of the work, because its Manhattan estimate keeps pointing it towards the goal.
