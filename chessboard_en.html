The Castle Guard Puzzle: Placing Pieces on a Strange Chessboard

A wobbly, oddly shaped castle needs k guards. Each guard can see along their whole row and their whole column, and no guard may stand where another guard can see them. In how many different ways can the guards be placed? We'll solve this classic contest problem step by step, and we'll even catch the five bugs hiding in its sample solution.

Ages 13+ Backtracking Bug hunt Interactive board 8 practice problems
LEVEL 1

The puzzle

Here is the problem in plain words.

The problem (POJ 1321)

You get a chessboard that fits in an n × n box (n ≤ 8). Not every square is part of the board: # marks a real square, and . marks a hole where nothing can go. Place k identical pieces (k ≤ n) on real squares so that no two pieces share a row or a column. Count all the different ways to do it.

If you play chess, you'll recognise these pieces: they behave exactly like rooks (♜), which attack along rows and columns. So the question really is: how many ways can k rooks sit on this broken board without attacking each other?

Let's try the smallest example. The board is 2 × 2 with only two real squares, and we want to place k = 1 piece:

The striped squares are holes. With one piece there are two real squares to choose from, so the answer is 2.

Now a 4 × 4 castle with k = 4 guards. Every row and every column must get exactly one guard, and the real squares form a diagonal line:

Each row has just one real square, so there's no choice at all: the answer is 1.

"Identical" matters

The pieces all look the same, so swapping two of them does not make a new arrangement. Only which squares are used matters. Keep this in mind, because it shapes how our program searches.

LEVEL 3

Thinking row by row

Two pieces can never share a row, so each row holds at most one piece. That gives us a neat plan: walk down the board one row at a time and make one decision per row.

Option A
Skip this row
Put no piece here and move to the next row. We need this because k can be smaller than n.
Option B
Place one piece
Pick a column that is a real square (#) and not used by another piece yet.
Stop when…
k pieces placed
That's one valid arrangement: count it! If we run out of rows first, it's a dead end.

To remember which columns are taken, we keep a list cols_used of True/False values. This is the backtracking recipe again: Choose a column → Explore the next row → Un-choose the column, so other branches can use it.

Here is the whole search tree for the first sample (#. / .#, k = 1). dfs(row, placed) means "we are at this row and have placed this many pieces":

k pieces placed → count +1ran out of rows → dead end
Quick quiz: why do we always go to the next row, and never come back to an earlier one?

Because the pieces are identical. If we were allowed to place a piece in row 1 and then go back to row 0, we would build the same set of squares in a different order and count it twice. Moving strictly downward means every arrangement is built in exactly one way, so it's counted exactly once.

Here is the repaired program. The logic is the same as the original. We just moved the search into solve() and fixed every bug:

chessboard.py (fixed)
def solve(n, k, board):
    ans = 0
    cols_used = [False] * n               # which columns already have a piece

    def dfs(row, placed):
        nonlocal ans                       # ✅ ans belongs to solve()
        if placed == k:                    # ✅ == compares
            ans += 1                        # k pieces placed: one more way!
            return
        if row == n:                       # ran out of rows: dead end
            return
        dfs(row + 1, placed)                # option A: skip this row
        for col in range(n):                # option B: a piece in this row
            if board[row][col] == '.' or cols_used[col]:
                continue                    # a hole, or the column is taken
            cols_used[col] = True          # choose  ✅ cols_used[col]
            dfs(row + 1, placed + 1)        # explore
            cols_used[col] = False         # un-choose

    dfs(0, 0)
    return ans

while True:
    n, k = map(int, input().split())
    if (n, k) == (-1, -1):
        break
    board = [input() for _ in range(n)]
    print(solve(n, k, board))

Bonus trap: blank lines in the input

Some judges put an empty line between test cases. Then input().split() returns an empty list and the program crashes with ValueError: not enough values to unpack. A safer way is to read all the input at once and walk through it word by word, because split() ignores blank lines completely:

robust_input.py (replaces the while-loop)
import sys

def main():
    data = sys.stdin.read().split()    # every word of the input, blank lines ignored
    pos = 0
    while True:
        n, k = int(data[pos]), int(data[pos + 1])
        pos += 2
        if n == -1 and k == -1:
            break
        board = data[pos:pos + n]        # the next n words are the board rows
        pos += n
        print(solve(n, k, board))

main()

# 1

LEVEL 7

Pruning: don't chase impossible dreams

Imagine we still need to place 5 pieces, but only 3 rows are left. Since each row holds at most one piece, this can never work. Yet our program keeps exploring anyway!

One extra line fixes that: if placed + (rows left) < k, give up right away. Let's count how many times dfs is called, with and without that line, on a full 8 × 8 board with k = 8:

pruning.py
def solve_counted(n, k, board, prune):
    ans = calls = 0
    cols_used = [False] * n

    def dfs(row, placed):
        nonlocal ans, calls
        calls += 1
        if placed == k:
            ans += 1
            return
        if row == n:
            return
        if prune and placed + (n - row) < k:
            return                     # ✂ not enough rows left
        dfs(row + 1, placed)
        for col in range(n):
            if board[row][col] == '.' or cols_used[col]:
                continue
            cols_used[col] = True
            dfs(row + 1, placed + 1)
            cols_used[col] = False

    dfs(0, 0)
    return ans, calls

full = ["#" * 8] * 8
print(solve_counted(8, 8, full, prune=False))   # (40320, 1952457)
print(solve_counted(8, 8, full, prune=True))    # (40320, 178882)
1,952,457
calls without pruning
178,882
calls with one line of pruning: about 11× less work, same answer 40,320
Why so much?

When k = n, every row must get a piece, so the "skip this row" branch is always hopeless. Without pruning, the program wanders down every one of those skip branches until it hits the bottom. The pruning check notices immediately and turns back.

LEVEL 8

Big numbers, and why we still need to search

On a full board (no holes) we can actually count with a formula. Let's see where it comes from.

Take a full n × n board and k = n. Row 0 has n columns to choose from, row 1 has n − 1 (one column is taken), row 2 has n − 2… So the count is n × (n − 1) × … × 1 = n! ("n factorial").

n12345678
n!126241207205,04040,320

For smaller k, there's a formula too: choose k of the n rows, choose k of the n columns, then match them up in k! ways. On the full 8 × 8 board with k = 4 that's 70 × 70 × 24 = 117,600.

But holes break every formula

As soon as the board has holes, the neat multiplication stops working, because different rows have different free columns. That's exactly why the problem asks us to search. With n ≤ 8, backtracking is fast enough. For bigger boards, programmers combine it with dynamic programming: they remember "row + used columns + pieces placed" so no situation is solved twice. You'll build that in practice problem 8!

CHECKPOINT

Quick concept quiz

Try to answer in your head before you peek.

Q1. What goes wrong if we delete the line dfs(row + 1, placed) (the "skip this row" option)?

Then every row we visit must get a piece. That only works when k = n. For sample 1 (k = 1), the program would place a piece in row 0 and stop, and it would never find the arrangement that uses only row 1. It would print 1 instead of 2.

Q2. What if we forget cols_used[col] = False (the un-choose step)?

Columns stay "taken" forever after their first use, even after we've backed out of that branch. Later branches wrongly think those columns are blocked, so many valid arrangements are never found and the count comes out too small.

Q3. Why does if placed == k come before if row == n?

If the last piece is placed in the last row, we call dfs(n, k). Both conditions are true there, and we want to count it, not throw it away as a dead end. Checking placed == k first also lets us stop early as soon as all k pieces are down, without walking through the leftover rows.

✅ Solution
ex3_show_all.py
def show_all(n, k, board):
    cols_used = [False] * n
    pieces = []                              # (row, col) of every piece

    def dfs(row):
        if len(pieces) == k:
            for r in range(n):
                line = list(board[r])
                for pr, pc in pieces:
                    if pr == r:
                        line[pc] = "O"
                print("".join(line))
            print()
            return
        if row == n:
            return
        dfs(row + 1)
        for col in range(n):
            if board[row][col] == '.' or cols_used[col]:
                continue
            cols_used[col] = True; pieces.append((row, col))
            dfs(row + 1)
            pieces.pop(); cols_used[col] = False

    dfs(0)

6. Queens in the castle ★★★

Upgrade the pieces to queens: now two pieces may not share a row, a column or a diagonal. Count the arrangements on a shaped board. (Check: full 8 × 8 with k = 8 → 92, the famous 8-queens answer. Sample 1 with k = 2 → 0.)

💡 Hint

Remember where each piece is. Two squares (r1, c1) and (r2, c2) are on the same diagonal when abs(r1 - r2) == abs(c1 - c2).

✅ Solution
ex6_queens.py
def solve_queens(n, k, board):
    ans = 0
    cols_used = [False] * n
    pieces = []

    def diagonal_free(r, c):
        return all(abs(pr - r) != abs(pc - c) for pr, pc in pieces)

    def dfs(row, placed):
        nonlocal ans
        if placed == k:
            ans += 1
            return
        if row == n:
            return
        dfs(row + 1, placed)
        for col in range(n):
            if board[row][col] == '.' or cols_used[col] or not diagonal_free(row, col):
                continue
            cols_used[col] = True; pieces.append((row, col))
            dfs(row + 1, placed + 1)
            pieces.pop(); cols_used[col] = False

    dfs(0, 0)
    return ans

print(solve_queens(8, 8, ["#" * 8] * 8))   # 92
print(solve_queens(2, 2, ["#.", ".#"]))    # 0   (the two squares share a diagonal)

7. Columns as bits ★★★

Replace the cols_used list with a single integer used, where bit c is 1 when column c is taken. Bonus: why don't you need an "un-choose" line any more?

💡 Hint

Column c is taken if used & (1 << c) is not zero. Pass used | (1 << c) into the next call. That's a new number, and your own used is never changed, just like code + letter in the backtracking lesson.

✅ Solution
ex7_bits.py
def solve_bits(n, k, board):
    ans = 0

    def dfs(row, placed, used):
        nonlocal ans
        if placed == k:
            ans += 1
            return
        if row == n:
            return
        dfs(row + 1, placed, used)
        for col in range(n):
            if board[row][col] == '#' and not used & (1 << col):
                dfs(row + 1, placed + 1, used | (1 << col))   # new number: nothing to undo

    dfs(0, 0, 0)
    return ans

print(solve_bits(2, 1, ["#.", ".#"]))                      # 2
print(solve_bits(4, 4, ["...#", "..#.", ".#..", "#..."]))   # 1

8. Remember, don't repeat (DP) ★★★

Turn the search into a function ways(row, placed, used) that returns the number of arrangements for the rest of the board, and add @lru_cache so repeated situations are only solved once. Test it against solve_bits (from problem 7) on 300 random boards.

💡 Hint

Same three cases as before: return 1 if placed == k, return 0 if row == n, otherwise add up the "skip" branch and every legal "place" branch. The answer only depends on (row, placed, used), which is why caching works.

✅ Solution
ex8_memo.py
import random
from functools import lru_cache

def solve_memo(n, k, board):
    @lru_cache(maxsize=None)
    def ways(row, placed, used):
        if placed == k:
            return 1
        if row == n:
            return 0
        total = ways(row + 1, placed, used)                   # skip this row
        for col in range(n):
            if board[row][col] == '#' and not used & (1 << col):
                total += ways(row + 1, placed + 1, used | (1 << col))
        return total
    return ways(0, 0, 0)

random.seed(2026)
ok = True
for _ in range(300):
    n = random.randint(1, 6)
    k = random.randint(1, n)
    board = ["".join(random.choice("#.") for _ in range(n)) for _ in range(n)]
    ok = ok and solve_memo(n, k, board) == solve_bits(n, k, board)
print(ok)                                   # True
print(solve_memo(8, 8, ["#" * 8] * 8))      # 40320
