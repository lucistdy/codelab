神奇的 5：只有最后一位数字说了算

Iahub 手里有一条很长的数字纸条——把字符串 a 首尾相接复制 k 份拼成的——他想删掉一些数字（但不能删光），让剩下的数字能被 5 整除。Codeforces 271C 问的是：他一共有多少种不同的删法？这条纸条最长能有 100 万亿位数字，所以想一种一种去数删法是完全不可能的。

写给爱思考的 13 岁少年 一个大发现：只有最后一位说了算 可互动
第一关

认识这个任务

给你一个数字字符串 a，还有一个数字 k。整条"纸条" s 就是把 a 连续写 k 遍（比如 a = "12"，k = 3，纸条就是 "121212"）。你可以随意删掉纸条上的一些数字——但不能把它们全删光，至少要留一个。剩下的数字从左到右连起来，就组成一个数（可以有前导零，007 其实就是 7，这里出现 007 这样的形式也没关系）。

请数一数：有多少种不同的删法，能让剩下的数被 5 整除？如果两种删法删掉的位置集合不同，就算是"不同"的删法——哪怕剩下的数字看起来一模一样也一样算不同。答案要对 1,000,000,007 取模后输出。

题目原话

a="1256", k=1 → 4。纸条就是 1256。四种成功的删法分别留下 5、15、25、125——全都能被 5 整除。
a="555", k=2 → 63。纸条是 555555（六个 5）。这六个 5 里任意非空子集都能被 5 整除，非空子集一共有 2⁶ − 1 = 63 个。
a="13990", k=2 → 528。纸条是 1399013990——别忘了，这是两份 a 拼在一起，不是 a 本身！

为什么要在意速度？

a 最长能有 100,000 位，k 最大能到 1,000,000,000。也就是说纸条最长能有 100,000,000,000,000 位——100 万亿位！这个字符串本身根本印不出来，更别说在 1 秒的时间限制内一位一位地去扫了。

第二关

破解整道题的关键一句话

这里有个你可能早就知道、只是没说出口的事实：一个数能不能被 5 整除，只看它的最后一位是不是 0 或 5。 2,847,530？能整除——末位是 0。2,847,533？不能——末位是 3。不管这个数有多长，前面的每一位是什么都不重要。只有最后一位说了算。

为什么会这样？除了最后一位，其他每一位分别站在十位、百位、千位……上，而 10、100、1000……全都是 5 的倍数（因为 10 = 2×5）。所以除了最后一位以外，其他每一位对整个数的贡献都是 5 的倍数，永远不会影响这个数能不能被 5 整除。只有最后一位不是"天然安全"的，它才是唯一能左右结果的关键票。

案卷线索

这种"只看余数"的思维方式，正是质数侦探社页面里的钟面数学。这里的"钟面"只有 5 个刻度（0、1、2、3、4），只有末位是 0 或 5 的数字才会正好落在刻度 0 上。

第三关

为什么"每种删法都试一遍"没有希望

如果纸条有 n 位数字，那么一共有 2n 种"保留哪些数字"的方案（每一位要么留、要么删，两种选择，乘起来）。当 n 最大能到 100 万亿时，这个数字已经不只是"很大"了，而是大得没法想象——远远超过可观测宇宙中原子的数量。没有任何一台计算机能把它们一一列出来。我们需要用一个公式直接算出成功删法的数量，而不是真的去生成每一种删法。

2100,000,000,000,000
最坏情况下的删法总数——一个超过 30 万亿位的数字
O(|a| + log k)

第四关

关键发现：锁定"最后留下的那一位"

根据第二关，我们已经知道剩下的数能被 5 整除的条件到底是什么：最后留下的那一位数字必须是 0 或 5。那我们不妨换个角度问问题：不问"哪种删法能成功？"，而是对纸条上每一个是 0 或 5 的位置分别问："有多少种删法，能让它恰好是最后留下的那一位？"

假设这个位置前面（从纸条最开头数起）一共有 i 个数字。要让它成为最后幸存的那一位：

  • 它后面的每一位都必须删掉——没有别的选择，只有 1 种方案。
  • 它前面的每一位，留还是删都无所谓——每个位置都有 2 种选择，i 个位置合起来就是 2i 种组合。
  • 这一位本身当然要保留（这正是我们要的效果）。

所以，单单这一个好位置，就贡献了恰好 2i 种成功的删法。把纸条上每一个是 0 或 5 的位置的 2i 加起来，就能不重不漏地数完所有成功的删法——因为每一种成功的删法都恰好有一个"最后幸存的数字"，所以它只会在那一个位置被数到一次。

拿数字条 1256 来验证一下（位置从 0 开始编号）：

i=0
2
i=1
5
i=2

i=3

只有位置 i=2（数字 5）符合条件，贡献 2² = 4。这正好和题目给出的 a="1256", k=1 的答案完全一致！

最重要的一句话

答案 = 纸条上每一个数字是 0 或 5 的位置 i（从纸条开头 0 起编号）对应的 2i 之和。

第五关

利用 k 份拷贝：等比数列

第四关的公式是对的，但一位一位地加 2i，还是得访问多达 100 万亿个位置。这里有个捷径：纸条其实就是同一段短字符串 a（长度为 L）首尾相接了 k 遍。"第 j 份拷贝（从 0 开始编号）里偏移量为 p"的位置，全局位置就是 i = j×L + p，所以它的贡献是 2jL+p = 2jL × 2p。

按"属于哪一份拷贝"把所有好位置分组。每一份拷贝里"好偏移量" p 是完全相同的，所以每份拷贝内部的求和结果也相同——我们把它叫 S = 一份 a 里所有好偏移量 p 对应的 2p 之和。第 j 份拷贝的总贡献就是 S × 2jL，也就是 S × rj，其中 r = 2L。把 k 份全部加起来：

答案 = S × (r⁰ + r¹ + r² + … + rk−1)

括号里那部分是经典的等比数列求和。它有一个现成的公式：(rk − 1) / (r − 1)（当 r ≠ 1 时；如果 r = 1，每一项都等于 1，求和直接就是 k）。用快速幂计算 rk 只需要 O(log k) 次乘法，而在取模意义下的"除法"，就是乘以一个模逆元。

案卷线索

快速算出 rk mod M，正是快速幂页面讲的那个技巧。而模逆元 (r−1)−1 是用 pow(r-1, M-2, M) 算出来的——这之所以成立，正是因为费马小定理，也就是费马测谎仪页面里那些检测背后依赖的同一个事实。

第六关

逐行读代码

下面是完整的解法。先看左边的代码，再看右边的大白话翻译。

magic_five.py
MOD = 1000000007

a = input().strip()
k = int(input())
L = len(a)

S = 0
power = 1
for ch in a:
    if ch == '0' or ch == '5':
        S = (S + power) % MOD
    power = power * 2 % MOD

r = pow(2, L, MOD)              # 用快速幂算 2^L mod MOD
if r == 1:
    geo = k % MOD
else:
    geo = (pow(r, k, MOD) - 1) * pow(r - 1, MOD - 2, MOD) % MOD

print(S * geo % MOD)
S = 0 power = 1 for ch in a: if ch == '0' or ch == '5': S = (S + power) % MOD power = power * 2 % MOD
遍历一份 a，边走边维护 power = 2p。每遇到一个好数字，就把它的 2p 加进 S（也就是第四关说的"一份拷贝内的求和"）。
r = pow(2, L, MOD)
Python 的三参数 pow 会自动帮你做快速取模幂运算——不管 L 多大，2L mod MOD 都能在 O(log L) 步内算出来。
geo = (pow(r, k, MOD) - 1) * pow(r - 1, MOD - 2, MOD) % MOD
第五关推导出的等比数列公式，在取模意义下计算：pow(r-1, MOD-2, MOD) 就是 (r−1) 的模逆元，充当"除法"的角色。
print(S * geo % MOD)
把"一份拷贝的和"乘上"等比数列总和"，正是第五关方框里那条公式。

第九关

练习题：先自己算，再用工具核对

每一题都先在纸上算一遍，再用上面的小工具验证答案。

练习 1：a="5", k=1。为什么答案一定是 1？

纸条就是单独一个数字 5。你不能把所有数字都删光，而这里本来就只有一个数字——所以唯一合法的做法就是保留它。S = 2⁰ = 1，r = 2¹ = 2，k=1 时等比数列之和就是 r⁰ = 1。答案：1 × 1 = 1。

练习 2：a="05", k=1。从 "05" 里删数字，共有 3 种非空删法——为什么这 3 种全都成功？

三种非空子序列分别是 "0"、"5"、"05"（其实就是带前导零的数字 5）。它们无一例外都以 0 或 5 结尾，根据第二关的规则，三个都能被 5 整除。用公式验证：位置 0（'0'）贡献 2⁰=1，位置 1（'5'）贡献 2¹=2，合计 S=3。k=1 时等比数列之和是 1，所以答案是 3。

练习 3：a="20", k=3（纸条是 "202020"）。用等比数列的捷径算出答案，而不是把全部 63 种删法都列出来。

只有偏移量 p=1（数字 0）是好位置，所以 S = 2¹ = 2。L=2，所以 r = 2² = 4。k=3 时等比数列之和是 4⁰+4¹+4² = 1+4+16 = 21。答案：S × 21 = 2 × 21 = 42。（你也可以用笨办法核对：在 "202020" 里，0 分别出现在位置 1、3、5，贡献 2¹+2³+2⁵ = 2+8+32 = 42——答案一样，只是算得更慢。）

练习 4：为什么好位置前面的数字是什么完全不重要——难道前面的选择不会悄悄破坏被 5 整除这件事吗？

不会——这正是第二关那条规则的神奇之处。能不能被 5 整除，只取决于最后留下的那一位。一旦这最后一位被锁定为 0 或 5，它前面的每一位只是把整个数往前挪了一个 10 的倍数（多加一些十位、百位、千位……），而 10 本身就是 5 的倍数，这永远不会改变整个数能不能被 5 整除。这正是为什么前面这些数字是"自由"的——留着还是删掉，对答案完全没有影响。

练习 5（挑战题）：修改代码，改成统计能让剩下的数被 2 整除的删法数量。哪里要变，哪里完全不用变？

能不能被 2 整除，同样只取决于最后一位（10 也是 2 的倍数！）——所以整套思路完全可以照搬。唯一要改的是"什么算好数字"：把 ch == '0' or ch == '5' 换成 ch in '02468' 就行了。其余的——单份拷贝之和 S、跨 k 份拷贝的等比数列、模逆元——统统原封不动。
