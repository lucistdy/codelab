龟兔赛跑：Floyd 判圈算法

有些数字序列会一直往前走，永不重复；有些却会偷偷绕回去，陷入一个永远重复的循环。怎么才能区分这两种情况——而且不需要用无穷多的内存去记住见过的每一个数字？答案的名字，直接借用了伊索寓言的那个故事。

不需要数学基础 双指针 可以互动
第一关

任务目标：这串数字会不会绕圈？

想象有一条规则，能把一个数字变成下一个数字：从某个数开始，套用规则得到下一个，再套用一次，再套用一次，一直下去。这就搭出了一条链：x₀ → x₁ → x₂ → x₃ → …

这样一条链，可能会发生两种情况：

  • 它一直不断产生新数字，永不重复（或者最终停在某个让过程终止的数字上，比如到达 1）。
  • 在某个时刻，它碰到了一个之前已经出现过的数字——从那一刻起，它就注定要永远重复那一段循环。

这一页要回答的问题是：给定规则和一个起始数字，怎么判断这条链会不会绕圈——甚至精确找出这个圈从哪里开始、有多长——而且不需要存下走过的每一个数字？

这个名字是怎么来的？

这个算法有个外号叫龟兔赛跑算法，来自伊索寓言里那个"跑得慢但很稳的乌龟"和"跑得快但很粗心的兔子"的故事。它让两个"跑步者"以不同的速度在同一条数字链上前进——而且，就像寓言里一样，这场比赛的结局会让你有点意外。

为什么不干脆记住每一个数字？

你完全可以用一个列表（或者集合）记下你见过的每一个数字，每次拿新数字去比对一下。这确实管用！但链条越长，占用的内存就越多——在一些实际问题里（想象一条有几十亿步的链条，或者一条藏在计算机内存里、没法随便去挨个查看的链条），这个代价会很大。龟兔赛跑技巧用只有两个变量就解决了同样的问题，不管链条最后到底有多长。

第二关

一个好玩的例子：快乐数

这里有一条很有意思的规则可以玩玩：拿一个数字，把它每一位数字都平方，再加起来，得到下一个数字。一直这样下去。如果最终到达 1，这个数字就叫作快乐数。如果永远到不了 1（反而陷入一个不断重复的循环），它就是不快乐的数。

每一个数字最终都会绕圈

这里有个很妙的事实：在这条规则下，任何起始数字最终都会进入某个循环——要么是只有 {1} 这一个数的"小循环"（快乐数），要么是所有不快乐的数最终都会掉进的那同一个 8 数字循环 {4, 16, 37, 58, 89, 145, 42, 20}。没有第三种可能。所以"这个数快不快乐"，本质上就是在问"它的链条最终会掉进哪个循环"——这正是我们这个算法要回答的问题。

第三关

最直接的办法：记住见过的一切

最简单的做法：用一个集合记录目前为止访问过的每一个数字。在走到下一个数字之前，先检查它是不是已经在集合里了。如果是，就说明找到了循环。如果最终到达 1，就是快乐数。

happy_naive.py
def next_number(x):
    return sum(int(d) ** 2 for d in str(x))

def is_happy_naive(x):
    seen = set()
    while x != 1 and x not in seen:
        seen.add(x)
        x = next_number(x)
    return x == 1

这个方法完全没问题，而且对这么小的问题来说，确实是个不错的解法——循环很短，集合也不会变得很大。但想象一条要走上几十亿步才会绕圈的链条（这在别的判圈问题里确实会发生，比如在一条巨大的链表上跟着指针一路走下去）。存下几十亿个访问过的值会把内存全部吃光。我们需要一种只用固定大小的额外空间就能检测出循环的方法。

第四关

巧妙的想法：两个跑步者，不同的速度

诀窍来了。在同一条数字链上放两个"跑步者"，都从起点出发：

  • 乌龟每次走一步：x → next(x)。
  • 兔子每次走两步：x → next(next(x))。

如果这条链永远往前走、从不重复，兔子就会一路领先乌龟越跑越远，两者永远不需要相遇——什么特别的事都不会发生（在快乐数这个例子里其实不会出现这种情况，因为每条链最终都会绕圈；但在别的场景里，比如以 None 结尾的链表，这就是"没有循环"的一般情形）。

但如果这条链确实绕圈了——把这个圈想象成一条真正的环形跑道——那么一旦两个跑步者都进了这条环形跑道，速度是两倍的兔子实际上就是在套圈乌龟。而在一条环形跑道上，跑得快的人套跑得慢的人的圈，迟早会追上、站到完全相同的位置。乌龟和兔子必然会在同一时刻站在同一个数字上。这就是循环存在的证明！

反过来的伊索寓言

在故事里，兔子因为粗心大意输掉了比赛。在这里，兔子做的正是它该做的事——它的速度恰恰保证了它迟早会一头撞回乌龟身上，证明这条跑道确实是个圈。不需要任何粗心大意，只需要一个 2 倍的速度差。

happy_floyd_detect.py
def next_number(x):
    return sum(int(d) ** 2 for d in str(x))

def is_happy_floyd(x):
    slow = next_number(x)
    fast = next_number(next_number(x))
    while slow != fast:
        slow = next_number(slow)
        fast = next_number(next_number(fast))
    return slow == 1

只用了两个变量，slow 和 fast——不管链条在绕圈之前有多长。等它们终于相遇了，只需要检查它们相遇在 1（快乐）还是别的地方（不快乐，困在那个 8 数字循环里）。

第五关

这到底为什么管用？

下面把直觉讲精确一点。假设这条链有一段长度为 μ 的"尾巴"（进入循环之前的那些数字），后面跟着一个长度为 λ 的循环（重复部分里有多少个数字）。

一旦乌龟和兔子都进入了循环，可以把它们的位置想象成一条有 λ 个格子的环形跑道上的点。每一轮，乌龟前进 1 格，兔子前进 2 格——所以每一轮，兔子都比乌龟多领先 1 格（这里说的"领先多少"是沿着这个圈往前数的）。

因为这个圈总共只有 λ 个格子，它们之间的差距（沿着圈计算）会依次经过 0, 1, 2, …, λ−1, 0, 1, 2, …，每 λ 轮就回到 0 一次。差距为 0 就意味着它们站在完全相同的数字上。因为这个差距每一轮都恰好增加 1，它必然会在两个跑步者都进入循环之后的最多 λ 轮之内再次回到 0——它不可能"跳过" 0，因为它每次只变化 1。

结论

它们相遇不是运气，而是简单算术保证的必然结果。而且这个过程很快：最多不超过 μ + λ 轮。

第六关

更进一步：循环从哪开始，有多长？

知道有循环存在固然好，但常常还想知道更多：到底哪个数字是第一个被重新访问的（这标志着尾巴的结束、循环的开始），以及循环里一共有多少个数字。Floyd 算法在找到相遇点之后，再用两个简短的阶段回答这两个问题。

第二阶段：找到循环的起点

这里有个小小的奇迹：把一个新指针，叫作 finder，重新放回链条的最开头。让另一个指针继续停在乌龟和兔子相遇的地方。现在让两个指针都每次走一步，一起走。它们这一次相遇的地方，正好就是循环的起点。

为什么"回到起点"这一招管用？

这归结于一点距离上的账目：乌龟和兔子第一次相遇的时候，乌龟走过的距离，减去尾巴长度 μ 之后，恰好是循环长度 λ 的整数倍。正是这层特殊的关系，让"从最开头每次走一步"和"从相遇点每次走一步"这两条路径，会在同一时刻踏上循环的入口。这是一段很漂亮的算术——你不需要自己推导一遍也可以相信它（不过等你熟悉了模运算之后，这其实是个很有趣的证明，值得找来看看）。

第三阶段：测量循环的长度

一旦知道了循环从哪开始，测量它的长度就很简单：站在那个数字上不动，用另一个指针一步一步走，数着步数，直到重新回到同一个数字。这个计数就是 λ。

floyd_full.py
def find_cycle(x0, next_fn):
    # 第一阶段：检测循环是否存在
    slow = next_fn(x0)
    fast = next_fn(next_fn(x0))
    while slow != fast:
        slow = next_fn(slow)
        fast = next_fn(next_fn(fast))

    # 第二阶段：找到循环的起点
    finder = x0
    while finder != slow:
        finder = next_fn(finder)
        slow = next_fn(slow)
    cycle_start = finder

    # 第三阶段：测量循环的长度
    length = 1
    p = next_fn(cycle_start)
    while p != cycle_start:
        p = next_fn(p)
        length += 1

    return cycle_start, length

第九关

该你练习了

先自己在纸上算出来，再用上面的工具验证。

挑战一：手动推演从 89 开始的链条。89 快乐吗？相对第七关的那个循环，它处在什么位置？

89 → 8²+9²=145 → 42 → 20 → 4 → 16 → 37 → 58 → 89。它是不快乐的数，而且因为 89 本身就是那 8 个循环数字之一，它的尾巴长度是 μ=0——它一开始就已经身处循环之中。

挑战二：如果乌龟和兔子从同一个数字出发，而这个数字本身就已经在循环里（尾巴长度为0），第一次比较就会相等吗？为什么？

不一定在第一轮就相等——到第一次比较的时候，乌龟已经走了 1 步，兔子已经走了 2 步，所以除非循环长度恰好是 1（比如快乐数的那个 {1} 循环，每一步都停在 1），否则走完第一轮之后它们通常会落在循环里的不同位置。按照第五关的论证，它们仍然保证会在 λ 轮之内相遇——从循环内部出发只是意味着 μ=0，所以"最多 μ+λ 轮"就变成了"最多 λ 轮"。

挑战三：为什么第三关那种"用集合记住一切"的朴素做法，链条越长占用的内存就越多，而龟兔赛跑的做法不会？

基于集合的做法会存下它访问过的每一个数字，所以内存占用跟走过的步数成正比——一条走了一百万步的链条，就需要一个最多能装一百万条记录的集合。龟兔赛跑的做法始终只跟踪两个当前位置（slow 和 fast），不管链条最后有多长——它只是不断覆盖旧的位置，而不是把所有位置都存下来，所以内存占用始终保持不变。

挑战四：这个算法在检测链表（一串盒子，每个都指向下一个，"next(x)"就是"顺着指针走"）中的循环时非常有名。你会怎么把第四关的快乐数代码改造成适用于链表？

算法的整体结构几乎不用变——只是"走一步"的含义变了。不再是用 next_number(x) 计算数字各位平方和，而是用 slow = slow.next，以及（两次）fast = fast.next.next，沿着链表的指针走，而不是套用数学公式。如果链表有循环（某个节点的指针绕回了前面的某个节点，而不是最终指向 None），快指针最终会等于慢指针，跟之前一模一样。如果链表没有循环，快指针就会先到达终点（None），这就告诉你根本不存在循环。

挑战五（较难）：所有不快乐的数最终都会掉进同一个 8 数字循环 {4, 16, 37, 58, 89, 145, 42, 20}。用第三关的朴素集合方法，你会怎么大致验证"对 1 到 10,000 之间的所有数字来说，这是唯一存在的不快乐循环"？

对 1 到 10,000 之间的每一个数字都跑一遍朴素算法（或者龟兔赛跑算法），对每一个结果是不快乐的数，都记录下它最终掉进的那个具体循环（也就是它开始重复时的那组数字）。然后把所有记录下来的循环互相比较一下。如果每一个都恰好是同一组 8 个数字 {4, 16, 37, 58, 89, 145, 42, 20}，这就是很强的经验证据（虽然不是对 10,000 以外的数字的数学证明），说明在这个范围内这是唯一的不快乐循环。这正是程序员几秒钟就能跑出来、而手算要花上很久的那种实验——也正是这个特定的 8 数字循环在快乐数爱好者里这么有名的原因之一。

Floyd 判圈算法（龟兔赛跑）——一种只用常数级额外内存就能检测循环的经典技巧。它出现在链表问题、快乐数这样的数论谜题里，甚至出现在 Pollard's rho 这样的密码学因数分解算法中。
