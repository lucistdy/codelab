质数工厂：把 15 位数字拆成配方

你已经会把一个小数字拆成它的质数"原料"了。这道题一口气丢给你一整摞数字——有些长达 15 位——告诉你一直处理下去，直到看见一个 0，并且要求把每份配方紧凑地写成 prime^count 的形式。核心思路和以前完全一样，只是把规模拉大到了一个粗心代码终于会被惩罚的地步。

不需要数学基础 质数与循环 可以互动
第一关

任务目标，原样来自题目

输入包含若干个正整数，每行一个——有些可能长达 15 位——最后以单独一行的 0 结束（这个 0 不需要分解）。对 0 之前的每一个数字，单独一行输出它的质因数分解，写成 p₁^e₁ p₂^e₂ \ldots 的形式——每一个能整除它的质数，带上它出现的次数，质数按从小到大排列。

题目原样给出的例子

输入：3111989、13091989、77145199750673，然后 0 结束。
输出：
317^1 9817^1
17^2 89^1 509^1
328439^1 234884407^1

已经学过质因数分解了吗？

这篇文章直接建立在 质因数分解 案卷之上，那篇讲了核心思路——测试候选除数、彻底除干净、√n 捷径——用的是不超过 10000 的数字。如果这些内容对你来说还是新的，建议先看那一篇；这里我们会讲得更快一些，专注在 15 位数字规模下真正不一样的地方。

第二关

快速复习：寻找配方的循环

核心算法完全没变：测试候选除数 d = 2, 3, 4, \ldots；只要 d 能整除 n 剩下的部分，就把它彻底除干净，用同一个 d 一直除到除不动为止；再换下一个候选数；一旦 d × d 超过剩下的部分就提前停止，因为此时剩下的必定本身就是最后一个质数。

factorize_basic.py
def factorize_basic(n):
    factors = []
    d = 2
    while d * d <= n:
        while n % d == 0:
            factors.append(d)
            n //= d
        d += 1
    if n > 1:
        factors.append(n)
    return factors

这正是 质因数分解 那篇里的算法，对任意 n 都正确。这篇文章接下来要讲的，是让它在 FACT0 这个规模下用得舒服、并且完全匹配它输入输出格式所需要的三个小改动。

第三关

新变化一：没人告诉你接下来有多少个数字

以前的题目通常一开始就会有一行"接下来有 n 个数字，读 n 次"。FACT0 用了一种不同的、在 SPOJ 这类老牌评测网站上很常见的写法：它只是不停地给你数字，每行一个，你要一直读下去，直到看见一个哨兵值——这里是数字 0——它表示"到此为止，停下来"。

read_until_zero.py
import sys

for line in sys.stdin:
    n = int(line)
    if n == 0:
        break
    # ... 在这里处理 n ...
为什么要用哨兵值？

这是一个简单的老派技巧：输入文件不需要在一开始就宣布自己有多长，数据本身在结束时会说"我讲完了"。你会在不少经典评测网站上见到这种写法——规则永远一样：先读一个值，检查它是不是停止信号，只有不是的时候才去处理它。

第四关

新变化二：输出要的是 p^e，不是重复的质数

质因数分解 那篇的输出风格是 5*7*7——每一份质数各打印一次。FACT0 要的是更紧凑的 7^2 形式：一个质数，后面跟着它出现了多少次。好消息是：这个次数早就在内层 while 循环里现成地存在了——我们只是之前没有把它记下来而已。

245 = 5 × 7 × 7
→
5^1 7^2

与其每除一次就往列表里追加一次 d，不如数清楚内层循环一共成功除了多少次，只有当这个次数大于零时，才把 (d, count) 这一对记下来：

count_not_list.py
count = 0
while n % d == 0:
    count += 1
    n //= d
if count > 0:
    factors.append((d, count))
第五关

新变化三：到了 15 位，√n 不再是可有可无的选项

在 质因数分解 那篇里，n 最大只有 10000，所以 √n 捷径只是一个不错的加分项——不用它，最多也就慢到一万步而不是一百步，还能忍受。这里，一个数字可以有15 位，接近 1015。这一下情况就完全不同了。

~1015
如果把每个 d 一直测试到 n 本身，需要检查的候选数量
~3.2 × 107
用 √n 捷径（√1015），需要检查的候选数量

十个测试用例，每个都要 1015 步，加起来大约是十千万亿次操作——这辈子都跑不完。换成 √n 之后，每个最坏情况的数字大约只需要 3200 万步——这是电脑能在远小于一秒的时间里嚼完的量。√n 捷径从"不错的加速"变成了"这道题之所以能被解出来的唯一原因"。

为什么这个捷径在这个规模下依然正确

这个推理跟规模大小无关：如果 n 剩下的部分有两个因子都比它的平方根大，它们的乘积就已经超过了 n 本身——这不可能。所以一旦 d × d 超过了 n 剩下的部分，最多只能再剩下一个质因数，而且它必定就是 n 本身。完整论证可以看 质因数分解 那篇。

第六关

新变化四（额外加速）：跳过偶数

这里有一个小技巧，在每一步操作都很宝贵的时候值得用上：先单独处理质数 2，把它彻底除干净。之后，n 就必定是奇数了——所以没有任何偶数能再整除它。之后再测试 d = 4, 6, 8, \ldots 完全是白费功夫；直接从 3 跳到 5 再到 7，跳过所有偶数候选。

2
然后
3, 5, 7, 9, 11, …

这大致能把第一步之后需要测试的候选数量减半——一旦你知道"剩下的数字"再也不可能是偶数，这就是一个完全免费的加速。

第七关

用 Python 写出来

把第三到第六关和第二关的核心循环结合起来：

count = 0 while n % 2 == 0: count += 1 n //= 2 if count > 0: factors.append((2, count))
第六关：先单独处理质数 2，这样之后的每一个候选都能安心跳过偶数。
d = 3 while d * d <= n: count = 0 while n % d == 0: count += 1 n //= d if count > 0: factors.append((d, count)) d += 2
第五关的 √n 捷径、第四关的次数统计、第六关的跳过偶数（用 d += 2 而不是 d += 1），全部融合在这一个循环里。
if n > 1: factors.append((n, 1))
循环停止后剩下的部分就是最后一个质数，和 质因数分解 那篇完全一样。

再加上第三关的"读到 0 为止"循环，完整程序如下：

fact0.py
import sys

def factorize(n):
    factors = []

    count = 0
    while n % 2 == 0:
        count += 1
        n //= 2
    if count > 0:
        factors.append((2, count))

    d = 3
    while d * d <= n:
        count = 0
        while n % d == 0:
            count += 1
            n //= d
        if count > 0:
            factors.append((d, count))
        d += 2

    if n > 1:
        factors.append((n, 1))

    return factors

for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    n = int(line)
    if n == 0:
        break
    parts = [f"{p}^{e}" for p, e in factorize(n)]
    print(" ".join(parts))
关于速度的一点说明

这份 Python 代码对任何输入都是正确的——但 Python 本身每一步操作的速度比 C++ 这样的编译型语言要慢。在真实的评测环境里，对一个最坏情况的 15 位质数，大约 3200 万次循环，Python 可能要跑上一两秒，而 C++ 只需要零点几秒，SPOJ 的时间限制往往是照着 C++ 的速度定的。这里用的算法正是一个快速解法所依赖的算法；如果真的提交时超时了，通常的解决办法是换一种语言（保持同样的逻辑），而不是换一种思路。

第八关

一起手动推演一遍：n = 13091989

这个例子很适合拿来手动推演，因为它含有一个重复出现的质因数。

步骤此时的 n动作
检查 213091989是奇数，count=0，不记录 2
d=313091989除不尽
d=5,7,9,11,13,1513091989都除不尽

第十关

轮到你练习了

先用纸笔自己算一遍，再用上面的工具检查答案。

练习 1：手动把 360 分解成 p^e 的形式。

360 = 2×2×2×3×3×5——三个 2，两个 3，一个 5。答案：2^3 3^2 5^1。

练习 2：对于一个质数，比如 n=97，factorize(n) 会返回什么？

循环永远找不到一个能整除它的候选（测试 3、5、7……一直到 √97≈9.8，没有一个能整除），所以循环结束时 n=97 依然剩下，而且大于 1。最后的检查会把 (97, 1) 加进去。输出：97^1——对一个本身就是质数的数字来说，这正是我们想要的结果。

练习 3：为什么检查完 2 之后，可以直接从 d=3 开始、每次跳 2（3、5、7、9……），而不需要再检查 4、6、8？

因为代码在那个循环开始之前，已经把 2 的所有因子彻底除干净了。做完这一步之后，n 剩下的部分不可能再是偶数——如果它还是偶数，就说明还有一个因子 2 没被除掉，这和"已经全部除干净"矛盾。之后再去测试 4、6、8……永远不会有结果，所以跳过它们不会损失任何正确性，却能实实在在地省下时间。

练习 4（较难）：如果输入只有一个 1，后面跟着 0，这个程序会打印什么？这是一个合理的答案吗？

对 n=1：处理 2 的那个循环不会执行（因为 1 % 2 != 0，count 保持 0），主循环的条件 d*d ≤ n 也就是 9 ≤ 1，一开始就是假的，最后的检查 n > 1 也不成立（n 正好等于 1）。于是 factors 保持为空，程序打印一个空行。这其实是对的：1 根本没有任何质因数——它是"空积"——所以一份空的因数列表才是数学上诚实的答案，尽管在屏幕上看起来有点奇怪。

练习 5：修改代码，让它在输出每个数字的分解结果的同时，也打印出实际测试了多少个候选除数 d——这样就能亲眼看到 √n 捷径省下了多少工作。
fact0_debug.py
def factorize_debug(n):
    factors = []
    tested = 1  # 2 总是会被"测试"一次

    count = 0
    while n % 2 == 0:
        count += 1
        n //= 2
    if count > 0:
        factors.append((2, count))

    d = 3
    while d * d <= n:
        tested += 1
        count = 0
        while n % d == 0:
            count += 1
            n //= d
        if count > 0:
            factors.append((d, count))
        d += 2

    if n > 1:
        factors.append((n, 1))

    return factors, tested

和第七关一模一样的算法，只是多加了一个计数器，记录循环实际访问过多少个候选。
